## P0: Flag integrity (the FLAG BAR)

These let students earn flags without the genuine multi-step exploitation the lab promises. Highest priority.

- **P0-1 XXE echo-marker awards (Critical, S).** Six XXE challenges award when the marker string merely appears in output; typing the markers into the import box works with zero entities, and the shared out-of-band collector log exposes other students' marker text, so a fresh session went 0 to 2 of 201 with no exploit (intermediate-05). Require proof of entity resolution: marker present in output AND absent from raw input, plus an entity declaration in the submission; add adversarial negative tests. Refs: expert A1; intermediate-05.
- **P0-2 Beacon awards without JavaScript execution (High, M).** XSS, CSTI, JSONP, and postMessage award on a beacon carrying a token scraped from page HTML; zero JS executes. CSTI 5/5 fell at about 30 seconds per lab with curl (ctf-03); JSONP 5/5 fell to token echo (beginner-05, intermediate-07); constructor beacons accept any non-empty data value (intermediate-03, beginner-13). Move stored XSS to a victim-bot model; make tokens derivable only via JS execution elsewhere; stop rendering raw tokens in HTML. Refs: expert A2; ctf-03, beginner-05, intermediate-03, intermediate-07, beginner-13.
- **P0-3 CSRF self-request awards (High, S).** Three challenges award for changing your own email in your own session, with a clickable "Load the forged request" shortcut (expert F3). Require cross-site evidence (Referer/Origin, like referer-bypass does) or a victim-bot; remove the shortcut. Refs: expert A3; beginner-03, ctf-5.
- **P0-4 Upload award-on-store (High, S).** A one-byte .html file earns the stored-XSS flag; all 8 upload challenges awarded on shape alone at upload, and one POST awards both upload-case and upload-double-ext (ctf-07, ctf-02). Award on proven execution (beacon after serving inline), not on file receipt; each challenge should award only its own id. Refs: expert A4, A6; ctf-02, ctf-07.
- **P0-5 CMDI evidence spoof by quoted echo (Medium-High, XS).** A quoted echo of the expected output text awards with no real command executed; the scrub removes only the exact raw input string (intermediate-04, ctf-04). Validate by running the command server-side and comparing structured evidence, not by substring matching. Refs: intermediate-04, ctf-04.
- **P0-6 LFI double-encode check tests for a bare percent sign (Medium-High, XS).** /lfi/double awards for %73ecret.txt (no traversal at all) because the check looks for % in the raw input rather than real double-encoded traversal (ctf-03). Check for decoded traversal semantics. Refs: ctf-03.
- **P0-7 Host-header SSRF content-only check (Medium-High, S).** The award triggers on a marker substring in the fetched body; a stand-in server returning the marker won the flag without the internal agent ever being contacted (ctf-06). Tie the award to the actual intended agent response or to evidence only it can produce. Refs: ctf-06.
- **P0-8 SQLi possession shortcuts (Medium, S).** Five of eleven sqli challenges fall to a secret obtained elsewhere: groupby-having accepts a quoted literal of the secret, blind and like-wildcard accept a secret extracted once by UNION, and order-by plus limit-offset award on pattern rather than on extracting the target (ctf-01, ctf-06, intermediate-01). Bind each submit box to a per-challenge derived secret. Refs: ctf-01, ctf-06, intermediate-01.
- **P0-9 proto-client claim awards with no pollution (Medium, XS).** GET /proto/client/claim?theme=dark awards with no page load and no actual pollution. Bind the claim to evidence of a real polluted render (server-issued one-time token echoed by page script). Refs: expert A5.
- **P0-10 Adversarial negative-test gap (High, M).** The test suite's negative tests use benign input, never adversarial input; the XXE cheat passes the full suite today (expert F10). Add marker-literal, beacon-without-load, self-CSRF, and trivial-upload negative tests per module. Refs: expert A8.

## P1: Shared-instance safety and classroom readiness

These decide whether the lab survives real multi-student use.

- **P1-1 Per-session challenge state (High, L).** Race state is process-global; prototype pollution is process-global; mass-assignment promotions, formula exports, cache poison, the hosted-DTD slot, and shared account passwords all leak across students. One student's redeem blocks everyone else's; another's password change breaks your brute-force lab (ctf-01, ctf-03); alice's silent promotion to admin nullified six IDOR challenges (burp-06). Scope state per session or document the lab as single-student per instance. Refs: expert B1; 44 reviews mention interference.
- **P1-2 `GET /race/reset` is a CSRF-able global reset (High, S).** One unauthenticated GET wipes everyone's race state (expert P1). Make it a POST and scope it per session. Refs: expert B1.
- **P1-3 Progress is volatile with no warning (High, S/M).** Two reboots during the wave reset every scoreboard to 0/201; the banner never hints volatility, and crypto secrets rotate silently (expert C10). Add a dismissible notice when the boot id changed; state in the UI that restarts reset progress; advise students to record each flag. Refs: expert C10; clicker-02, intermediate-12, instructor-01 to 05.
- **P1-4 No classroom tooling (High, L).** No accounts, roster, tracking, progress export, per-student reset, or isolation. All five instructors: cannot run a class on it yet. Minimum: scoreboard CSV export, documented reset procedure, `docs/CLASSROOM.md` with isolation notes. Refs: expert C4; instructor-01 to 05.
- **P1-5 Certificates are per-install, not per-student (High, M).** The completion code derives from install identity plus path id only, so all classmates get identical codes. Bind the code to a student identifier or document that it is not identity-bound. Refs: expert C5.
- **P1-6 Session fragility under parallel load (Medium-High, M).** After parallel bursts the scoreboard reads 0/201 and the session id has changed, even for one process sharing one jar; reproduced three times (intermediate-07). A race-module student can silently lose every captured flag. Investigate the store layer; until fixed, warn students. Refs: intermediate-07, beginner-05.
- **P1-7 Fix-mode DoS surface (High, M).** No memory cap (student code can OOM the whole process); each submission blocks the event loop about 6 s; no `unhandledRejection` handler on Node 24, so one throw after an `await` in the seven bare async race handlers kills the lab for everyone (expert E1, X1, X2). Isolate in worker_threads with resourceLimits; add an async-handler wrapper plus a process-level log. Refs: expert B2, B3.
- **P1-8 Demo credentials drift from seeds (Medium-High, S).** Fixation advertises admin/admin123 and returns 403 (burp-02); hostheader advertises alice/alice123 and returns 401 while bob/bob123 works (intermediate-06); the sqli admin password reads "Invalid" (ctf-06). Students burn real time on step zero. Add a boot-time smoke test asserting every advertised demo credential logs in. Refs: burp-02, intermediate-06, ctf-06; 18 reviews mention credentials.
- **P1-9 Deployment secret and session hygiene (Medium, S).** `docker-compose.yml` ships with the session secret commented out, so real deployments use the public fallback (expert S1); `saveUninitialized: true` with purge-only-at-boot grows the session store unboundedly (expert S2). Generate and persist a random secret on first boot; set `saveUninitialized: false` with a timer purge. Refs: expert B4, B5.

## P2: Burp-first honesty

The lab promises Community edition suffices; the guidance must keep that promise.

- **P2-1 Race Intruder guidance vs Community (High, M).** Hint ladders prescribe throttled Community Intruder for a 150 to 250 ms window (expert F1); 34 reviews call this out. Teach Repeater's "Send group in parallel" (single-packet attack) first; document it in the setup guide; rewrite race payload blocks (expert F5). Refs: expert D1, D4.
- **P2-2 crypto-rand-pin not Community-feasible (High, M).** A million Intruder payloads is days of throttled fuzzing, contradicting the docs' "guessable spaces are small"; SOLUTIONS.md claims about 72 s at about 2,800 requests per second, measured about 130 to 150 per second with 20 to 24 workers (intermediate-07). Shrink the space, teach `Math.random()` prediction honestly, or sanction Turbo Intruder with the real math (expert F2). Refs: expert D2; intermediate-07, intermediate-12, beginner-10.
- **P2-3 OTP brute force has no honest guidance (Medium, S).** The 10k-code challenge needs a Grep-Match walkthrough and expected Community runtime; nothing exists (expert F4, F6). Add "Reading Intruder results" to the setup guide; link from otp-bruteforce and sqli/blind (expert F5). Refs: expert D3, D5.
- **P2-4 Misleading tool routing in hints (Medium, S).** cors-reflect hint 3 describes an unnecessary attacker-page-through-proxy demo; cors-null hint 3 says to collect the flag in the "Burp proxy browser" for a plain GET; cors-regex hint 2 pushes Intruder Sniper where Repeater is faster; hints keep demanding Proxy steps for browser-trivial reads (burp-06, clicker-01). Audit hint tool-routing per challenge. Refs: burp-06, clicker-01.
- **P2-5 Missing Burp workflows (Low, S).** CSRF challenges omit "Generate CSRF PoC" (expert F7); Proxy Match and Replace is used but never documented (expert F8); the JWT module offers Node forging with no Burp-native alternative (Decoder base64url, JWT Editor extension) (expert F10); the PEM newline trap (beginner-03, ctf-05, beginner-15) deserves one line in the alg-confusion ladder. Refs: expert D6, D7, D8.
- **P2-6 Burp setup cliff (High, S).** Nothing in the web UI links the setup guide; the first challenge's starting point assumes Proxy is configured; /about never mentions Burp (expert F1). Add a "Set up Burp first" card to /about and the Start-here page. Refs: expert C1.
