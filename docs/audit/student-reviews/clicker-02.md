# Student Review: Clicker Dot (clicker-02)
- Modules tested: ssti (assigned), xss (my choice)
- Post-reboot verification: the VM rebooted twice during this audit (around 01:37 UTC and again around 02:47 UTC), wiping per-boot state each time. After the second reboot I re-ran every confirmed exploit on the live instance and all 6 flags were awarded again with the banner: SSTI greet basic ({{7*7}}), SSTI scope leak, /ssti/dotblock, /ssti/curly, /ssti/exec RCE, and the /xss reflected beacon flow. Final live scoreboard check after the second reboot: SSTI 5/9, XSS 1/9, total 6 / 201 flags. All results below hold on the post-reboot instance.
- What worked well:
  - Every link I clicked resolved. All 9 SSTI challenge endpoints and all 11 XSS endpoints returned HTTP 200. No dead pages anywhere in the sweep.
  - Every challenge page has a way back. /ssti/greet, /ssti/wordfilter, /ssti/nounderscore, /ssti/nobrackets, /ssti/dotblock, /ssti/curly, /ssti/noquotes, /ssti/exec all link "Back to SSTI module". All 9 XSS challenge pages link back to the XSS module page. I never got stranded.
  - Global progress is always visible. Every page header carries a score chip with the running flag count (I saw it move 1/201, 2/201, 3/201, 4/201 as I captured). The homepage module cards show per-module progress bars (for example "0/9", and my SSTI card filled as I solved).
  - The custom 404 page is good UX. Tested by visiting /xss/reflected and /xss/stored (which 404). It says "404 Lost in the lab? That page does not exist. It may have been a mistyped URL, or a module that never shipped." with working "All modules" and "Scoreboard" links.
  - Flag capture UX is satisfying. On /ssti/greet and /ssti/exec the page shows "Flag captured", "Saved to your scoreboard", a "Copy flag" button, and links to Scoreboard and All modules. Same banner on the /xss/collect confirmation page.
  - /ssti/greet has a "test {{7*7}}" quick link, so the first experiment is one click. Hint toggles (Nudge / Technique / Explicit) open and close fine on every card. Copy buttons exist on all 9 SSTI cards.
  - XSS challenge pages are clicker-friendly. /xss/search shows a "How to claim this flag" walkthrough, plus "Challenge card" anchor links (for example /xss#reflected) and a "Try to fix this" link (/fix/xss/reflected). Each page is skinned as a fake app (Brightside Goods, Maple Street Cafe), which makes them fun to click through.
  - Junk handling is sane. Submitting <script>alert(1)</script> into /ssti/greet reflected it (it is an SSTI lab, XSS is out of scope there) without errors. Submitting it into /xss/search reflected it raw (intended, it is the XSS lab). A guestbook POST stored and redisplayed my junk entry on the next page load.
- Bugs found (with reproduction):
  - BUG 1: Two SSTI challenges are unreachable by clicking. The "Dot Blacklist Bypass" and "Curly-Brace Strip Bypass" cards never name their endpoint URL or parameter. The "Starting point" text says only "Proxy the form through Burp, send the request to Repeater, and fuzz the input parameter", with no URL anywhere on the card, the brief, or the hints. I found /ssti/dotblock and /ssti/curly only by probing candidate names (both return 200 and both award flags when solved). The other 7 SSTI cards and all 9 XSS cards name their endpoints. Repro: open /ssti, read cards 6 and 7, try to find the target page by clicking. You cannot.
  - BUG 2: Captured flags can silently vanish. I captured flags on 5 SSTI challenges, each time seeing the "Flag captured / Saved to your scoreboard" banner (basic with {{7*7}}, scope leak, dotblock, curly, exec). The shared instance became unreachable for a few minutes mid-test (curl exit 7, HTTP 000). When it came back, the scoreboard showed only 2 of my 5 captures, and Scope Leak, Dot Blacklist and Curly-Brace showed "Not captured". Re-solving a challenge restored it correctly (SSTI moved 2/9 to 3/9 with correct marking), so normal scoring works, but the banner text "Saved to your scoreboard" overpromises: a restart wipes earlier captures with no warning. This repeated on the second reboot (around 02:47 UTC): all captures were wiped again, and re-running all six exploits on the live instance restored them correctly (SSTI 5/9, XSS 1/9, total 6/201). The lost captures are a pool restart artifact, not a mapping bug in the scoreboard, but the banner gives no hint that progress is volatile.
  - BUG 3: "Break then fix" copy is repeated 10 times. The SSTI module page shows "Fix mode is not available for this module yet." and then, once per challenge card, "Fix mode is not available for this challenge yet." (9 more times). Meanwhile /fix/ssti/basic returns HTTP 200 with its own "Fix mode is coming soon for this challenge" placeholder. One notice would do.
  - MINOR: nested paragraph tags in the SSTI module brief markup (a <p> opened directly inside another <p> before "This greeting card renders your name..."). Browsers recover, but it is invalid HTML.
- Friction/confusion points:
  - No breadcrumbs anywhere. Grep for breadcrumb markers on /ssti, /xss and challenge pages found zero. You can always get back via back-links, but there is no "Home > Modules > SSTI" trail and no "you are here" indicator on challenge pages, so after opening a few tabs I lost track of which challenge I was in.
  - No progress indicator inside the module page. After capturing 3 SSTI flags, /ssti showed zero captured markers on the cards (the word "captured" appeared 0 times). On /xss the only "captured" mentions were the word inside hint prose ("Send the captured search request to Repeater"), not badges. You must leave the module and open the Scoreboard (or squint at the header chip) to see which cards are done. The homepage module cards have progress bars, the module pages themselves do not.
  - Nav has two links to the same place. In the header, both the "PenTrix VulnLab" logo and the "Modules" nav item point to "/". As a clicker I clicked both and felt tricked once.
  - Empty form submit gives zero feedback. Submitting the /ssti/greet form with an empty name renders no greeting section at all, no "please enter a name" message. Clicking "Greet me" appears to do nothing.
  - The dotblock challenge's wording misled me. The card says "read the flag property from the db object", so I tried db["flag"], then db["secretFlag"], and got "Record: undefined" each time. The property is actually named "key". I only found it via Object["keys"](db), which no hint suggests. The card/hints never tell you the name is not literally "flag".
  - XSS card ids do not match page paths. Card id "reflected" lives at /xss/search, card id "stored" lives at /xss/guestbook. Typing /xss/reflected or /xss/stored gives the 404 page (which is well designed, but the mismatch still cost me clicks).
  - The /xss/collect beacon only works as GET with c, v, n query params. POST to /xss/collect returns 404, and GET without params returns 400. The page copy shows a GET-style payload pattern, but a student firing a classic fetch POST beacon will hit a 404 and think the collector is down. No flag was awarded for my POST attempts; the lab awarded the flag once I used the documented GET shape with a fresh one-time token.
  - The "Copy" buttons on SSTI cards copy the "Starting point" paragraph, which is prose instructions, not a payload. The label made me expect a starter payload on my clipboard.
- Hint quality (helpful? spoilery? useless?):
  - SSTI three-level ladder (Nudge, Technique, Explicit) is the best structure I have seen in these labs. Hint 1 nudges, hint 2 teaches, hint 3 for Basic basically hands you the technique, which feels right for the first challenge of the module.
  - The challenge pages themselves add one more "Hint (click to reveal)" that is usually the sharpest one (the curly page: "The filter strips one pair of braces. What happens if you send two pairs?" is excellent).
  - XSS pages put "How to claim this flag" steps right on the page, extremely explicit, almost a walkthrough. Great for an impatient clicker, maybe too spoilery for a purist, but this is a learning lab so I call it helpful.
  - One weak spot: the dotblock Hint 2 says "reach the flag-holding object's key with brackets around a quoted string". The double meaning of "key" (property name vs access key) is confusing, and nothing nudges toward enumerating the object's properties.
- Difficulty fairness:
  - SSTI Basic through the filter bypasses feel fair and escalate sensibly (Easy to Hard matches my experience). The exec RCE is clearly signposted as Hard and the hint names require and execSync directly.
  - Dot Blacklist is the outlier: the hidden property name makes it a guessing game rather than a technique challenge. Medium feels wrong for it as written; either name the property in the card or add an enumeration nudge.
  - I attempted the Word Blacklist challenge with about a dozen payload variants (concatenation, eval, case tricks) and no flag was awarded. The challenge loads and renders fine ({{7*7}} evaluates to 49), so I report it as "attempted, not solved" rather than broken.
  - XSS Reflected: fair. The one-time token plus collector flow worked exactly as the page describes once I followed the instructions.
- Burp-first feasibility:
  - High for SSTI. Every card is written Burp/Repeater-first and every endpoint also accepts plain curl/browser requests with the parameter named in the card (except the two unlinked cards, which use "input"). I solved greet, dotblock, curly and exec entirely with curl standing in for Repeater.
  - Mixed for XSS. The forms and payloads are Repeater-friendly, but the reflected/stored challenges require actual JavaScript execution (document.cookie plus window.__px) to fire the beacon, so Burp alone cannot complete them; a proxied browser is needed, which the cards do say. The token-plus-GET-collector shape is curl-simulatable if you want to cheat the browser step.
  - DOM-based XSS (/xss/dom) is fragment-driven ("greetings are built in the browser from the part of the URL after #"), so nothing happens over the wire with curl. Expected, but a pure-Burp student will need the browser for that one.
- Suggestions (concrete):
  - Add the endpoint URL and parameter name to the Dot Blacklist and Curly-Brace Strip cards, or add a real "Open challenge" button to every card.
  - Put captured badges on module-page cards, reusing the same capture state the scoreboard already has.
  - Collapse the ten "fix mode not available" notices into one banner at the top of the module page.
  - Add a breadcrumb or module label on challenge pages (for example "SSTI / No Dots") so tab-hoppers know where they are.
  - Show a friendly message on empty form submits instead of silently rendering nothing.
  - Link the header score chip to /scoreboard, and make its label read "N of 201 flags" for clarity.
  - Accept POST on /xss/collect as well as GET, or state the beacon method explicitly in the page copy.
  - Fix the dotblock wording: say the property is not literally named "flag" and nudge toward enumerating the object.
- Rating: 4
