# Student Review: Grinder Jade (intermediate-04)
- Modules tested: ssti (all 9 challenges, live), cmdi (all 9 challenges, live), http (code-reviewed only, NOT live tested). Career path "Zero to Web Pentester" first 5 steps (source-reviewed only, NOT live tested).

Method: curl as Burp Repeater simulation, unique cookie jar /tmp/cookies-intermediate-04.txt on every request, 1s sleep between bursts. Scoreboard went 0 to 18/201 across the two live modules (9 ssti + 9 cmdi), each flag confirmed as awarded in the response. The shared instance at 127.0.0.1:18409 died mid-session (connection refused, no listener, no node process) before I reached the http module; per instructions I did not boot or restart it.

- What worked well:
  - SSTI is a genuinely excellent module. The escalation arc is perfect for an intermediate: prove evaluation with {{7*7}} (49 renders, flag awarded), then read the in-scope flag variable, then beat six filter variants (single-strip braces, word blacklist, underscore strip, bracket strip, dot strip, quote strip plus word block), then turn SSTI into real RCE with require("child_process"). Every payload I tried worked first try: {{{{7*7}}}} on curly, eval("vaultSec"+"ret") on wordfilter, eval("db"+String.fromCharCode(95)+"pass") on nounderscore, JSON.stringify(cfg) on nobrackets (nice, teaches serialization instead of indexing), db["key"] on dotblock, eval(String.fromCharCode(...)) spelling the blocked variable name on noquotes, and require("child_process").execSync("id").toString() on ssti-rce (uid=0(root) rendered). The lab awarded the flag in all 9.
  - CMDI evidence-based awarding is the right call. The flag fires only when the shell output proves a second command really ran, and a plain ping with no injection awarded nothing (verified). ping2 through ping6 and ping8/ping9 all fell to the intended technique: newline past the first-semicolon strip, $IFS for stripped spaces, ${IFS} past the naive $IFS string filter, real newline past blocked separators, backticks past the $( filter, | past the ; filter, %09 past stripped spaces. The lab awarded the flag in all 9.
  - Technique-gated awards on ping3/ping4/ping5 are good teaching: my lazy 127.0.0.1;id ran fine on ping3 but awarded nothing because the challenge demands the $IFS technique specifically. That is correct design, it forces the lesson instead of the shortcut.
  - Replay safety: re-sending an already-solved exploit re-renders the same flag banner but the scoreboard stayed at 18/201, no double counting.
  - The career path's first 5 steps read well from source: XSS reflected (run your script, beacon it back), SQLi login bypass (bend the query, land in admin panel), IDOR profile (neighboring numbers), CSRF email change (no token, build the auto-submitting page), misconfig debug page (read what it was never supposed to show). Sensible order: client-side injection, then server-side injection, then broken access control, then session riding, then information disclosure. Each note teaches the concept in plain words without handing over the payload.

- Bugs found (with reproduction):
  - BUG 1 (real, verified): the CMDI evidence check is spoofable by echoing a shaped fake marker. The scrub in the shared helper only removes the exact raw input string from the output, but echo 'uid=7(hacker)' outputs uid=7(hacker) without quotes, which survives scrubbing and matches the id-output regex. Reproduction on a fresh jar: GET /cmdi/ping?host=127.0.0.1;echo 'uid=7(hacker)' (URL-encoded) -> the lab awarded the flag although no real command ever ran (only ping and echo). Same class on ping3: GET /cmdi/ping3?host=127.0.0.1$IFS;echo$IFS'root:x:0:0:root:/root:/bin/bash' -> the raw host contains the literal $IFS the challenge requires, the filter strips spaces it never had, echo prints a forged passwd line at line start matching the passwd regex -> the lab awarded the flag with no real file read. The code comment claims "merely echoing a marker cannot award", which is false for quoted echoes. Suggested fix: also strip every single/double-quoted literal found in the raw input from the output before matching evidence, or require the evidence to differ from any quoted substring of the input.
  - BUG 2 (friction, verified): ping7's own suggested payload is messy. The how field suggests host=127.0.0.1;/???/bin/?at /???/p?sswd. On the live box /???/bin/?at also matches binaries outside /bin (e.g. under /usr/bin), so the response page embeds ~97KB of raw ELF binary dump. The lab still awarded the flag, but a student will think the exploit broke. Cleaner payload verified live: host=127.0.0.1;/bin/?at /etc/passwd -> 6KB page, no binary garbage, flag awarded. The leading / in /bin/?at survives the standalone-slash filter (it only strips / at string boundaries or next to whitespace), and ?at never contains the literal word cat. Suggest updating the how/hint text to the tighter payload.
  - NOT A BUG (checked, clearing my own false alarm): ping5's award condition looked like it tested for a literal backslash-n instead of a real newline, which would have made it unsolvable. Live test proved otherwise: a real newline plus cat /etc/passwd was awarded the flag. The scary reading was a display artifact; the live behavior is correct.
  - INFRA (not a lab bug): the shared instance died during testing (connection refused on 127.0.0.1:18409, no listener, no node process). I lost the http module and the career-path progress-tracking test to the outage. I did not restart it, per instructions.

- Friction/confusion points:
  - ping7 ELF dump (above): a first-time student using the documented payload gets a page full of binary garbage and may abandon a working exploit.
  - ssti wordfilter hint 3 tells the student to "send the request to Intruder and fuzz", which is overkill for a challenge solved by one eval payload; it may send intermediates down a long fuzzing rabbit hole.
  - ping2's how says "URL-encoded command separator the filter cannot see": with curl, pre-encoding %0a inside --data-urlencode double-encodes it; you must send a literal newline and let the tool encode. In Burp Repeater this is natural (edit the raw request), but the how text could say "a raw newline byte (%0a in the raw request)".
  - Duplicate route registration in ssti: both basic and rce challenge files register GET /greet; the first registration wins and both award paths live there, so it works, but it is confusing when reading the module and fragile if load order ever changes.

- Hint quality (helpful? spoilery? useless?):
  - SSTI ladders are the gold standard here. Level 1 always says "capture in Proxy, send to Repeater, try the baseline", level 2 names the technique ("JavaScript has a second property-access syntax", "build the underscore from its char code"), level 3 shows the payload shape without pasting a complete copy-paste answer (except rce's how, which is nearly the full payload, acceptable for the finale). None felt spoilery, none felt useless.
  - CMDI ladders are consistently good, especially the ones that tell you to watch what the filter removed ("send $IFS and read the page to see what the filter removed"). ping3 hint 2 ("Bash has a built-in variable that expands to whitespace") teaches the concept instead of naming $IFS outright. Fair.
  - HTTP hints (code-read only): verb-tamper's ladder is honest and minimal; crlf-log's ladder correctly points at %0d/%0a and the log viewer; cache-deception's ladder clearly describes the two-session attack and the X-Flag header. Could not verify live.

- Difficulty fairness:
  - SSTI: 7 Medium + 2 Hard (noquotes, ssti-rce). Fair. noquotes earns Hard (char codes plus eval plus a word-blocked variable name is genuinely the toughest filter here). ssti-rce earns Hard as the capstone. The six Medium filters are each one insight, which is right for the level.
  - CMDI: 3 Easy (backtick, pipe, tab) + 5 Medium + 1 Hard (wildcard). Fair. The Easies are genuinely one-step ("the filter only strips X, use Y"). Wildcard earns Hard: counting characters for ? patterns and realizing expansion happens after filtering is the biggest leap in the module.
  - HTTP: rated Easy/Medium/Medium from source; verb-tamper looks like a true Easy, crlf-log a fair Medium, cache-deception a fair Medium (two-session reasoning plus response-header reading). Not live-verified.

- Burp-first feasibility:
  - Fully feasible with Burp Community for everything I tested. Every challenge is a GET with query parameters, so Repeater alone covers ssti and cmdi; the hints' Repeater/Proxy/Decoder references match what a student actually does. Newline (%0a) and tab (%09) payloads need raw-request editing in Repeater, which Community supports. No Intruder paywall features are required (the one Intruder mention is optional). Cache-deception needs two sessions (normal + private window or a cookie-less Repeater tab) and reading the X-Flag response header, all Community-feasible. Could not verify live due to the outage.

- Suggestions (concrete):
  1. Fix the echo-spoof bypass (Bug 1): strip quoted literals from the input out of the output before evidence matching, in the shared CMDI helper, so a forged marker can never match the id/passwd regexes.
  2. Replace ping7's documented payload with host=127.0.0.1;/bin/?at /etc/passwd (verified live, no ELF dump) and mention why the broad /???/bin/ glob is noisy.
  3. Soften wordfilter hint 3: suggest the eval-plus-fragments approach before Intruder fuzzing, or mark Intruder as the fallback.
  4. Clarify ping2's how: "a raw newline byte (shows as %0a in the raw request)" instead of "URL-encoded command separator".
  5. Deduplicate the /greet route registration in the ssti module (one handler, or explicit mount order comment) so a future reorder cannot silently break the rce award.
  6. Cache-deception on a shared instance: the edge cache is process-global, so one tester's /cache-purge wipes another's primed state, and a stale victim entry from someone else can award a newcomer who skips the priming step. Consider keying the demo cache per session, or scoping the purge button with a warning.

- Rating: 4
  - SSTI is a 5/5 module on its own: tight progression, honest hints, every payload worked first try. CMDI is strong but loses a point for the echo-spoof verification bypass (a real cheat, reproduced twice) and the noisy documented ping7 payload. HTTP and the career-path progress tracking could not be tested because the shared instance went down mid-session, so this rating covers only what I actually verified live.
