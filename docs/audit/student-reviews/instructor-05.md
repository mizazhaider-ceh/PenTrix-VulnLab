# Student Review: Prof. Elif (instructor-05)
- Modules tested: race (Race Conditions, 8 challenges), upload (Unrestricted File Upload, 8 challenges), on the shared pool instance at http://127.0.0.1:18406/ using a unique curl cookie jar as a Burp stand-in. Scoreboard for my session ended at race 8/8, upload 8/8 (16/201 total).

- What worked well:
  - Race: all 8 challenges solved first try with the documented workflows. 20 parallel POSTs double-spent the RACE10 coupon (20 redemptions); 20 parallel $100 transfers drove the $100 wallet to -$1900; 2 parallel votes for one name both recorded; 10 parallel REF2026 claims paid out 350 points; 10 parallel signups created 10 accounts with one username; 20 parallel rate-limit hits broke the 5-request cap; 2 parallel orders of 5 oversold the 5-unit stock; the TOCTOU file was fetched inside the 2-second scan window and was gone (404) at 3 seconds. The lab awarded the flag in every case.
  - Upload: all 8 challenges solved first try. v1 HTML stored and served back as text/html inline; evil.SVG beat the case-sensitive blacklist; Content-Type: image/png let an HTML file past v4 (a text/html attempt was correctly rejected with HTTP 400); shell.svg.jpg was served as image/svg+xml by /upload/view/; evil.s.svgvg was stored as evil.svg by the strip-once filter; ../pwn.txt escaped the uploads dir and read back through /upload/traversed?f=; bob's avatar was overwritten and served the new bytes; the GIF89a+script polyglot passed the magic-byte check and rendered as text/html. The lab awarded the flag in every case.
  - Briefings are genuinely classroom-grade: each challenge page states the scenario, shows a live status readout, and has a "Test it yourself" box with a step-by-step Burp workflow (Proxy capture, Repeater, Intruder parallel mode). The race module page teaches the check-then-act concept up front and gives the curl parallel-burst command verbatim.
  - Hint ladders are consistent and well-shaped everywhere I read them: level 1 nudges, level 2 names the technique, level 3 gives the payload shape marked KEY INSIGHT. Three levels is the right count for a classroom; students can self-regulate how much help they take.
  - Scoreboard for my two modules was accurate: race showed 8/8, upload 8/8, every challenge row flipped to captured with its difficulty pill, and the 16/201 total matched. No display bug found in names, counts, or captured states.

- Bugs found (with reproduction):
  - Race state is global in-memory state shared across ALL sessions, with a module-wide reset and no session scoping (race/shared.js keeps one object; GET /race/reset wipes it for everyone). Reproduction: reset, burst the coupon endpoint 20-wide with my cookie jar, and all 20 succeeded, but any other tester on the pool instance hitting /race/reset between my reset and my burst changes my results (I observed a referral burst land only 7 of 10 claims, consistent with a mid-attempt reset by another session). On a shared pool, one student's reset silently destroys another student's in-progress attempt, and the "Already redeemed" page can greet a student who never touched the coupon.
  - Upload has no reset at all. There is no /upload/reset route and no reset link on the module page. Reproduction: after I overwrote bob's avatar via POST /upload/avatar?user=bob, there was no way to restore the original; every subsequent visitor sees my bytes. Same for stray files in the shared uploads directory.
  - The flag banner can render in several parallel responses for one burst (e.g., 15 of my 20 ratelimit responses showed "Flag captured"). The scoreboard still counts it once per session, so grading is unaffected, but students may be confused by repeated award banners.
  - Minor: race-stock.js imports getDb from lib/db and never uses it (dead import, no behavior impact).

- Friction/confusion points:
  - The race-upload-scan (TOCTOU) challenge reads filename and content from urlencoded form fields, not a binary body. A curl user sending --data-binary gets silently defaulted to upload.txt with empty content, which looks like success but is not what they sent. The page form shows the fields, so it is recoverable, but the "how" text ("Upload a file at /race/upload") does not say this, and there is no curl example on that challenge page.
  - The upload module page shows two card lists: "Upload endpoints" (v1, v3, v4, v6, v7, v8, v9) and "Challenges" (stored-xss, double-ext, case, ctype, traversal, strip-once, overwrite, polyglot). The mapping between them is not spelled out (v3 serves two challenges; the version numbers skip v2 and v5 with no explanation). Students will ask where v2 and v5 went.
  - The reset link wording says "Resets coupons, balances, votes, accounts, uploads, limits and stock", which reads as personal ("your lab"), but the reset is instance-wide. At least one line should warn that it affects everyone on a shared instance.

- Hint quality (helpful? spoilery? useless?): Helpful and well-graded. Level 1 is a real nudge ("Filesystems and browsers do not care about case"), level 2 teaches the technique, level 3 is borderline spoilery (upload-strip-once's start text hands over the exact filename evil.s.svgvg, and upload-case's level 3 names the case-variant answer). For classroom use this is acceptable: the ladder is opt-in, and level 3 acting as a worked solution means no student is permanently stuck. I would not make level 3 any more generous, though; it is at the limit.

- Difficulty fairness: Fair across both modules. Race ramps Easy (vote, stock), Medium x5, Hard (TOCTOU); upload ramps Easy x3, Medium x5, Hard (polyglot). The 150-250 ms check-to-use window in the race module is generous enough that a 20-wide curl burst succeeds on the first try, and the 2-second TOCTOU window is generous too. Nothing required guessing, luck, or sub-100ms timing. The hardest fair step is conceptual (recognizing the TOCTOU window), not mechanical.

- Burp-first feasibility: Mostly feasible with one real caveat. Proxy capture, Repeater replays, and header/filename edits are all documented step by step and work as written. The parallel attacks assume Burp Intruder with concurrent requests raised, which is a Burp Pro capability; Burp Community Edition throttles Intruder so it cannot reliably fire a 20-wide burst. The module page does give the curl fallback (seq 1 20 | xargs -P20), which is what I used and it worked every time, so a classroom without Pro licenses can still do the module via curl. Recommendation for the briefing: say this explicitly ("Burp Pro, or curl") instead of implying Community Intruder will do it.

- Suggestions (concrete):
  1. Session-scope race state, or at minimum offer a per-session sandbox: namespace the coupon/balance/votes/referral/accounts/files/ratelimit/stock state by session cookie, and scope /race/reset to the caller's session. This is the single change that makes the race module classroom-ready; as it stands, 30 students on one instance will constantly clobber each other and each other's resets.
  2. Add GET /upload/reset (restore bob's avatar, clear the uploads dir) and link it on the module page, matching the race module's reset pattern. Instructors need a between-classes cleanup.
  3. On the race module page, add one warning line next to "Reset lab state" that the reset is instance-wide on shared deployments.
  4. Add a small endpoint-to-challenge map on the upload module page (e.g., "v3 ext-blacklist: used by double-ext and case challenges") and one line explaining the skipped v2/v5 numbers.
  5. Add a curl example to the race-upload-scan challenge page showing the filename/content form fields, since its upload shape differs from every other upload in the lab.
  6. For instructors, consider a read-only class view: with 30 students on one pool instance there is currently no way to see aggregate progress (scoreboard is per-session only), and no per-student reset. Even a simple shared leaderboard keyed by a student-chosen handle would make this runnable as a class.
  7. In the race briefings, note that Burp Community Intruder is throttled and point students at the curl parallel command as the primary path when Pro is unavailable.

- Rating: 4
