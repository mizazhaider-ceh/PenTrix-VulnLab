# Student Review: Day-One Aisha (beginner-05)
- Modules tested: jsonp (5 challenges: Callback XSS, JSONP Data Theft, Callback Filter Bypass, Array Constructor Hijack, JSONP MIME Sniffing) and race (8 challenges: Single-Use Coupon Redeemed Twice, Double-Spend the Balance, Vote Counted Twice, Referral Bonus Claimed Twice, Duplicate Username Registration, Beat the AV Scan (TOCTOU), Burst Through the Rate Limit, Oversell the Stock). Tested 2026-10-20 against the shared pool instance at http://127.0.0.1:18405/ with a single dedicated cookie jar. All 13 challenges exploited via curl flows that mirror the documented Burp Proxy/Repeater/Intruder steps; every exploit produced a flag in the response. Baseline scoreboard was 0/201.
- What worked well: The module briefing pages genuinely teach. The race module's "check-then-act" explanation with the two-steps-apart story made the concept click before I touched a challenge. The hint ladders (nudge, technique, payload shape) are the best part of the lab: three rungs means I could stop at the rung that unblocked me instead of getting the whole answer at once. Every challenge card has a "Starting point" and most race challenges have a "Test it yourself" box with numbered Intruder steps, so I never stared at a blank page. The tools pills (Burp/ZAP, Browser, curl, Python) decode on hover, which answered my "what am I supposed to use" question. /race/reset before each attempt is clearly signposted and works. Cheat testing behaved correctly everywhere I probed: a beacon with a wrong token returns 400, replaying a consumed beacon returns "No flag", the single-use coupon secret rotates after one award so replaying the beacon fails, and a single sequential coupon redeem earns no flag. The demo attacker pages (/jsonp/attacker, /jsonp/array-attacker) both render fine and make the cross-origin theft story concrete.
- Bugs found (with reproduction): (1) Earned flags are not reliably retained on the scoreboard after parallel-burst testing. Reproduction: with one shared cookie jar, I exploited all five JSONP challenges sequentially (each: load the feed, read the per-session token from the response, echo it to the beacon) and verified the scoreboard at 5/201. Then I ran the documented race workflow, bursts of 20 parallel POSTs sharing the same jar (e.g. `seq 1 20 | xargs -P20 -I{} curl -s -X POST http://127.0.0.1:18405/race/coupon/redeem`, after GET /race/reset), for all eight race challenges. Every burst's responses displayed flags for the broken invariant (8 of 20 redeems succeeded on the coupon, balance went to -$500 on double-spend, 15 duplicate accounts on register, etc.). But the final scoreboard showed only 2/201, with just the last two race challenges (ratelimit, stock) marked captured; the five verified JSONP captures had vanished from my session. Sequentially re-running the Callback XSS exploit re-awarded the flag and the count rose to 3/201 and persisted, and a fresh-jar coupon burst test also persisted (1/201). So the loss is intermittent and tied to the concurrent-request workflow the module itself documents: parallel requests sharing one session appear able to clobber or strand earlier award state. As a beginner this was demoralizing: I did the exploit right, saw the flag, and the lab forgot it. (2) The documented race example command on the /race page uses the wrong port: `seq 1 20 | xargs -P20 -I{} curl -s -X POST http://localhost:3000/race/coupon/redeem`. The lab runs on port 18405 here, so a literal copy-paste hits nothing. A day-one student will assume they typed it wrong and waste time.
- Friction/confusion points: (1) The JSONP "execution proof" (echo the per-session token to the beacon) can be satisfied by copy-pasting the token from the feed response straight into the beacon URL in a browser address bar. I never executed any JavaScript for any of the three reflection challenges and the lab awarded every flag. As a beginner this taught me the wrong lesson: the briefing says the payload must really execute, but the lab cannot tell execution from copy-paste, and I only realized this by accident. Either make the proof stronger or state plainly that manual token echo is an accepted beginner path. (2) The JSONP module is labeled Intermediate with prerequisites "xss, cors", but three of its challenges are labeled Easy and all five were solvable by me on day one mostly by reading responses carefully. The labels made me hesitate to start a module I could actually do. (3) The 400 page for the filter-bypass challenge shows a "How to claim this flag" card containing a complete working payload pattern. The challenge solves itself by copy-paste; hint rung 1 and 2 become irrelevant. (4) I was never sure whether GET /race/reset would wipe my earned flags. It does not (my ratelimit and stock captures survived later resets), but nothing on the page says so, and I dreaded clicking it mid-run. (5) The race-coupon page says "Reset the lab to try again" after a single legit redeem; combined with the global reset, I was confused about what state I was in after each attempt until I re-read the coupon page counters. (6) The vote challenge's hint rung 3 says "Watch the results table", but I could not find a results table showing per-name vote counts on the vote page; I wanted to see the double count to confirm my exploit and could not. (7) Every module page carries a "Break then fix" section saying fix mode is not available yet, with badges and CTAs. As a day-one student this is clutter before the basics have landed; it reads like an unfinished feature, not guidance. (8) The beacon-xss error page tells me to "Load the JSONP URL as a script and let your payload fire the beacon" but shows no minimal HTML example. I stared at it until I tried the token in the address bar.
- Hint quality (helpful? spoilery? useless?): Callback XSS: helpful; rung 1 ("ask what the response would execute if the callback were not a plain function name") genuinely taught me to read the response as code, rung 3 gives the beacon URL shape which is slightly spoilery but I needed it. JSONP Data Theft: helpful but the rung 3 instruction ("replay the beacon in Repeater, the response carries the flag") hands over the whole answer; combined with the auto-stealing attacker demo page, this challenge requires zero exploit crafting. Callback Filter Bypass: rungs 1-2 are a good progression (probe the 400, rebuild the word at runtime), but the payload-pattern card on the 400 page is fully spoilery and undercuts them. Array Constructor Hijack: helpful; rung 1-2 walk Proxy history well, rung 3 is explicit about replaying the beacon. JSONP MIME Sniffing: helpful; rung 2 ("try an HTML-shaped callback value") was exactly the nudge I needed, rung 3 gives the beacon URL. Race challenges: the hints consistently push Burp Intruder with concurrent requests, which is the right technique, and the "Test it yourself" boxes are clearer than the hints themselves; but nothing warns that Burp Community throttles Intruder, which is the single most likely reason a beginner's parallel attack silently fails. The TOCTOU upload-scan hints are good and the 2-second window is stated honestly.
- Difficulty fairness: JSONP: Callback XSS (Easy) and MIME Sniffing (Easy) are fair and genuinely teach their vuln class. Data Theft (Medium) and Array Hijack (Hard) are mislabeled in practice: opening the provided attacker demo page does the whole attack for you, so they play easier than Callback XSS. Filter Bypass (Medium) is fair if you ignore the payload card on the 400 page, trivial if you read it. Race: the Easy ones (vote, stock) are fair; the Medium ones (coupon, balance, referral, register, ratelimit) are all the same one trick repeated, which is fine for drilling but the difficulty spread is really "one idea, eight skins". Upload-scan (Hard) is fair: the challenge is speed and sequencing, not cleverness, and the page tells you the file is live "now" with a 2-second fuse. Overall nothing felt unfair, but the labels overstate the spread.
- Burp-first feasibility: Callback XSS: fully doable, Repeater to craft the breakout, Burp's browser to load it, copy the token from the feed response, GET the beacon in Repeater. JSONP Data Theft: doable, proxy the attacker page, send the beacon POST to Repeater and replay. Filter Bypass: doable in Repeater (400 probe, then the concatenation payload). Array Hijack: doable via the attacker page plus Repeater replay of the beacon. MIME Sniffing: doable in Repeater plus the browser. All eight race challenges: the documented path is one Intruder parallel attack each, which is correct in principle, but Burp Community throttles Intruder so 20 genuinely concurrent requests are not reliable; in Community the curl one-liner from the module page is the dependable path. Upload-scan is doable in Repeater only if you fetch within the 2-second window, which is tight but possible with a pre-staged Repeater tab. Net: every challenge is Burp-doable, but the race module as documented assumes a Burp tier most beginners do not have.
- Suggestions (concrete): (1) Fix the example command port on the /race page (localhost:3000 is wrong for this deployment); better, show the command with a placeholder host the student copies from their own address bar. (2) Either strengthen the beacon execution proof so copy-pasting the token does not earn the flag, or add one honest line on the beacon pages saying a manual token echo counts as the beginner path. (3) Fix award persistence under concurrent requests: run the documented 20-parallel-burst workflow with one shared session and assert earlier captures survive; until fixed, warn students that parallel bursts can drop scoreboard state. (4) Add one line next to "Reset lab state": "Earned flags are kept; only lab state is wiped." (5) On each race challenge, add a "Burp Community?" callout pointing at the curl one-liner, since Intruder is throttled in Community. (6) Put a minimal `<script src="...">` HTML example on the beacon-xss error page. (7) Make the vote results table visible on the vote page, or drop the hint's mention of it. (8) Collapse or hide the "Break then fix, coming soon" sections until fix mode exists. (9) Tone down the spoilery payload card on the filter-bypass 400 page, or move it behind a "show me" toggle so rungs 1-2 keep their value.
- Rating: 4
