# Student Review: Buffer Bea (ctf-05)
- Modules tested: CSRF & Clickjacking (5/5 captured), JWT Attacks (8/8 captured), Open Redirect (5/5 captured). 18 of 18 assigned challenges solved, all with curl from the command line against http://127.0.0.1:18402/. Time to first flag: csrf about 75 seconds after login, jwt about 2 minutes, redirect on the very first request. IMPORTANT CONTEXT: the lab pool rebooted at about 01:37 UTC in the middle of my run (all sessions and per-boot keys reset). Every result below was re-run and re-confirmed on the live instance AFTER the reboot, and the scoreboard totals were re-verified post-reboot.
- What worked well: Every challenge is a clean, single-request or short-chain exploit, which makes speed-running satisfying and makes the intended technique obvious in hindsight. Winning requests (all verified live, post-reboot): (1) CSRF Change Email: GET /csrf/change-email?email=attacker%40evil.com with the alice session, the lab awarded the flag instantly. (2) Clickjacking: GET /csrf/framedemo to get the one-time frame token, GET /csrf/vip-action?frame=TOKEN, then POST /csrf/vip-action with body frame=TOKEN, the lab awarded the flag. (3) JSON API CSRF: POST /csrf/api/email with Content-Type text/plain and body {"email":"attacker@evil.com"}, flag awarded. (4) Weak Referer Check Bypass: POST /csrf/api/nickname with header "Referer: https://evil.com/?pentrix.lab" and body nickname=hacked, flag awarded. (5) Method Override: POST /csrf/account with body _method=DELETE, flag awarded. (6) JWT alg=none: POST /jwt/none with a hand-built unsigned token (header {"alg":"none","typ":"JWT"}, payload {"user":"admin","role":"admin"}, empty signature segment), flag awarded. (7) JWT Weak HMAC Secret: brute-forced the sample guest token offline with a small wordlist of classic defaults, signed an admin token with the winning secret, POST /jwt/weak, flag awarded. (8) JWT Algorithm Confusion: signed an HS256 admin token using the published RSA public key bytes as the HMAC key, POST /jwt/confusion, flag awarded (but see the bug below, the first correct attempt failed). (9) JWT Expiry Never Checked: copied the leaked expired admin token from the page and POSTed it unchanged to /jwt/noexpiry, flag awarded. (10) JWT Audience Not Validated: copied the partner token from the page and POSTed it to /jwt/aud/login, flag awarded. (11) JWT Untrusted jku: registered kid ctf05evil with my own secret at /jwt/attacker-keys/register, minted an HS256 admin token with header kid and jku pointing at http://localhost:18402/jwt/attacker-keys/jwks?kid=ctf05evil, POST /jwt/jku, flag awarded. (12) JWT Default Key for Missing kid: signed a kid-less HS256 admin token with the tiny guessable default key, POST /jwt/kiddefault, flag awarded. (13) JWT SQL Injection in kid Lookup: kid header of the shape ' UNION SELECT 'mykey' -- plus a token signed with mykey, POST /jwt/kid, flag awarded. (14) Protocol-Relative Redirect: GET /redirect/go?next=//evil.example.com/phish returned 302 with Location //evil.example.com/phish and the lab awarded the flag. (15) javascript Scheme: GET /redirect/js?next=javascript:alert(1) returned Location javascript:alert(1), flag awarded. (16) data Scheme: GET /redirect/data?next=data:text/html,... returned the data URL in Location, flag awarded. (17) Parameter Pollution: GET /redirect/polluted?next=/home&next=https://evil.example.com redirected to the second (evil) value, flag awarded. (18) Backslash Allowlist Bypass: GET /redirect/trusted?next=https:%5C%5Cevil.example.com/x passed the check and 302-redirected off-site, flag awarded. Scoreboard (/scoreboard) confirmed all of it: module 07 CSRF & Clickjacking 5/5, module 14 JWT Attacks 8/8, module 21 Open Redirect 5/5, every challenge in the three modules showing Captured, account total 18/201.
- Bugs found (with reproduction): BUG 1 (real, cost me about 20 minutes): Algorithm Confusion punishes the exact technique it teaches. The HMAC key the verifier uses is the server PEM export bytes INCLUDING the trailing newline at the end of the key text. The page at /jwt/confusion-pubkey renders the key in a pre block where that final newline is invisible. Reproduction: fetch the key page, extract the key text exactly as displayed (ends at "-----END PUBLIC KEY-----" with no trailing newline), sign an HS256 admin token with those bytes, POST it to /jwt/confusion: result is 403 "Signature invalid or role is not admin." Append one newline to the key text and sign again with everything else identical: the lab awards the flag. The page HTML source does contain the newline (it sits right before the closing pre tag), so the built-in Copy button, which copies the raw text content, works, but any student who hand-selects the visible key text, or extracts it with a script the obvious way, gets bytes that silently do not match, with a generic error that points nowhere. BUG 2 (minor display artifact): the /scoreboard markup always contains the empty-state text "No challenges match your filter. Try clearing the search." even when the page is full of results; it only disappears once the page JavaScript runs, so it can flash or linger in a text-only view and reads like the scoreboard is empty when it is not. BUG 3 (cosmetic): on /jwt/noexpiry the leaked token's issued-at time is later than its expiry time, which looks wrong when you decode it, even though "expired token still accepted" is the whole point of the challenge. NOT A LAB BUG but worth recording: the pool reboot at about 01:37 UTC mid-run killed my session and rotated the per-boot RSA keys, so any in-progress work had to be redone; all 18 captures in this review are post-reboot.
- Friction/confusion points: The alg-confusion trailing newline (Bug 1) is the big one: my token was cryptographically correct for the key as displayed and the denial message gave zero signal. Everything else was smooth. Small things: the JWT module index links several challenges as page anchors (/jwt#weak-secret style) instead of direct challenge URLs, so from the index you scroll instead of landing on the challenge. The weak-secret wordlist hunt took two lists: the first 29 classic defaults missed, a wider list of about 100 found it, which is slightly more than the "tiny wordlist" the briefing promises. CSRF note by design: the lab is single-session, so every CSRF "attack" is fired against your own logged-in session; that is the lab simulating the victim, and the clickjacking challenge is honest about it. The cheat battery mostly came back clean: bare POST to /csrf/vip-action with no frame token (BLOCKED, no flag), POST with an invented frame token (BLOCKED), replaying a used frame token a second time (BLOCKED, single-use works), POSTing a fresh frame token without the framed page load first (BLOCKED, the full chain is required), sending an HS256-signed token to /jwt/none (BLOCKED, only alg none is accepted there), POST to /csrf/api/nickname with no Referer at all (BLOCKED, 403), plain POST to /csrf/account without the override field (BLOCKED, nothing happens), a real DELETE /csrf/account (deletes but no flag, by design and the page says so), a safe same-origin value on /redirect/go?next=/home (no flag), and a plain https://evil.example.com value on /redirect/trusted (BLOCKED, 400). Two alternate referer spellings also passed (trusted string inside a query parameter, and trusted string as a subdomain prefix of an evil host); both are fair variants of the same intended substring-check lesson, not extra cheats. No flag in my three modules fell without performing the intended technique, except that CSRF is inherently self-targeted in this lab setup.
- Hint quality (helpful? spoilery? useless?): Helpful overall, with one harmful exception. The CSRF hint ladders are excellent: level 1 points at the right request, level 2 names the missing control, level 3 basically hands you the Repeater workflow, and following them feels like a good tutor. The redirect hints are short and accurate (the backslash challenge page even prints a working sample value, which is generous for a Medium). The JWT hints are fine for none, weak-secret, kid-default and kid-sqli. The alg-confusion hints are the exception: hint 1 says "Copy the PEM text; that is the raw material," which is exactly the action that fails if you copy the visible text (Bug 1). The hint is confident, correct-sounding, and wrong at the byte level, which is worse than no hint. Level 3 hints across all three modules are spoilery by design (they describe the full request shape), which is fine for a teaching lab since you still have to build the request yourself.
- Difficulty fairness: Mostly fair. Easy challenges (change-email GET, alg=none, expired token replay, protocol-relative redirect) are genuinely one-request wins. Mediums (JSON CSRF, referer substring, method override, weak secret, aud bypass, kid-default, kid-sqli, the javascript/data/pollution redirects) each add exactly one idea. jku at Hard is fair Hard: register a key, build a header, sign, submit, all inside the lab. Algorithm Confusion at Hard is unfair for the wrong reason: the difficulty is not the RS256-to-HS256 idea (that is a great Hard challenge), it is an invisible trailing newline in the key bytes that the challenge page cannot show you. A student can understand the attack perfectly, implement it perfectly against the key as displayed, and still fail. That is luck, not skill.
- Burp-first feasibility: Excellent. I used curl, but every single winning request above is one raw HTTP request (or the 3-request clickjacking chain) that can be replayed verbatim in Burp Repeater, and most challenges are explicitly designed around Proxy history plus Repeater. Token crafting (none, weak secret, kid tricks, jku, confusion) needs an offline signer, and the lab hints themselves point at the node/jwt CLI approach, which works. Nothing in my three modules needs a real browser except appreciating the clickjacking frame visually, and even that chain replays fine in Repeater because the server tracks the framed load through the session.
- Suggestions (concrete): (1) Fix alg-confusion fairness: make the verifier use the key bytes exactly as displayed on the pubkey page (trim the trailing newline on both sides), or render the key in a textarea whose value is byte-exact and label it "copy this exactly, including the final line break". Also change the denial message for a near-miss signature to something less misleading, or at least make hint 1 say the exact bytes, including the trailing newline, are the key. (2) Hide the scoreboard empty-state element by default in the markup and only reveal it via script when a filter truly matches nothing. (3) Give the JWT index cards direct challenge URLs instead of in-page anchors. (4) For weak-secret, either soften "tiny wordlist" in the briefing or pick a secret that sits in everyone's first 30 guesses. (5) Fix the leaked no-expiry token so its issued-at precedes its expiry when decoded (purely cosmetic, but CTF players decode everything and notice). (6) Keep the clickjacking verification model exactly as is; requiring the framed load plus the post-back with a single-use token is the best anti-cheat design in the three modules and other modules should copy it.
- Rating: 4
