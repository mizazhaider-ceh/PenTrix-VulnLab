# Student Review: Pwn Pixie (ctf-02)
- Modules tested: cors (6 challenges), upload (8 challenges), idor (7 challenges). Tested only http://127.0.0.1:18409/ with a dedicated cookie jar (/tmp/cookies-ctf-02.txt). Speed-run style: skimmed briefings, went straight at each vulnerability, then ran a cheat battery on every challenge (bare claim with no exploit, replay, trivial one-byte/empty inputs, cross-challenge capture).
- Time to first flag per module: cors ~1 minute (bare prove requests won instantly), upload ~3 minutes (one-byte .html upload), idor ~7 minutes (profile IDOR as alice). All 21 assigned flags captured in about 10 minutes total.
- What worked well: Every challenge's intended exploit path works exactly as briefed. The CORS /cors/prove design is excellent for a CTF player: one GET with the right origin proves the header combination and the lab awards the flag immediately, with the exact response headers shown on the page so you learn the check. IDOR endpoints are clean single GET/POST shots (change :id, change user_id, force-browse a path). Upload endpoints take the raw body with ?filename=, which makes curl/Burp Repeater testing fast. The apikey-regen anti-cheat (tracking which key was rotated through the IDOR and by whom) genuinely blocks the lazy reuse of another user's seeded key. Replays are idempotent: re-running a winning request re-awards to the same session without double-counting the scoreboard.
- Bugs found (with reproduction):
  1. Upload and IDOR module index pages never show captured state. Repro: capture flags, then GET /upload and /idor: zero "flag captured" pills, while /cors shows 6. Cause: the cors index uses captured(req, ...) per card, but upload/index.js and idor/index.js have no captured() usage at all. A student cannot see progress on those module pages.
  2. Bob's avatar stays defaced instance-wide after the overwrite lab. Repro: POST /upload/avatar?user=bob with any bytes, the lab awards the flag; bob's avatar now serves attacker bytes for every student until the server restarts (shared.js only seeds the file if missing, never restores a modified one). I restored it manually after testing. Comment deletion self-heals on the next page view, but avatars do not.
  3. One filename awards two flags at once on /upload/ext-blacklist. Repro: POST /upload/ext-blacklist?filename=x.svg.SVG with SVG bytes: the response contains both the "Case bypass" flag and the "Double extension bypass" flag. The blacklist is dodged by the final .SVG while the double-extension regex also matches .svg. in the middle. Two challenges meant to teach two separate techniques fall to one request.
  4. stored-xss awards with a one-byte body containing no HTML at all. Repro: POST /upload?filename=a.html with body "x" (a single byte): the lab awards the flag. No script, no HTML, nothing ever needs to render. The same applies to upload-ctype: POST /upload/mime-check?filename=a.html with Content-Type: image/png and body "x" wins. The flag checks the filename and header only, never the content.
  5. The supposedly Hard polyglot challenge falls to a 12-byte marker string. Repro: POST /upload/polyglot?filename=x.gif with body "GIF89a onx=1": the lab awards the flag. The script detection is a regex (/<script[\s>]|on\w+\s*=/i) over the body, so any body containing "onx=" passes without being a real GIF/HTML polyglot. No real polyglot technique is required.
  6. CORS: wildcard-data and expose-headers award with literally any origin, no exploit needed. Repro: GET /cors/prove?vuln=cors-wildcard-data&origin=junk and GET /cors/prove?vuln=cors-expose-headers&origin=junk: the lab awards both flags. These endpoints always send the vulnerable headers, so the "prove" step proves nothing beyond visiting a URL.
  7. Minor: the reflected-origin lab accepts the literal string "null" as an origin. Repro: GET /cors/prove?vuln=cors-reflect&origin=null: the lab awards the reflect flag because the endpoint echoes any string. A student fuzzing for the null-origin lab can accidentally win the reflect lab with the null lab's payload.
- Friction/confusion points:
  1. The live instance serves from a different directory than the repo copy named in my task briefing (files I uploaded landed under pentrix-verify/uploads, and my traversal file landed in the pentrix-verify root). If a student is told to inspect stored files locally, the path they expect will not match. Worth one line in the lab docs.
  2. The traversal read endpoint needs one more ../ than intuition suggests (5 levels to reach / from the uploads dir, not 4), because the uploads dir sits 5 levels deep. I initially got 404s on /etc/passwd at 4 levels and thought reads were restricted; the arbitrary read works fine at the right depth.
  3. For the email-change lab, the original emails are not shown anywhere obvious after you change them (I restored admin and alice from the seed values visible in the invoice text). A student who overwrites them has no in-lab way to see what they were.
  4. The seeded API keys use a different format (idor_alice_key_...) than regenerated ones (idor_<hex>), which briefly confused my key extraction during testing. Harmless, but noticeable.
- Hint quality (helpful? spoilery? useless?): Helpful and well layered. The 3-level ladder format (nudge, technique, KEY INSIGHT) is good. Level 3 is openly spoilery by design (the strip-once "start" text literally hands you the winning filename evil.s.svgvg), which is fine for a learning lab but means a CTF player can skip all thinking by reading hint 3. The CORS challenge pages also pre-fill the winning origin in the prove form, so level-1 effort is enough there. For students the ladders teach; for cheaters they are the cheat sheet.
- Difficulty fairness: Mostly fair, with one big outlier. Easy labels on cors-wildcard/expose are honest (they are trivial by design). upload-case, upload-ctype, stored-xss, strip-once, traversal, and all IDOR labs match their labels. The outlier is upload-polyglot labeled Hard: it is currently the easiest flag in the upload module because the marker-string regex accepts a 12-byte non-polyglot body. A student who builds a genuine polyglot does unnecessary work; a cheater does less work than on any Easy lab.
- Burp-first feasibility: 100%. Every challenge is a single GET or POST with query parameters or form fields, all readable in Proxy history and replayable in Repeater. No JavaScript execution is required for any flag (even the stored-XSS ones award server-side on upload). The CORS labs explicitly teach the Repeater workflow (add Origin header, watch response headers).
- Suggestions (concrete):
  1. Make stored-xss and upload-ctype check the body like polyglot does: only award when the uploaded bytes contain scriptable content (e.g. a <script> tag or event handler), so a one-byte "x" body wins nothing.
  2. Harden the polyglot detector: require the body to contain a plausible HTML structure (for example both an opening <script and its closing tag, or real markup after the GIF header) instead of a bare regex that matches "onx=1". Alternatively relabel the challenge Easy, since the current check is easier than the Easy labs.
  3. Split the two ext-blacklist flags so one request cannot earn both: award the case flag only when the double-extension pattern is absent, and the double-extension flag only when the final extension is lowercase-blocked-bypass style. Or document that one clever filename may win both and treat it as a feature.
  4. Add captured() pills to the upload and IDOR module index cards, matching the CORS module, so students see per-challenge progress.
  5. Re-seed bob's avatar when it is detected as modified (compare against the known original on read), or add a note in the lab that overwriting it affects all students and how to restore it.
  6. For cors-reflect, reject the literal origin "null" (or route it to the null lab's logic) so the two origin labs do not overlap.
  7. Consider requiring the CORS wildcard/expose proves to show the header on the actual vulnerable endpoint response rather than accepting any origin string, or keep as-is but mark them as freebie warmups in the brief.
- Rating: 1-5: 4. The three modules are fast, fun, and genuinely teach the vulnerability shapes; the prove-it pattern for CORS is the best flag UX of the three. One point off for the polyglot difficulty mismatch and the flags that fall to zero-technique requests (one-byte uploads, any-origin CORS proves, double-flag filename), plus the missing captured pills on two module pages.
