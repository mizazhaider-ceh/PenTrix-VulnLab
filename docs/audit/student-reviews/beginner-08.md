# Student Review: Day-One Omar (beginner-08)
- Modules tested: ReDoS (4 challenges) and XXE Injection (8 challenges), all 12 exploited live with curl against the shared pool instance, simulating Burp Proxy, Repeater and Intruder flows. All 12 exploits earned a flag.
- What worked well: The ReDoS module briefing explains backtracking in plain words and every ReDoS result page prints the pattern, the match result and the measured time, so I always knew exactly what the server did with my input. The XXE module briefing gives a full example payload with an absolute path, which made my first ever entity declaration succeed on the first try. The in-lab OOB collector is the star feature: it hosts my DTD, logs pingbacks and even shows a starter DTD template, so out-of-band exfiltration works with no external listener and no Burp Collaborator (important, since Community has none). The param challenge page explains the double-quote versus single-quote trick clearly, and the result page tells me exactly how many pingbacks carried the secret (2 in my run), which made success obvious. Lesson learned per challenge: email flag at 2412 ms, search flag at 30096 ms, billion laughs flag via the size side (about 8.9 million chars expanded, 764 ms), external DTD flag confirmed both in the response and in the collector log.
- Bugs found (with reproduction): (1) Marker reflection cheat on five XXE challenges. On a brand new session that had never run an exploit, POST /xxe/import with xml set to the literal text <data>XXE-SECRET-4471</data> (no DOCTYPE, no entity, no file read) and the lab awarded the flag. Same for the SSRF challenge: POST /xxe/import with xml <data>SSRF-INTERNAL-9921</data> and no http:// entity at all, flag awarded. Same on a fresh session for the SVG challenge: POST /xxe/svg with svg <svg><text>XXE-SECRET-4471</text></svg>, flag awarded. Same pattern on POST /xxe/xinclude and POST /xxe/soap with the marker typed as plain text. The marker strings are easy to learn: the SSRF one is printed in the module briefing itself, and the file one appears in the parsed output after the first legitimate file read, so after solving one challenge a student can fake the other four without learning anything. The external DTD and param challenges resisted this cheat (literal text scored 0 pingbacks and no flag was awarded), because they require a real collector pingback during the request. ReDoS challenges also resisted faking: no flag was awarded for any input under the time threshold. (2) Scoreboard re-verification was cut short: midway through testing the pool server stopped responding entirely (connection refused, nothing listening on the port), and per instructions I did not restart it, so the final scoreboard state could not be re-checked at the end.
- Friction/confusion points: (1) The ReDoS payloads the guides suggest are far stronger than needed and they hurt: following the URL challenge's own how text blocked the whole server for about 43 seconds, the username payload took 65954 ms, and the search payload 30096 ms. On a shared single-threaded server, one beginner following instructions freezes the lab for everyone. I had no idea I was overdoing it until the page came back a minute later. (2) The /redos/url and /redos/search endpoints are GET forms; my first curl used -d (a POST) and got a plain "Not found" page with no hint that I used the wrong method. A beginner will hit this in Burp too if they resend a captured request wrong. (3) The SSRF challenge tells me the target URL shape as http://127.0.0.1:PORT/... but as a day-one student I did not know where to find the port or the exact internal path; I only got there via hint rung 4 and by reading the XXE briefing note that names SSRF-INTERNAL-9921. (4) The external DTD challenge needs two separate trips (host the DTD on the collector page, then submit the import), and nothing on the /xxe/dtd form page itself says the DTD must be hosted first; I only understood the order from the challenge card's starting point. (5) Several XXE forms pre-fill the textarea with a near-complete or complete working payload (param, xinclude, dtd sample), which confused me about whether I was supposed to just press the button or write my own XML.
- Hint quality (helpful? spoilery? useless?): ReDoS email: helpful, rung 2 unlocked it (grow a run of valid characters, end with a match breaker, watch the timer). ReDoS username: spoilery but fine for Easy, the form note prints the pattern and the recipe. ReDoS url: hints are thin ("Same as email") but the how box hands over the payload shape, so combined they are spoilery. ReDoS search: helpful, rung 3 unlocked it (set q to the haystack's repeated character); the how box then spells out the compiled pattern. XXE file read: helpful, the module briefing example plus rung 3 (absolute path, find the echo point first) got me there. XXE SSRF: helpful, rung 4 unlocked it (exact URL shape, URL-encode the field). Billion laughs: helpful, rung 2 (cascade of entities, each level repeating the previous) was the key idea. External DTD: helpful, rung 2 and rung 3 plus the collector's starter DTD template. SVG: spoilery, the form itself shows the exact entity line to declare. XInclude: spoilery, the form pre-fills a working sample including the real path. Param OOB: very spoilery, the form pre-fills the complete working exploit, though the surrounding explanation text taught me the most of any challenge. SOAP: helpful, rung 2 (same DOCTYPE, keep the envelope intact) unlocked it.
- Difficulty fairness: Mostly fair. Username as Easy and SOAP as Easy felt right. The ReDoS Mediums are conceptually Medium but the runaway timings make them feel punishing rather than hard. Param OOB and SSRF are labeled Hard, but with the pre-filled sample and hint rung 4 they played easier than the external DTD challenge labeled Medium, which needed the most steps and the most thinking. Billion laughs Medium felt right once the cascade idea clicked.
- Burp-first feasibility: All 12 challenges are doable in Burp Community. Every exploit is a single request I can replay and edit in Repeater (GET parameters for ReDoS, the xml or svg form field for XXE). Intruder is optional only for ReDoS, to grow a run length step by step, and Community Intruder is slow but workable for a handful of positions. No challenge needs Collaborator, because the in-lab collector replaces it for both OOB challenges. The only Burp-specific trap is resending a ReDoS GET form as a POST, which returns a bare 404 page.
- Scoreboard check: On my first live fetch of /scoreboard with my session, the ReDoS section showed the correct module name, 4/4 count, 100 percent progress and all four challenge names (Catastrophic Email Regex, Nested Quantifier Username, Catastrophic URL Regex, Regex Injection Search) with Captured status, and the XXE section showed 8/8 at 100 percent. Names, counts and captured states displayed correctly at that point. A second verification pass was not possible because the server went down before I could finish it (see Bugs), so I cannot confirm the page still renders the same way now.
- Suggestions (concrete): (1) Award the five reflection-based XXE flags only when the marker arrives through entity expansion, not when it is typed into the input as plain text (the DTD and param challenges already prove the stricter check works). (2) Tune the ReDoS example payloads down so the suggested input lands just past 1000 ms (for example suggest fewer username characters and fewer URL segments), and add one line to the briefing warning that a bigger payload blocks the shared server for everyone for much longer. (3) On the /xxe/dtd form page, add one sentence: "First host your DTD on the collector page, then submit this form." (4) For the param, xinclude and SVG challenges, ship the form with a harmless placeholder instead of a working payload, and move the working shape into hint rung 3, so the Hard label means something. (5) Return a friendlier error for a wrong-method request on /redos/url and /redos/search, for example "this endpoint expects GET". (6) On the SSRF challenge card, print the full internal URL with the real port filled in, the way the collector page already prints its own URLs.
- Rating: 4
