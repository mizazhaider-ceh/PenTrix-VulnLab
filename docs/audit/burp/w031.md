## 1. ssrf-metadata (Cloud metadata SSRF)

- **Verdict:** BURP-CLEAN
- **Tools old -> new:** C -> BZ, C (BZ first)
- **Burp workflow steps:**
  1. Browse to the FetchKit debugger page (`/ssrf/fetch-meta`) through Burp Proxy.
  2. Submit a fetch, send the request to Repeater.
  3. In Repeater, change the `url` value to the cloud link-local metadata address (the credentials listing path), Send, and read the credential name from the response.
  4. In Repeater, change the `url` value to the credential name path and Send again to read the secret material.
- **Issues:** none. Plain GET with a query parameter; nothing Burp normalizes or mangles; the metadata service is simulated in-process so no external network or timing dependence.
- **Changes applied:** `tools` is now `'BZ, C'`; `start` rewritten as a Burp-oriented starting point (Proxy the page, send the request to Repeater, change the `url` value), no curl one-liner; `hints` rewritten to name the Burp step (Repeater, `url` value) as nudges without pasting the payload; `how` rewritten Burp-flavored but tool-neutral in substance.
- **Verification:** node --check passes; zero em dashes in diff; scratch server booted (DB_PATH=/tmp/burp-w031.db, PORT=18033); `/ssrf` index, `/ssrf/fetch-meta` landing, and `/ssrf/octal-ip` landing all returned 200; Repeater-equivalent GETs to `/ssrf/fetch-meta?url=...169.254.169.254...` returned the simulated credentials containing the flag. Existing test `ssrf-metadata` passes. Note: the in-process metadata simulation answers any request to the 169.254.169.254 hostname with the credential document, so the flag appears on the first metadata fetch; the two-step listing-then-credential workflow in the hints still works as described.

## 2. ssrf-octal-ip (Octal IP bypass)

- **Verdict:** BURP-CLEAN
- **Tools old -> new:** C -> BZ, C (BZ first)
- **Burp workflow steps:**
  1. Browse to the Octal IP fetch page (`/ssrf/octal-ip`) through Burp Proxy.
  2. Submit a fetch, send the request to Repeater.
  3. In Repeater, first send a plain dotted-decimal loopback `url` value and observe the 403 block.
  4. In Repeater, edit the `url` value to spell the loopback address with leading zeros and aim it at the internal secret path, then Send and read the flag from the response.
- **Issues:** none. Plain GET with a query parameter; the bypass is in the server-side URL parser (leading zeros read as octal) versus a naive substring blocklist, so no raw sockets, no malformed HTTP, no timing, no byte mangling involved.
- **Changes applied:** `tools` is now `'BZ, C'`; `start` rewritten as a Burp-oriented starting point (Proxy the page, send the request to Repeater, edit the `url` value), no curl one-liner; `hints` rewritten to name the Burp step (Repeater, `url` value) as nudges without pasting the payload; `how` rewritten Burp-flavored.
- **Verification:** node --check passes; zero em dashes in diff; scratch server booted; Repeater-equivalent GET to `/ssrf/octal-ip?url=http://0177.0.0.1:PORT/ssrf/internal/secret` returned the flag. Existing test `ssrf-octal-ip` passes.
