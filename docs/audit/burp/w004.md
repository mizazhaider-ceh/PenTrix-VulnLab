# Burp-first audit: w004, sqli/blind (Boolean Blind Injection)

## Verdict
BURP-CLEAN. The challenge is a textbook boolean blind SQLi oracle ("Product exists." vs "Not found."). Standard Burp Community workflow fully solves it: Repeater compares the true/false responses one condition at a time, and Intruder automates character extraction by matching on the true answer. No redesign needed; only the vuln metadata needed Burp-first wording. Changes applied to modules/sqli/challenges/blind.js only.

## Tools: old -> new
- Old: `B, C`
- New: `BZ, B, C`

## Burp workflow steps
1. Proxy: open the Stock lookup page (/sqli/product) with Burp intercepting, check a normal id and send the request to Repeater.
2. Repeater: establish the oracle baseline. Send id=1 (true) and confirm the page answers "Product exists."; send a nonexistent id and confirm the page answers "Not found." These two responses are the only thing the oracle ever returns.
3. Repeater: probe boolean conditions. Inject a condition that is true only when your current guess about the admin secret is correct, and watch the page flip between its two answers to confirm or reject each guess.
4. Repeater or Intruder: extract the admin secret one character at a time. In Intruder, set a payload position over the guessed character, attack a character set, and match on the true ("Product exists.") response; flag results to read off the secret.
5. Browser: paste the extracted secret into the "Submit extracted admin secret" form on the product page to earn the flag.

## Issues found
1. Metadata was curl-first: `tools` was "B, C" and `start` was a curl one-liner, contradicting the Burp-first lab voice (D16).
2. The singular `hint` and the `hints` array named no Burp step, so a student following the lab voice got no pointer toward Repeater/Intruder.
3. The second hint embedded a concrete payload fragment ("the first character is 'P'") as an example, which is closer to a worked solution than a nudge; removed during the rewrite.
4. No functional issues: the oracle is stable ("Product exists." vs "Not found.", errors collapse to "Not found."), exactly what tests/sqli.test.js (the oracle extraction test) relies on.
