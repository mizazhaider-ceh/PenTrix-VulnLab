# Burp-first audit w060: race-ratelimit

## Verdict
CLEAN. Fully solvable via Burp Suite Community. The race window is a
150-250ms async accounting gap (modules/race/shared.js `WINDOW()`),
exploited with plain parallel HTTP POSTs to /race/ratelimit/hit. The test
helper `burstN` in tests/race.test.js uses only `Promise.all` over normal
POSTs: no raw sockets, no protocol tricks, no custom framing. Burp Intruder
parallel mode reproduces this exactly, so no redesign is needed.

## Tools
- Old: `P, C`
- New: `BZ, P, C` (BZ first per D16; Python and curl remain valid alternatives)

## Burp workflow steps
1. Start Burp, enable Intercept off, and Proxy-browse the Rate-limited API
   page at /race/ratelimit.
2. Click "Send one request" once and send that POST /race/ratelimit/hit to
   Repeater. Replay it a few times: each replay raises the window count by
   exactly one, and the 6th returns 429.
3. Reset lab state (/race/reset), send the same request from Repeater to
   Intruder, and run one parallel-mode attack with 20 concurrent requests.
4. Watch the response cards: accepted counts climb past 5, the page calls
   out "More than 5 requests were allowed in one window", and the flag bar
   appears. The flag is awarded once per session (FLAG BAR and FLAG SECRECY
   untouched).
