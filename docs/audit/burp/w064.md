# w064 Burp-first audit: code-leak (OAuth Lab 2)

## Challenge
code-leak: Authorization Code Leaked in Server Log (OAuth Lab 2). The IdP
writes every issued authorization code into a world-readable request log,
and the token endpoint accepts a code owned by a different IdP user. The
flag is awarded when a direct exchange succeeds for a code that belongs to
someone other than the requester.

### Verdict
BURP-CLEAN. The full exploit chain works through Burp Suite Community with
Proxy + Repeater. The leak is read through the normal browser (proxied),
which renders the world-readable log at /oauth/idp/log; finding alice's
line and copying the 32-character code after ?code= is plain browser work.
The spend is a vanilla form POST to /oauth/idp/token with
client_id=pentrix-spa (a public client, so no secret and no special
headers), reproducible in Repeater with zero byte tricks: no raw sockets,
no malformed HTTP, no encoded bytes, no non-HTTP protocols. Session
identity travels in a normal session cookie, and the flag is awarded
server-side when the endpoint accepts alice's code from a non-alice
session.

### Tools: old -> new
- old: `B, C` (Browser, curl)
- new: `BZ, B` (Burp/ZAP first, then Browser)

### Issues found in the previous metadata edits
- The old `start` field was a two-step curl recipe (curl login as bob, curl
  the log), which contradicts the Burp-first doctrine (D16).
- One old hint pointed at the wrong path: `/oauth/log (or similar)`, while
  the real route is `/oauth/idp/log`. The new hints use the correct route.
- The old `tools` did not lead with Burp/ZAP.
- No other issues: the edits are metadata-only (see below), hints are
  nudges that name the Burp step without pasting exploit payloads, and the
  file contains zero em dashes.

### Changes applied
In `modules/oauth/challenges/code-leak.js`, vuln object only (4 insertions,
4 deletions; router and all logic untouched):
- `tools`: `B, C` -> `BZ, B`.
- `start`: rewritten as a Burp workflow (set Burp as the browser proxy,
  open the log in the browser, copy the 32-character code, POST it in
  Repeater from a session that is not alice); no curl one-liner.
- `hints`: three Burp-flavored nudges (open the log in the proxied browser
  and find the authorize line, copy her code and send it to Repeater, spend
  it as bob or logged out). No exploits pasted.
- `how`: Burp-flavored rewrite naming the token endpoint and the public
  client parameter.

### Burp workflow steps
1. Send the browser through Burp Proxy. Open the IdP server log at
   /oauth/idp/log in the browser.
2. Find the line with `authorize user_id=` and a `?code=` at the end from
   alice's seeded login, and copy the 32-character code after `?code=`.
3. In a Repeater tab, POST the code to /oauth/idp/token with
   client_id=pentrix-spa, from a session that is not alice: either log in
   as bob in the proxied browser first, or send with no IdP session at all.
   The JSON response carries the flag when the stolen code is accepted.
