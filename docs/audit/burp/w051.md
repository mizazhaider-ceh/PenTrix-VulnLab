# Burp-first audit w051: XXE in Uploaded SVG (xxe/xxe-svg), XInclude File Inclusion (xxe/xxe-xinclude)

Both challenges POST a single XML text field through a normal HTML form and parse it server-side with external resource resolution enabled. No file upload, no multipart, no raw sockets, no malformed HTTP, no bytes Burp mangles, no non-HTTP protocol. Standard Burp Community tooling (Proxy + Repeater) covers the full exploit chain.

## Challenge 1: XXE in Uploaded SVG (`xxe-svg`)

### Verdict

**BURP-CLEAN.** The full exploit chain runs over a plain `POST /xxe/svg` with a form-urlencoded body. Capture the extractor form submission in Proxy, send it to Repeater, replace the `svg` parameter with an SVG carrying a DOCTYPE that declares an external entity, and read the `<text>` extraction results in the response.

### Tools

- Old: `B, C` (Browser, curl)
- New: `BZ, B` (Burp/ZAP first, Browser kept for loading the extractor form)

BZ goes first because the entire solve is Proxy-to-Repeater field editing.

### Burp workflow steps

1. Proxy your browser through Burp and open GET `/xxe/svg` (the SVG text extractor form).
2. Submit the form once with a plain SVG so you have a baseline in Proxy HTTP history.
3. Find the `POST /xxe/svg` request in Proxy HTTP history and send it to Repeater.
4. In Repeater, replace the `svg` parameter with an SVG that declares a DOCTYPE with an external entity pointing at the secret file, and reference that entity inside a `<text>` element. Burp URL-encodes the body for you.
5. Send and read the extracted text section of the response: the resolved entity content lands in the `<text>` extraction results.

### Issues

- Tooling was curl-first (`tools: 'B, C'`, `start` was a two-line curl one-liner, `how` said "Upload an SVG"), which fights D16's Burp-first voice.
- Despite the "upload" wording, the challenge uses a textarea named `svg` (form-urlencoded), not multipart. The task note about "multipart intercept" does not apply; Repeater handles the urlencoded body trivially. No redesign needed for this.
- Hints named the trick but not the Burp step; the ladder now names Proxy baseline capture, Repeater, and reading the extractor output, without pasting exploits.
- No functional blocker: entity expansion works over plain HTTP, parameters stay intact through Burp, and the flag bar and flag secrecy are unchanged.

### Changes applied

- `tools`: `B, C` -> `BZ, B`.
- `start`: now Burp-oriented (Proxy, submit baseline, find POST in history, Repeater, replace `svg` field); no curl one-liner.
- `hints`: three nudges naming the Burp steps (baseline capture in Proxy, Repeater field replacement, read the extractor output); no exploit pasted.
- `how`: Burp-flavored, tool-neutral on the exact DOCTYPE so the learner discovers it.
- Verified: `node --check` passes, diff has zero em dashes, scratch boot (DB_PATH=/tmp/burp-w051.db, PORT=18051) returned HTTP 200 for `/xxe/svg`, server killed after.

Capture the importer form submission in Proxy, send it to Repeater, replace the `xml` parameter with XML using the XInclude include element, and read the expanded document in the response.

### Tools

- Old: `B, C` (Browser, curl)
- New: `BZ, B` (Burp/ZAP first, Browser kept for loading the importer form)

BZ goes first because the entire solve is Proxy-to-Repeater field editing.
