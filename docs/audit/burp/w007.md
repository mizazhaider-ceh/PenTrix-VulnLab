## Challenge 1: limit-offset (LIMIT/OFFSET Injection)

**Verdict: BURP-CLEAN**

**Tools:** old `B` -> new `BZ, B`

**Burp workflow steps:**
1. Configure the browser to proxy through Burp and open `/sqli/paged`.
2. Find the `GET /sqli/paged?limit=2` request in Proxy history and send it to Repeater.
3. In Repeater, change the `limit` parameter to LIMIT syntax the form never
   offers (values beyond a plain positive page size) and resend.
4. Compare each response against the default 2-row page: when the returned row
   set shifts (more rows, or different rows), the flag block renders in the page.

**Issues:** none. The payload is a plain ASCII query parameter (`limit=-1`,
`limit=0,100`). No raw sockets, no malformed HTTP, no timing dependence, no
bytes Burp normalizes or mangles. Burp Repeater sends the parameter exactly as
typed, and the award condition (non-numeric limit that changes the page) is a
pure response-content check.

**Changes applied:**
- `tools`: `B` -> `BZ, B` (Burp first, browser still useful for viewing the page).
- `start`: replaced the curl one-liner with a Burp-oriented starting point
  (browse through the proxy, send to Repeater, tweak `limit`).
- `hint`/`hints`: rewritten to name the Burp step (Proxy, then Repeater);
  nudges only, no pasted exploits.
- `how`: Burp-flavored (tamper with the parameter in Repeater).

## Challenge 2: like-wildcard (LIKE Wildcard Exfiltration)

**Verdict: BURP-CLEAN**

**Tools:** old `B, C` -> new `BZ, B, C`

**Burp workflow steps:**
1. Configure the browser to proxy through Burp and open `/sqli/wildcard`.
2. Run one normal search, find the `GET /sqli/wildcard?q=...` request in Proxy
   history, and send it to Repeater.
3. In Repeater, build the boolean oracle: break out of the LIKE pattern with a
   quote and add a subquery against the `users` table so that every product
   matches only when the character guess is right. The response flips between
   "all N products match" and "0 of N products match".
4. Hand the oracle to Intruder with a character payload set per secret position
   and grep the match count in the response (Grep - Match on the count line).
5. Extract the full admin secret, paste it into the submit form, and the flag
   block renders on acceptance.

**Issues:** none. The oracle payload lives entirely in a standard URL query
parameter; quotes, spaces, comparison operators, and the SQL comment terminator
are all plain ASCII that URL-encode cleanly and that Burp Repeater/Intruder pass
through untouched. The true/false signal is a response-body count, not timing.
No raw sockets, no malformed HTTP, no Burp-mangled bytes, no curl-specific
behavior (curl kept in the tool list only as an optional scripting aid, same as
the sibling blind challenge).

**Changes applied:**
- `tools`: `B, C` -> `BZ, B, C` (Burp first; Intruder is the natural driver for
  the character loop; browser kept for viewing, curl kept as optional aid).
- `start`: replaced the curl one-liner with a Burp-oriented starting point
  (browse through the proxy, run a search, send to Repeater, probe `q`).
- `hint`/`hints`: rewritten to name the Burp steps (Proxy, Repeater, then
  Intruder with a character payload set); nudges only, no pasted exploits.
- `how`: Burp-flavored (build the oracle in Repeater, drive extraction with
  Intruder, submit the secret).
