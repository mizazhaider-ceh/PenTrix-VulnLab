# w109 Burp Audit: cors-reflect, cors-regex (CORS module)

## cors-reflect: Reflected Origin with Credentials

### Verdict: BURP-CLEAN

The full exploit chain is standard HTTP: a GET with an `Origin` request
header, read the `Access-Control-Allow-Origin` / `Access-Control-Allow-Credentials`
response headers. Works in Repeater, observable in Proxy HTTP history, no raw
sockets, no binary trickery, nothing Burp mangles. D16 satisfied.

### Tools: old -> new

- Old: `B`
- New: `BZ, B`

Burp leads (Proxy, Repeater); the browser stays because the end goal is
showing a cross-origin read inside a victim's browser.

### Burp workflow steps

1. In Burp, open the built-in browser (Proxy tab, Open browser) and navigate
   to `/cors/api/profile`. Confirm the request appears in Proxy HTTP history.
2. Right-click the request and Send to Repeater. Add an `Origin` request
   header with any origin (e.g. `https://evil.com`) and send.
3. The response reflects that origin in `Access-Control-Allow-Origin` and adds
   `Access-Control-Allow-Credentials: true`. Any origin works, there is no
   allowlist at all.
4. Load the attacker page served on 127.0.0.1 in a browser routed through
   Burp Proxy and let it fetch the victim API with credentials. The reflected
   ACAO tells the browser the read is allowed, so the profile (including
   alice's secret) comes back. The flag is awarded via `/cors/prove`.

### Issues

- None for Burp. Nothing in the chain needs curl, raw sockets, or bytes Burp
  normalizes. The old `start` curl one-liner is replaced, but that was
  presentation, not a protocol blocker.

### Changes applied

File: `modules/cors/challenges/cors-reflect.js` (vuln object only, no tests
touched, no push).

- `tools`: `B` -> `BZ, B` (BZ first per D16 voice; B kept since the goal is a
  cross-origin read in a victim's browser).
- `start`: replaced the curl one-liner with a Burp-oriented starting point
  (browse to the endpoint through the Proxy, send to Repeater, add an
  Origin header, send).
- `hints`: rewritten as nudges that name the Burp step (Repeater the
  request, watch the response headers, attacker page fetch through Burp
  Proxy). No exploits pasted.
- `how`: Burp-flavored chain (Repeater the Origin header, reflected ACAO
  plus Allow-Credentials earns the flag, or prove via `/cors/prove`).

## cors-regex: Regex Allowlist Bypass

### Verdict: BURP-CLEAN

The exploit is Intruder work by design: fuzz the `Origin` header value on
`/cors/api/data` with a small payload list of origins and watch which ones
come back echoed. Standard HTTP, one header, plain text. D16 satisfied.

### Tools: old -> new

- Old: `B`
- New: `BZ, B`

Burp leads (Repeater, Intruder Sniper on the Origin header); the browser
stays as the frame for the cross-origin read.

### Burp workflow steps

1. In Burp, browse to `/cors/api/data` through the Proxy and send the request
   to Repeater.
2. In Repeater, set an `Origin` header and confirm the allowlist regex
   behavior: `https://evil.com` is not echoed, `https://pentrix.lab` is not
   echoed either (the prove endpoint requires an attacking origin, not the
   genuine one).
3. Send the request to Intruder, mark the Origin header value as the Sniper
   position, and load a small payload list (origins such as
   `https://evil.com`, `https://pentrix.lab`, `https://pentrix.lab.evil.com`,
   `https://sub.pentrix.lab.evil.com`).
4. Run the attack and look at the responses: the origin that merely contains
   the expected string (`pentrix.lab` inside a longer domain) passes the
   regex (`^https://.*pentrix\.lab`, no subdomain boundary, no end anchor)
   and comes back reflected with `Access-Control-Allow-Credentials: true`.
5. The reflected winner (`https://pentrix.lab.evil.com`) earns the flag via
   `/cors/prove`.

### Issues

- None for Burp. The naive-regex design is itself the fuzz target, which is
  exactly what Intruder payload lists are for. No binary payloads, no
  Burp-normalized header tricks, nothing curl-specific in the original notes.

### Changes applied

File: `modules/cors/challenges/cors-regex.js` (vuln object only, no tests
touched, no push).

- `tools`: `B` -> `BZ, B` (BZ first per D16 voice; B kept as the frame).
- `start`: replaced the curl one-liner with a Burp-oriented starting point
  (Repeater the request, mark the Origin value in Intruder Sniper, fuzz with
  a short origin list).
- `hints`: rewritten as nudges that name the Burp step (Repeater for the
  behavior check, Intruder Sniper over the Origin header). No exploits
  pasted.
- `how`: Burp-flavored chain (fuzz the Origin header in Repeater/Intruder,
  the containing-origin passes and is reflected with credentials, or prove
  via `/cors/prove`).
