## idor/idor-email-change

- Verdict: BURP-CLEAN
- Tools: "BZ, C" -> "BZ, B"
- Burp workflow:
  1. In the browser (with Burp Proxy as the proxy), log in as alice and open Account settings (/idor/account). Submit the change-email form with any new address and find the POST /idor/account/email request in Burp's Proxy history.
  2. Right-click that request and send it to Repeater. Inspect the body parameters: email, and a hidden user_id that carries the caller's own account id.
  3. In Repeater, change the user_id parameter to another account's id (the admin's is a strong target) and keep the email value. Send the request.
  4. Observe the response: the confirmation page names the account whose address actually moved, and the flag box appears, because the server trusts the client-supplied user_id with no check against the logged-in user.
  5. Optional: verify the change took effect by browsing to the affected account's profile or account page.
- Issues: none. Standard application/x-www-form-urlencoded POST with a session cookie, no raw-socket needs, no byte-level quirks. The flag is awarded on the POST response page itself, so no follow-up request is required.
- Changes applied: vuln object in modules/idor/challenges/idor-email-change.js updated. tools now "BZ, B" (Burp first as the recommended path, curl dropped). start rewritten as a Burp-oriented starting point ("In Burp Proxy, log in as alice, open Account settings, and submit the change-email form while watching the request in the proxy history.", no curl one-liner). hint reworded to name the Burp step. hints ladder keeps its Nudge/Technique/Explicit tiers and now names the Burp step where it helps (capture in Proxy history, send to Repeater, replay with a changed user_id); no exploit payloads pasted. how stays tool-neutral ("POST /idor/account/email with another user's id in the user_id parameter.").
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (DB_PATH=/tmp/burp-w097.db PORT=18097 node app.js) returned HTTP 200 for /idor#idor-email-change; server killed afterwards (only my instance, other workers' instances untouched).
