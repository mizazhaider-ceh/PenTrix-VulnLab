## Burp workflow steps
1. Proxy on, open `/jsonp/snippet?callback=hello` in the Burp browser. In Proxy history, inspect the response headers: the JSONP is served as `text/html; charset=utf-8`, so the browser treats it as a document, not a script.
2. Send the captured GET to Repeater. The `callback` value reflects raw into the body (up to 300 chars), next to a per-session token embedded in the JSON data. Shape the `callback` parameter into an HTML-shaped value so the document context executes your markup; plain URL encoding carries the payload, no raw bytes needed.
3. Paste the Repeater-crafted URL into the browser and load it. Served as text/html, the response parses as a document and the injected markup runs in the target origin.
4. The executing code reads the per-session token from the response text and fires a same-origin beacon GET to `/jsonp/beacon-xss?v=mimetype&n=<token>`. The server consumes the single-use nonce, checks the session recorded an HTML-shaped attempt, awards the flag, and the beacon page shows it.

The chain is plain HTTP GETs plus one browser page load; the payload is pure ASCII in a URL-encoded query parameter, so Burp neither mangles nor normalizes anything. Session state rides the standard cookie jar (Proxy keeps it). No raw sockets, no malformed HTTP, no timing tricks, no curl-only behavior, no non-HTTP protocol. The beacon-from-browser pattern is the D16 standard (payload crafted in Repeater, execution plus beacon in the browser).
