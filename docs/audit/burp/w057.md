## upload-strip-once (Strip-once filter bypass)

**Verdict: BURP-CLEAN**

The exploit chain is a single standard HTTP request: `POST /upload/filter?filename=<nested>` with the file bytes as the raw body. The query parameter carries plain ASCII (no percent-encoding quirks, no malformed HTTP), and the response returns the stored name plus the flag box. Proxy, Repeater, and even a blank Repeater request typed by hand can reproduce it exactly. No raw sockets, no byte-mangling, no non-HTTP protocol.

**Tools:** `C` -> `BZ, C`

**Burp workflow steps:**
1. In Burp, set the browser to proxy through Burp and browse to `/upload`.
2. In Repeater, create a POST to `/upload/filter` with the nested filename in the `filename` query parameter.
3. Paste the SVG bytes into the message body, send the request.
4. Read the response: it shows the stored filename. The `.svg` extension survived the single strip, and the flag box plus fix panel are in the page.
5. Confirm by browsing to the `/upload/view/<stored name>` link: it serves as `image/svg+xml`.

**Issues:** none. `curl --data-binary` translates 1:1 into a Repeater request.

**Changes applied:** `tools` now leads with `BZ`; `start` rewritten as a Burp Repeater starting point (no curl one-liner); `hints` name the Burp step (Proxy, Repeater) and give nudges only, no pasted exploit; `how` is Burp-flavored and tool-neutral.

## upload-traversal (Path traversal on write)

**Verdict: BURP-CLEAN**

The exploit chain is two standard HTTP requests: `POST /upload/traverse?filename=../pwn.txt` with the file bytes as the raw body, then `GET /upload/traversed?f=../pwn.txt`. Repeater sends `../` in the query string verbatim (no normalization), the write happens outside the uploads dir, and the read endpoint returns the bytes. Flag box appears in the upload response. No raw sockets, no malformed HTTP, no Burp-normalization risk.

**Tools:** `C` -> `BZ, C`

**Burp workflow steps:**
1. In Burp, proxy through the module and send the upload POST to Repeater.
2. Set the `filename` query parameter to a name containing `../` segments, paste the file bytes into the body, send.
3. The response shows "That name resolved outside the dropbox folder" with the flag box and a link to the read-back endpoint.
4. In a second Repeater tab, send `GET /upload/traversed?f=` with the same filename to read the escaped file back as plain text.

**Issues:** none. No encoding or path-normalization traps; `path.normalize` runs server-side after Burp has delivered the request.

**Changes applied:** `tools` now leads with `BZ`; `start` rewritten as a two-step Burp Repeater starting point (no curl one-liner); `hints` name the Burp step (Proxy, Repeater) and give nudges only, no pasted exploit; `how` is Burp-flavored and tool-neutral.
