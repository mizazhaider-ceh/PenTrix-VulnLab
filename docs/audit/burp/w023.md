# Burp-first audit: w023, ssti/rce (Scope Leak, Data Exposure)

## Verdict
BURP-CLEAN. The exploit is a single plain HTTP GET to /ssti/greet with the name parameter set to a template expression that reads the in-scope server variable; the rendered greeting echoes the flag value and the flag is awarded inline on the page. Proxy captures the request, Repeater replays and mutates it, no Intruder run is even needed. Nothing here needs raw sockets, malformed HTTP, timing, Burp-mangled bytes, or curl-specific behavior (curly braces are ordinary query-string bytes that Express decodes either raw or percent-encoded). No redesign needed; only the vuln metadata needed Burp-first wording. Changes applied to modules/ssti/challenges/rce.js only.

## Tools: old -> new
- Old: `B, C`
- New: `BZ, B, C`

## Burp workflow steps
1. Proxy: open /ssti/greet in the browser with Burp intercepting, submit any name in the form, and send the intercepted request to Repeater.
2. Repeater: confirm expression evaluation. Set the name parameter to a harmless arithmetic expression in {{ }} and check that the greeting echoes the computed result (49), proving the template engine evaluates.
3. Repeater: probe the template scope. Change the name parameter to a {{ }} expression referencing the server-side variable that holds the flag (the module hint says its name is the most obvious one for the job) and send the request.
4. Read the flag: the rendered greeting echoes the in-scope variable's value, and the page awards the "Scope Leak (Data Exposure, Not RCE)" flag right below it. This is a scope leak, not RCE: no command runs, no shell output is involved.

## Issues found
1. Metadata was curl-first: `tools` was "B, C" and `start` was a curl one-liner, contradicting the Burp-first lab voice (D16).
2. The singular `hint` and the `hints` array named no Burp step, so a student following the lab voice got no pointer toward Proxy/Repeater.
3. `how` pasted the full worked payload (`name={{secretFlag}}`); reworded to a Burp-flavored, tool-neutral description that no longer hands over the answer.
4. No functional issues: the whole chain is one GET parameter; the award condition (`rendered.includes(secretFlag)`) is stable and matches what tests/ssti.test.js (the scope-leak probe test) asserts.

## Changes applied (modules/ssti/challenges/rce.js, vuln metadata only; router untouched)
- `tools`: "B, C" -> "BZ, B, C" (BZ first).
- `start`: replaced the curl one-liner with a Burp-oriented start: open the page with Proxy intercepting, send the request to Repeater, then change the name parameter to probe the scope.
- `hint`: reworded to name the Repeater step, still a nudge, no exploit pasted.
- `hints`: rewritten to name the Burp steps (send to Repeater, confirm evaluation with arithmetic, probe the scope for the flag variable); exploit fragments removed.
