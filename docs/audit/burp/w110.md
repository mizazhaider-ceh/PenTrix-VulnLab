# w110 verdicts

## cors-subdomain

- Verdict: BURP-CLEAN
- Tools: "B" -> "BZ, B"
- Burp workflow:
  1. Start Burp Suite Community with Proxy on 127.0.0.1:8080 and route your browser through it.
  2. Browse the Pentrix Partners page (/cors/subdomain) and click "Check my partner status". In Proxy history, find the GET /cors/api/partner request and right-click to send it to Repeater.
  3. In Repeater, add an Origin header (or edit the existing one) with a subdomain label of your own choosing under the trusted suffix, e.g. an invented label under trusted.pentrix.lab, and resend.
  4. Observe the response headers: the endpoint echoes your invented origin back as Access-Control-Allow-Origin with Access-Control-Allow-Credentials: true. The suffix check (hostname.endsWith('.trusted.pentrix.lab')) cannot tell your subdomain apart from a real partner's.
  5. Optional: use Intruder (Sniper) over the Origin header value with a small list of invented subdomain labels to confirm every label passes, while origins outside the suffix get no ACAO header back.
- Issues: none. The exploit chain is a plain GET with a hand-set request header, standard HTTP, no raw sockets, no Burp-mangled bytes, no curl-specific behavior. Tests confirm: evil.trusted.pentrix.lab awards the flag, while a plain subdomain (shop.trusted.pentrix.lab) and missing origin award nothing.
- Changes applied: vuln object in modules/cors/challenges/cors-subdomain.js updated. tools now "BZ, B" (Burp first, browser kept). start rewritten as a Burp-oriented starting point (send the partner API request to Repeater and work the Origin header), no curl one-liner. hints ladder now names the Burp step at each tier (watch ACAO in Repeater, swap the subdomain label in Repeater); nudges only, no exploit pasted. how made Burp-flavored: Repeater request to /cors/api/partner with an invented subdomain under trusted.pentrix.lab, plus the prove URL as an alternative.
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (DB_PATH=/tmp/burp-w110.db PORT=18110 node app.js) returned HTTP 200 for /cors/subdomain; GET /cors/api/partner with Origin https://evil.trusted.pentrix.lab returned Access-Control-Allow-Origin echo plus Access-Control-Allow-Credentials: true; scratch DB and log removed, server killed, port confirmed free.

## cors-wildcard-data

- Verdict: BURP-CLEAN
- Tools: "B" -> "BZ, B"
- Burp workflow:
  1. Start Burp Suite Community with Proxy on 127.0.0.1:8080 and route your browser through it.
  2. Browse the Pentrix Team directory page (/cors/wildcard) and click "Load team". In Proxy history, find the GET /cors/api/users request and right-click to send it to Repeater.
  3. In Repeater, resend the request exactly as captured and read the raw response headers.
  4. Observe: Access-Control-Allow-Origin: * rides on a response that returns every user's email address. No Origin header is needed at all; any website can fetch this directory cross-origin and read the body, no credentials required.
- Issues: none. The exploit chain is a plain GET with no special request setup, standard HTTP. No raw sockets, no Burp-mangled bytes, no curl-specific behavior. Tests confirm: the endpoint itself never awards the flag, the prove form without an origin awards nothing, and proving with https://evil.com awards.
- Changes applied: vuln object in modules/cors/challenges/cors-wildcard-data.js updated. tools now "BZ, B" (Burp first, browser kept). start rewritten as a Burp-oriented starting point (browse the team page, find the request in Proxy history, send to Repeater), no curl one-liner. hints ladder now names the Burp step (read raw response headers in Repeater, replay the request to confirm the wildcard rides on every response); nudges only, no exploit pasted. how made Burp-flavored: Repeater request to /cors/api/users, read the ACAO: * header on the email response, plus the prove URL as an alternative.
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (same instance as above) returned HTTP 200 for /cors/wildcard; GET /cors/api/users with Origin https://evil.com returned Access-Control-Allow-Origin: * over the user email JSON; scratch DB and log removed, server killed, port confirmed free.

Note: the in-page "Try it raw" curl payloadBlocks in both challenge pages were left untouched; only the vuln object fields (tools, start, hints, how) were changed per the audit scope. If a follow-up wants the page copy Burp-first as well, that is a separate page-text pass.
