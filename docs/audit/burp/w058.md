# Burp Audit Verdict: race-balance (w058)

## Verdict
BURP-CLEAN

## Tools old -> new
Old: `P, C`
New: `BZ, C`

Burp/ZAP moves to first position because the winning technique (a burst of
parallel transfer requests) is a textbook Intruder job. curl stays as the
second tag for the documented sequential check; the Python tag was dropped
because nothing in this challenge needs a script, and the Burp-first
doctrine prefers Intruder over a hand-rolled parallel client.

## Burp workflow steps
1. Proxy: browse to `/race/transfer` and submit the transfer form with Proxy
   intercept on. Forward the request, then send it to Repeater (right-click,
   Send to Repeater, or Ctrl+R).
2. Repeater: send one transfer of $100. The balance drops to $0 and no flag
   appears. This confirms the sequential path is safe and shows exactly what
   a winning response will look like (the "New balance" line).
3. Intruder: send the same request to Intruder. The form fields `to` and
   `amount` are plain body parameters, so use a Sniper attack with a null
   payload (or one trivial payload) and set the concurrent request count
   high enough that about 20 requests fire together.
4. Fire the attack and watch the responses: each response shows a balance,
   and one or more responses show a balance below zero with the flag box.
   The flag awards when the balance goes negative, which happens when every
   request passes the balance check against the same $100 before any debit
   lands.
5. Optional: reset the lab (`/race/reset`) and repeat to confirm the result
   is stable, not a one-off.

## Issues
None that force a redesign. The test wins the race with plain parallel HTTP
POSTs (`Promise.all` over 20 requests), no raw sockets, no malformed HTTP,
no byte-exact payloads. The check-to-use window is wide (150 to 250 ms per
`modules/race/shared.js`), so Intruder's parallel mode can reproduce what
the test does. Two honest caveats, neither blocking: Burp Community's
Intruder is throttled compared to Pro, so keep the concurrent request count
as high as it allows and use the reset link between attempts; and the
challenge page's own "Test it yourself" block still shows a curl/xargs
one-liner, which remains accurate but is no longer the recommended path.
FLAG BAR kept: the flag awards only when the balance goes negative, never
for a single sequential transfer. FLAG SECRECY kept: hints stay nudges, no
exploit payloads pasted anywhere.
