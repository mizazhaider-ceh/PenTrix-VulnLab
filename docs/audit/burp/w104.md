## proto/proto-constructor (Blacklist Bypass via constructor)

- Verdict: BURP-CLEAN
- Tools: "C" -> "BZ, B, C"
- Burp workflow:
  1. Open the merge console (/proto/constructor) in your browser with Burp Proxy on and submit a harmless query string. In Proxy > HTTP history, find the GET /proto/constructor request.
  2. Right-click the request and send it to Repeater.
  3. In Repeater, edit the query string: the blacklist drops any key containing the literal string __proto__, so spell the path to Object.prototype through constructor and prototype instead, setting the property the admin check tests. Send the request.
  4. Note that Burp (or the browser) may URL-encode the [ and ] characters as %5B and %5D; the server decodes them, so either form merges the same way.
  5. Open /proto/constructor/admin in the browser. The fresh {} object now inherits role = 'admin' from the polluted Object.prototype, and the flag box is awarded.
  6. Optional: use Intruder on the key segment to confirm that __proto__ is dropped (admin check stays denied) while constructor-based paths pollute (flag awarded), proving the blacklist is literal-string only.
