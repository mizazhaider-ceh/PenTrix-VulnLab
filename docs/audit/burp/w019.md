## xss-attr-breakout (XSS via Attribute Breakout)

### Verdict
BURP-CLEAN.

### Tools old -> new
`B` -> `BZ, B` (Burp first per D16; browser still needed to fire the beacon).

### Burp workflow steps
1. Proxy on, open `/xss/attr` in the Burp browser and submit the nickname form once with a harmless value.
2. In Proxy history, send the captured GET to Repeater.
3. In Repeater, set the `n` parameter to breakout candidates and read the response. The form field escapes the value, but the Preview card input reflects it raw inside `value="..."`, so watch for your markup landing unescaped in the preview input.
4. Once the response shows the breakout markup, copy the Repeater request URL into the browser. The injected script runs there and calls `/xss/collect`; the claim box then offers the flag.

The whole chain is a plain HTTP GET with one query parameter. URL-encoding of the quote and angle brackets passes through Burp untouched. No raw sockets, no malformed HTTP, no timing tricks, no curl-only behavior.

- `tools` listed only `B` with a curl `start` one-liner, contrary to D16.
- `hints` described the mechanism but never named the Burp steps (Proxy capture, Repeater tweak, response inspection).
- `how` was tool-neutral; `start` was a curl pipe to grep.

### Changes applied
- `tools`: `B` -> `BZ, B`.
- `start`: replaced the curl one-liner with a Burp-oriented starting point (Proxy, Repeater, watch the reflection, then browser).
- `hints[2]`: names the Burp step (build in Repeater, inspect reflection, load URL in browser to fire the beacon). Nudge only; no exploit pasted.
- `how`: Burp-flavored (Repeater craft, browser fires the beacon).
- Route, flag conditions, claim box: untouched.

## xss-backtick (XSS in a Template Literal)

### Verdict
BURP-CLEAN.

### Tools old -> new
`B` -> `BZ, B` (Burp first per D16; browser still needed to fire the beacon).

### Burp workflow steps
1. Proxy on, open `/xss/backtick` in the Burp browser and submit the status form once with a harmless message.
2. In Proxy history, send the captured GET to Repeater.
3. In Repeater, set the `m` parameter to `${...}` candidates and read the response. The reflection sits inside a template literal as `var msg = `...`;`, so watch for your expression surviving inside the backticks without a syntax error.
4. Once the response shows the expression intact, copy the Repeater request URL into the browser. The literal evaluates your expression on load, it calls `/xss/collect`, and the claim box offers the flag.

The whole chain is a plain HTTP GET with one query parameter. Burp handles the URL-encoding of `${`, `}` and any semicolons without mangling anything. No raw sockets, no malformed HTTP, no timing tricks, no curl-only behavior.

### Issues
- `tools` listed only `B` with a curl `start` one-liner, contrary to D16.
- `hints` described the `${...}` mechanism but never named the Burp steps (Proxy capture, Repeater tweak, response inspection).
- `how` was tool-neutral; `start` was a curl pipe to grep.

### Changes applied
- `tools`: `B` -> `BZ, B`.
- `start`: replaced the curl one-liner with a Burp-oriented starting point (Proxy, Repeater, watch the `var msg` reflection, then browser).
- `hints[2]`: names the Burp step (build in Repeater, check the reflected script, load URL in browser to fire the beacon). Nudge only; no exploit pasted.
- `how`: Burp-flavored (Repeater craft, browser fires the beacon).
