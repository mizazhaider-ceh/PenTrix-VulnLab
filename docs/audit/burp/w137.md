## Verdict

BURP-CLEAN

## Exploit chain (Burp-first)

1. Browser routed through Burp Proxy: visit `GET /api/login/alice` to grab a session cookie.
2. Browse to `GET /api/me`, send the request to Repeater (Ctrl+R). The response shows your profile columns: `id`, `username`, `email`, `role` (role is `user`).
3. In Repeater, change the request to `PATCH /api/me` and add one extra key to the JSON body that raises your privilege level. Send it.
4. The response returns `"flag"` and a follow-up `GET /api/me` shows `role: "admin"`.

Every step is standard HTTP over Proxy/Repeater. Adding JSON fields in Repeater is trivial. No raw sockets, no Burp-mangled bytes, no curl-specific behavior, no non-HTTP protocols.

## Burp workflow steps

Proxy on -> log in as alice (`GET /api/login/alice`) -> browse `GET /api/me`, send to Repeater (Ctrl+R) to read your columns -> in Repeater, build the `PATCH /api/me` request with one extra JSON key -> send -> flag in the response.
