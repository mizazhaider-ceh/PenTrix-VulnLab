# Burp-first audit w059: race-coupon

Challenge: modules/race/challenges/race-coupon.js (Single-Use Coupon Redeemed Twice)

## Verdict

CLEAN. The race window is fully reproducible with Burp Intruder's parallel
(concurrent requests) mode. No redesign needed. Vuln object updated to
Burp-first voice.

## Tools old -> new

- Old: `P, C` (Python, curl)
- New: `BZ, P, C` (Burp/ZAP first, Python and curl still possible)

## Burp workflow steps

1. Proxy the browser, redeem the coupon once normally to learn the request.
2. In Proxy HTTP history, right-click POST /race/coupon/redeem and send to Intruder.
3. Positions: clear all (or keep the request unchanged; the body carries no
   per-request data), Payloads: Null payloads, generate 20 payloads.
4. Resource pool: create a pool with concurrent requests set to 20 and assign
   the attack to it.
5. Start the attack. Count the responses showing "Coupon redeemed": more than
   one means the one-use coupon was double-spent, and the flag appears.

Why this works: the "already used?" check and the "mark used" write are split
by an async sleep of 150-250ms (modules/race/shared.js WINDOW()). Every
request in the burst passes the check before any write lands, so the coupon is
redeemed multiple times.

## Issues

- None blocking. The test (tests/race.test.js burstN) wins with 20 plain
  parallel POSTs via Promise.all: no raw-socket tricks, no special headers,
  no token requirement. The window (150-250ms) is wide enough for Intruder's
  concurrent requests, so the parallel burst is a faithful reproduction of
  what Intruder sends.
- Pre-audit voice mismatch: the vuln object listed Python/curl first and the
  page showed a curl one-liner, contradicting the Burp-first doctrine. Fixed.

3. `hints[2]`: now names the Burp step (send the redeem request to Intruder,

4. `how`: Burp-flavored ("Send POST /race/coupon/redeem to Burp Intruder and
   run a concurrent-request attack...").
5. "Test it yourself" panel on /race/coupon: replaced the
   `seq 1 20 | xargs -P20` curl one-liner with numbered Intruder steps
   (send to Intruder, Null payloads x20, resource pool with 20 concurrent
   requests, count the successes).
