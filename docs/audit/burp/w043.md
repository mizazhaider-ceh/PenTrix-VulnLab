## cmdi-newline (Ping Gadget v5, separators blocked)

**Verdict:** BURP-CLEAN

**Tools old->new:** `B, C` -> `BZ, B`

**Burp workflow steps:**
1. In Burp's browser (Proxy on), open the ping5 gadget and submit a plain host like 127.0.0.1. In Proxy history, find the request and send it to Repeater.
2. Try a classic separator in the host value to confirm the filter strips ; & |.
3. In Repeater, place a URL-encoded newline (%0a) between a valid host and a command that prints recognizable output, so each line runs as its own statement. Send the request and read the response body to confirm the second command's real output before claiming the flag.

**Issues:** The test builds its exploit with `encodeURIComponent`, i.e. the newline travels as `%0a`, exactly what Burp Repeater sends and what a browser percent-encodes. A literal raw newline typed into Repeater's URL field would be re-encoded by Burp, so the encoded form is the correct path and the hints name it explicitly. No redesign needed; the `%0a` form is Burp-safe (burp keeps it encoded in the raw request), and the award fires on the decoded newline server side.

**Changes applied:**
- hints: rewritten as a three-step Repeater nudge ladder (observe the strip, recall %0a, place newline between host and command), no exploit pasted.
- tools: `BZ` first.
- start: Burp-oriented starting point (proxy a plain request, push to Repeater), curl one-liner removed.
- how: Burp-flavored, %0a named as the vehicle, no example payload.

**Verification:** node --check passed on both files; zero em dashes in the diff; scratch server booted (DB_PATH=/tmp/burp-w043.db PORT=18043) and both /cmdi/ping3 and /cmdi/ping5 returned 200, then the server was killed.
