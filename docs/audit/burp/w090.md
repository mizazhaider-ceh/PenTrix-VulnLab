# Burp Audit: otp-bruteforce (w090)

## Verdict
BURP-CLEAN. The whole exploit chain is plain HTTP and works in Burp Suite Community with Proxy, Repeater and Intruder.

## Tools old -> new
Old: `P, C`
New: `BZ, P, C` (Burp/ZAP now listed first; Python and curl stay as alternatives)

## Burp workflow steps
1. Enable the proxy and browse to `/auth/otp-reset` in the Burp proxy browser. Note the recovery token printed on the page.
2. Submit the "Verify and reset" form once with any 4-digit guess. Forward the request through the Proxy and send that POST (`/auth/otp-reset/verify`) to Intruder.
3. In Intruder, set the attack type to Sniper and clear all payload positions, then mark only the `otp` field with the payload marker (leave `token` and `newPassword` fixed).
4. Choose a numeric payload set covering 0000-9999 (min integer 0, max integer 9999, step 1, min integer digits 4, max integer digits 4).
5. Start the attack and grep the responses: failures render "Wrong code", the single hit renders "Password changed" and the flag box. That is the OTP; complete the password reset for admin.

## Issues
None. The verify endpoint is a standard URL-encoded form POST with no rate limiting, no lockout and no expiry, so the attack is fully automatable. Success and failure pages differ in content and length, so Intruder result filtering is reliable. Burp Community throttles Intruder, so a full 0000-9999 run is slow, but that is a pacing issue, not a design flaw.

## Changes applied
- `hint`: now names the Intruder sniper attack and grepping for the success page.
- `hints`: ladder rewritten to name the Burp step at each level (count the space, set sniper on the otp field, watch for the response that differs). No exploit code is pasted.

- `how`: Burp-flavored (Intruder sniper over the otp field, numeric payload 0000-9999).
- `start`: replaced the curl one-liner with a Burp-oriented starting point (proxy browser to the reset page, copy token, send verify POST to Intruder, sniper on the otp field).
