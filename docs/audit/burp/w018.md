# Burp-first audit w018: dom (DOM-based XSS)

## Verdict
BURP-CLEAN. The payload is delivered in the URL fragment of a normal browser navigation, and the beacon is a browser-fired standard HTTP `fetch()` GET to `/xss/collect`. No raw sockets, no malformed HTTP, no Burp-normalized bytes, no non-HTTP protocol. All of it is interceptable and replayable through Burp Proxy and Repeater (Community edition is enough).

## Tools old -> new
- Old: `B, DT` (Browser, DevTools)
- New: `BZ, B, DT` (Burp/ZAP first, Browser kept, DevTools kept)

## Burp workflow steps
1. Start Burp Proxy and configure the browser to use it.
2. Browse to `/xss/dom` in the proxied browser. In Proxy HTTP history, confirm the server response is just a static page (the fragment never leaves the browser).
3. View the page source in the browser and read the inline script: it reads `location.hash`, URL-decodes it, and assigns it to `innerHTML`.
4. Craft a URL of the form `/xss/dom#<event-handler payload>` that fires the `/xss/collect` beacon (parameters `c`, `v=dom`, `n=window.__px`) on page load. Remember that a `<script>` tag inserted via `innerHTML` never executes, so the handler must fire on its own.
5. Paste the crafted URL into the proxied browser address bar and load it. In Proxy HTTP history, watch the browser fire the beacon GET to `/xss/collect`. The flag is awarded on the claim page.
