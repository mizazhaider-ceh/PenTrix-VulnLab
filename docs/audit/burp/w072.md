## jku (Untrusted jku Key Server)

**Verdict: BURP-CLEAN**

The exploit chain is two standard HTTP requests, both already friendly to the lab's own UI. First, `POST /jwt/attacker-keys/register` publishes a kid and HMAC secret on the in-lab attacker key server (a plain form POST; the browser form at `/jwt/attacker-keys` does exactly this). Second, `POST /jwt/jku` submits the forged token, whose `jku` header points at the lab's own JWKS endpoint. The server performs the JWKS fetch itself, so nothing about that fetch depends on the attacker's tooling. Repeater sends the token POST verbatim (URL-encoded form body, no binary, no mangled bytes), and the 200 response carries the "Welcome, admin" page with the flag box. The only step Burp cannot do alone is signing the token, which still needs a JWT library (Node with jsonwebtoken), hence `N` stays. No raw sockets, no curl-specific behaviors, no non-HTTP protocol.

**Tools:** `N, C` -> `BZ, N, C`

**Burp workflow steps:**
1. In Burp, route the browser through Proxy and browse to `/jwt/attacker-keys`.
2. Fill in the "Publish key" form (kid and HMAC secret) and submit; it is a plain form POST that appears in Proxy history.
3. Forward the kid and secret out of band to the signing step: sign an admin token with the secret (HS256), with the `jku` header pointing at your published JWKS URL and the `kid` header matching.
4. In Repeater, send `POST /jwt/jku` with the token as the `token` form field.
5. Read the response: the "Welcome, admin" page with the flag box confirms the flag; the fix panel is in the page.

**Issues:** none. Every request is standard HTTP with a URL-encoded body; nothing for Burp to mangle. The hints previously described an RSA keypair flow ("publish the public half", "your private key") while the challenge actually uses a shared HMAC secret, so the hints were rewritten to match the real oct-key flow.

**Changes applied:** `tools` now leads with `BZ` (kept `N`, kept `C`); `start` rewritten as a Burp Repeater starting point (no curl one-liner); `hints` name the Burp step (Proxy, Repeater), give nudges only with no pasted exploit, and were corrected to the shared-secret model; `how` is Burp-flavored and tool-neutral. FLAG BAR and FLAG SECRECY untouched.
