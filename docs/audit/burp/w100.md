## log-leak (Session ID in Debug Log)

- Verdict: BURP-CLEAN
- Tools: B, DT -> BZ, B
- Burp workflow: With Burp Proxy on, open the verbose logging page (/session/logleak) and follow the link to the debug log viewer (/session/debug-log). Read the log rows and find the line recording the admin session start: it carries the admin sid in plain text. Send a GET for the admin panel (/session/leak-admin) to Repeater, set your Cookie header to lab_sid=<the admin sid>, and send. The response is 200 with the flag banner. No brute force needed, so Intruder is not required; Proxy plus Repeater covers the whole chain.
- Issues: none. Three plain GET requests (page, log viewer, admin panel) plus one Cookie header value. Burp Community Proxy and Repeater handle everything with no mangling: no URL encoding subtleties, no special characters in the sid (32 lowercase hex), no raw sockets, no malformed HTTP, no timing dependency, no Burp-mangled bytes, no curl-specific behavior, no non-HTTP protocols.
