# w086 verdicts

## bizlogic/biz-otp-client

- Verdict: BURP-CLEAN
- Tools: "BZ, C" -> "BZ, B, DT"
- Burp workflow:
  1. Start Burp Proxy and browse to /bizlogic/otp in the configured browser. The page shows the real OTP for the demo, but you do not need it. Enter any wrong OTP and submit, intercepting the POST to /bizlogic/otp/verify in Proxy.
  2. Right-click the intercepted request and send it to Repeater. Inspect the body: besides the otp field there is a hidden otp_ok field the JavaScript never flipped, because the OTP was wrong.
  3. In Repeater, flip the otp_ok field to its verified value while leaving otp wrong, then send the request. No browser-side check runs against the forged request.
  4. The response renders "OTP accepted, order confirmed" with "Verified without the real code." and the flag box, because the server trusted the client-side claim instead of verifying the OTP itself.
  5. Optional: use Intruder on the otp_ok value to confirm only the verified value succeeds, or compare the Repeater response lengths between the failed and forged submissions.
- Issues: none for the exploit chain. Minor note: the page copy still says "Try it with curl" and shows a curl starter payload box. That text was left untouched as out of this audit's edit scope; it contradicts the Burp-first voice on the card and could be reworded in a follow-up pass.
- Changes applied: vuln object in modules/bizlogic/challenges/biz-otp-client.js updated. tools now "BZ, B, DT" (Burp first; browser for the form flow; DevTools for inspecting the hidden otp_ok field; curl tag dropped). start rewritten as a Burp-oriented starting point with no curl one-liner (Proxy on, submit a wrong OTP, find the POST in HTTP history, send to Repeater). hints ladder keeps its Nudge/Technique/Explicit tiers and now names the Burp step (Proxy history, Repeater); no exploit values pasted. how is Burp-flavored: forge the otp_ok claim in Repeater with a wrong OTP so the server accepts it without running the JavaScript check.
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. ## bizlogic/biz-price-tamper

- Verdict: BURP-CLEAN
- Tools: "BZ, B" -> "BZ, B, DT"
- Burp workflow:
  1. Start Burp Proxy and browse to /bizlogic/price-tamper in the configured browser. View the page source or use DevTools to see the hidden price field carrying the $50 catalog price.
  2. Click "Buy now for $50", intercepting the POST to /bizlogic/price-tamper/buy in Proxy. The body carries product_id and the price the browser reported.
  3. Right-click the intercepted request and send it to Repeater. Lower the price parameter to a value below the catalog price and send the request. Negative values are rejected by the server, so stay positive.
  4. The response renders the order receipt with "You paid" showing the tampered amount and the flag box, because the server honored the submitted price without re-checking the catalog.
  5. Optional: use Intruder to sweep the price parameter downward and watch the "You paid" line change, confirming the server-side total follows the submitted value.
- Issues: none for the exploit chain. Minor note: the page copy still shows a curl starter line. That text was left untouched as out of this audit's edit scope; it contradicts the Burp-first voice on the card and could be reworded in a follow-up pass.
- Changes applied: vuln object in modules/bizlogic/challenges/biz-price-tamper.js updated. tools now "BZ, B, DT" (Burp first; browser for the buy flow; DevTools for spotting the hidden price field). start rewritten as a Burp-oriented starting point with no curl one-liner (intercept the buy POST, send to Repeater, experiment with the price parameter). hints ladder keeps its Nudge/Technique/Explicit tiers and now names the Burp step (DevTools for the field, Repeater for the tamper); no exploit values pasted. how is Burp-flavored: tamper the price parameter on the way to /bizlogic/price-tamper/buy in Repeater, since the server honors the submitted price without re-checking the catalog.
- Verification: node --check passes. grep for em dash over the challenge file diff: zero.
