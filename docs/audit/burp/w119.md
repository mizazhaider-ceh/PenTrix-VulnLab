# w119 Burp Audit: array-hijack (JSONP Array Constructor Hijack)

## Verdict
BURP-CLEAN

## Tools old -> new
`B, DT` -> `BZ, B`

The old start field was a curl one-liner (`curl -s "http://localhost:3000/jsonp/legacy?callback=gotFriends"`), which does not capture the exploit chain and does not fit the Burp-first doctrine. Replaced with a Burp-oriented start. `BZ` now leads; `B` stays since a real browser loads the attacker page; `DT` dropped because DevTools inspection is not needed for the chain.

## Burp workflow steps
1. Set up Burp Proxy as the interception proxy and point a browser at it.
2. In the browser, visit `/jsonp/array-attacker`. The page overrides the global `Array` constructor, then loads `/jsonp/legacy?callback=gotFriends` via a `<script>` tag. The legacy endpoint emits `gotFriends(new Array("alice:A1","bob:B2","carol:C3","feed-token:..."))`, so the overridden constructor captures every element, including the per-session feed token.
3. Watch Burp's Proxy HTTP history: the page then POSTs the captured items as JSON to `/jsonp/array-beacon`.
4. Right-click that beacon request and send it to Repeater. Replay it: a valid beacon (carrying the session token) returns `{ ok: true, flag }`, which the challenge records on the scoreboard.
5. The beacon is single-use: the feed token rotates after a successful beacon. To re-solve, reload the attacker page and replay the fresh beacon.

Alternative pure-Repeater path: GET `/jsonp/legacy?callback=x` with your session cookie, extract the items array (including `feed-token:...`) from the JavaScript body, then POST `{"items":[...]}` to `/jsonp/array-beacon`. Same result, no browser required, but the attacker-page flow is the primary intended path.

## Issues
- Old `start` field was a curl one-liner, not Burp-oriented and not representative of the actual exploit chain (chain needs the Array override plus the beacon POST, not just a feed fetch).
- `tools` lacked the `BZ` tag even though the challenge is fully Proxy/Repeater compatible.

## Changes applied
File: `modules/jsonp/challenges/array-hijack.js` (vuln object only)

- `how`: Burp-flavored description of the full chain (attacker page redefines Array, loads the feed, beacons the captured elements including the session token; beacon replay in Repeater works too).

Verification: `node --check` passes; zero em dash characters in the edited file; scratch server (`DB_PATH=/tmp/burp-w119.db PORT=18119`) served `/jsonp/array-attacker` with HTTP 200; server stopped afterwards. Tests (`tests/jsonp.test.js`) were not modified.

## Flag secrecy notes
Feed token is per-session (`jsonpArrayToken`) and rotates after a valid beacon; forged beacons with guessed tokens are rejected with 400. Flag is only issued by the server-side `award()` call. No redesign needed: FLAG BAR and FLAG SECRECY preserved.
