## Burp workflow steps
1. Proxy on, open `/upload` in the Burp browser and upload any HTML file through the v4 (mime-check) form once, letting Burp capture the request.
2. In Proxy history, send the captured `POST /upload/mime-check?filename=evil.html` request to Repeater. Note that the request carries a `Content-Type` header set by the client.
3. In Repeater, change the `Content-Type` request header to `image/png`, keeping the body as the HTML file bytes, and send. The server checks only this header, so the HTML file is accepted as an image.
4. The response confirms the file was stored; open the view link to confirm the HTML serves as active content. The claim box awards the flag.

The exploit chain is a single standard HTTP POST with one client-controlled header edited in Repeater. All bytes are plain ASCII, no multipart boundary rewriting is needed (the body is sent raw via `express.raw`), so Burp neither mangles nor normalizes anything meaningful. No raw sockets, no malformed HTTP, no timing tricks, no curl-only behavior.
