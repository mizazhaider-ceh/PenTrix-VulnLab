# Burp audit w075: jwt/none-admin (alg=none Accepted) and jwt/weak-secret (Weak HMAC Secret)

Both challenges run on plain HTTP form traffic and are fully solvable with
Burp Suite Community (Proxy, Repeater, Intruder, Decoder). No redesign needed.

---

## Challenge 1: jwt/none-admin (alg=none Accepted)

### Verdict
BURP-CLEAN. The full exploit chain is a GET that renders the page plus a sample
unsigned token, then a single urlencoded `POST /jwt/none` with the token field.
The token is pure ASCII base64url, nothing Burp would mangle, no curl-specific
behavior, no non-HTTP protocol. Every step maps to Proxy and Repeater.

### Tools: old -> new
- Old: `B, N` (Browser, Node/JWT)
- New: `BZ, N` (Burp/ZAP first, Node/JWT kept as a helper)
- Why: minting and replaying the unsigned token is Repeater work; Node is
  genuinely handy for base64url encoding claims offline, so N stays. The
  Browser tag drops because Burp's browser and Proxy cover that role.

### Burp workflow steps
1. Set Burp Proxy as the browser proxy and browse to
   `http://localhost:3000/jwt/none`. The page shows a sample unsigned token.
2. Paste any value into the token form and submit once to learn the request
   shape. In Proxy history, find `POST /jwt/none`, right-click, Send to
   Repeater.
3. Paste the sample token into Burp Decoder and Smart-decode it to confirm the
   shape: header segment, payload segment, empty signature segment.
4. In Repeater, hand-craft a new token with an `alg: none` header and
   `role: "admin"` claims, put it in the `token` field, and send.
5. The response renders the "Welcome, admin" page with the flag. Intruder is
   not needed; this is a single hand-crafted replay.

### Issues
- None blocking. The old tool tags (`B, N`) and the curl one-liner as the
  starting point did not match the Burp-first voice (D16).

### Changes applied
- `modules/jwt/challenges/none-admin.js` (vuln object only):
  - tools: `B, N` -> `BZ, N`
  - start: curl one-liner replaced with a Burp-oriented starting point
    (Proxy to the page, intercept the submit, send to Repeater, hand-craft
    the unsigned token, replay until the welcome page appears)
  - hints: now name the Burp steps (intercept in Proxy and send to Repeater,
    Smart-decode the sample token in Decoder, replay from Repeater); nudges
    only, no exploit pasted
  - how: Burp-flavored phrasing (replay the submit from Repeater), same meaning
- Verified: `node --check` passes, zero em dashes in the diff, scratch server
  booted (DB_PATH=/tmp/burp-w075.db PORT=18075) with `GET /jwt`, `GET /jwt/none`
  and `GET /jwt/weak` all returning 200, and a hand-crafted unsigned admin
  token posted to `/jwt/none` returned 200. Server killed afterwards.
- No changes to tests/ and no git push, per constraints.

## Challenge 2: jwt/weak-secret (Weak HMAC Secret)

### Verdict
BURP-CLEAN. This is the textbook Intruder challenge: the full chain is a GET
that renders a signed guest token, a tiny offline wordlist loop, and a
urlencoded `POST /jwt/weak` per candidate. All bytes are ASCII form traffic, so
Burp neither mangles nor mis-encodes anything. No raw sockets, no curl-specific
behavior, no non-HTTP protocol. Steps map to Proxy, Intruder (Sniper attack
over the token field, grep match on the welcome marker), and Decoder.

### Tools: old -> new
- Old: `N, W` (Node/JWT, Wordlist)
- New: `BZ, N, W` (Burp/ZAP first, Node/JWT and Wordlist kept)
- Why: replaying candidate tokens is Intruder work; Node is genuinely needed to
  sign one admin-claims token per candidate secret (Burp Community has no JWT
  signer), so N stays; the wordlist supplies the candidate secrets, so W
  stays. BZ goes first per the Burp-first voice (D16).

### Burp workflow steps
1. Set Burp Proxy as the browser proxy and browse to
   `http://localhost:3000/jwt/weak`. The page shows a legitimate signed guest
   token; decode it in Burp Decoder to read the claims.
2. Offline, build a tiny wordlist of classic default secrets and sign the same
   admin claims once per candidate (Node with jsonwebtoken works, or any JWT
   tooling). This produces one candidate token per secret.
3. Submit the form once with anything in it. In Proxy history, find
   `POST /jwt/weak`, right-click, Send to Intruder.
4. In Intruder, clear all payload positions and mark only the `token` value.
   Use the Sniper attack type with the candidate signed tokens as the payload
   list.
5. Add a grep match for the success marker (the "Welcome, admin" text).
6. Start the attack. Every wrong secret yields a 403 rejection; the one
   response carrying the welcome marker used the correct secret, and that
   response contains the flag.

### Issues
- None blocking. The old tool tags (`N, W`) had no Burp tag and the starting
  point was a curl one-liner, which did not match the Burp-first voice (D16).
- Note: Intruder replays candidate tokens signed offline; Burp Community does
  not sign JWTs itself, so the offline signing step is inherent to the
  challenge, not a redesign issue. The lab still runs entirely through
  standard HTTP, which is exactly what Intruder is for.

### Changes applied
- `modules/jwt/challenges/weak-secret.js` (vuln object only):
  - tools: `N, W` -> `BZ, N, W`
  - start: curl one-liner replaced with a Burp-oriented starting point
    (Proxy to the page, intercept the submit, send to Intruder, build a tiny
    wordlist, sign admin-claims tokens per candidate offline, sniper them
    through Intruder while grepping for the welcome response)
  - hints: now name the Burp steps (feed signed tokens to Intruder as a
    sniper payload list, grep responses for the success marker); nudges only,
    no exploit pasted, no secret value disclosed
  - how: Burp-flavored phrasing (Intruder replays candidate signed tokens
    while you grep for the success response), same meaning
- Verified: `node --check` passes, zero em dashes in the diff, scratch server
  booted (DB_PATH=/tmp/burp-w075.db PORT=18075) with `GET /jwt/weak` returning
  200 and a wrong-secret signed token correctly rejected with 403 (positive
  path is covered by tests/jwt.test.js). Server killed afterwards.
- No changes to tests/ and no git push, per constraints.
