# Burp audit w013: misconfig/listing (Directory Listing Leak)

## Verdict
BURP-CLEAN. The full exploit chain is two plain HTTP GET requests, both fully
reproducible in Burp Proxy and Repeater with Community Edition: browse the
hand-rolled listing at /misconfig/files/, spot secret.txt, request it. No raw
sockets, no malformed HTTP, no timing tricks, no bytes Burp would mangle.

## Tools old -> new
- Old: `B`
- New: `BZ, B`

Burp is the recommended primary tool (Proxy to browse, Repeater to request the
exposed file), with the plain browser as fallback.

## Burp workflow steps
1. Start Burp, set the browser to proxy through Burp (intercept off).
2. Browse to http://localhost:3000/misconfig and open the Shared files section
   (/misconfig/files/).
3. Right-click the listing request in Proxy history, send to Repeater, and read
   the response: the file list exposes secret.txt alongside the public files.
4. In Repeater, change the request line to GET /misconfig/files/secret.txt and
   forward it. The response body contains the secret and the flag is awarded.

## Issues
None. No Burp-mangling risk: both requests are standard GETs with no special
headers, body, or encodings. The query-parameter variant (/misconfig/files?f=)
is equally replayable in Repeater.

## Changes applied
