## redos-search (Regex Injection Search)

### Verdict

### Tools old -> new

### Burp workflow steps
1. Proxy on, open `/redos/search` in the Burp browser and submit the search form once with a harmless query.
2. In Proxy history, send the captured request to Repeater (works for both the GET and POST forms; POST is a plain urlencoded body).
3. In Repeater, set `q` to the haystack's repeated character so the server compiles it into the nested-quantifier template `^((a)+)+$`, tested against the fixed 27-char haystack with its trailing mismatch.
4. Send and watch the response time Repeater reports under the response. The claim fires when the round trip exceeds 1000 ms.

The whole chain is a plain HTTP GET/POST with one form parameter, alphanumeric only, so Burp never mangles anything. Timing is observable directly in Repeater (per-send response time). No raw sockets, no malformed HTTP, no curl-only behavior.

## redos-url (Catastrophic URL Regex)

### Verdict
BURP-CLEAN.

### Tools old -> new
`B, C` -> `BZ, B, C` (Burp first per D16; curl stays as a fallback).

### Burp workflow steps
1. Proxy on, open `/redos/url` in the Burp browser and submit the validator once with a harmless URL such as `http://example.com/`.
2. In Proxy history, send the captured GET to Repeater.
3. In Repeater, grow the `url` parameter: repeat one simple path segment many times, then end with a character the pattern rejects, forcing the nested path group `([\/\w .-]*)*` to retry every split. Stay within the 46-char server limit.
4. Send and watch the response time Repeater reports under the response. The claim fires when the round trip exceeds 1000 ms.

The whole chain is a plain HTTP GET with one query parameter. Burp handles the URL-encoding of `!` and `/` without mangling anything. Timing is observable directly in Repeater. No raw sockets, no malformed HTTP, no curl-only behavior.

### Issues
- `tools` listed `B, C` with a curl `start` one-liner, contrary to D16.
- `hints[2]` described the mechanism but never named the Burp steps (Proxy capture, push to Repeater, grow `url`, watch response time).
- `how` and `start` were tool-neutral / curl-oriented, not Burp-flavored.

### Changes applied
- `tools`: `B, C` -> `BZ, B, C`.
- `start`: replaced the curl one-liner with a Burp-oriented starting point (Proxy, submit harmless URL, send to Repeater, grow `url`, watch response time).
- `hints[2]`: names the Burp step (capture in Proxy, push to Repeater, grow `url` with repeated segments and a bad tail, watch Repeater's response time). Nudge only; no exploit pasted.
- `how`: Burp-flavored (Proxy capture, Repeater craft, repeated path segments plus rejected tail, >1000 ms claim). Keeps the concrete size guidance from the original.
