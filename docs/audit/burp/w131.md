# w131 verdicts

## csrf/clickjacking

- Verdict: BURP-CLEAN
- Tools: "B" -> "BZ, B"
- Burp workflow:
  1. In Burp's browser (or a browser routed through Burp Proxy), open /csrf/framedemo. Watch Proxy history: the page embeds /csrf/vip-action?frame=<one-time token> in an iframe.
  2. Inspect the frame response headers: there is no X-Frame-Options header and no CSP frame-ancestors. That missing framing protection is the vulnerability.
  3. Send the frame request to Repeater (keep the session cookie). Replay the framed GET carrying the one-time token: the server records a real framed load in the session.
  4. Replay the framed form's POST in Repeater with the same token and session cookie. The server sees the token both loaded in the frame and posted back and awards the flag.
  5. Alternatively, click through the demo page in the proxied browser: the framed form submits with its token and the flag box appears. Proxy history shows the whole chain for the write-up.
- Issues: none. The challenge mechanics needed no change: the full chain is plain HTTP plus a browser click, exactly what Proxy and Repeater are for. The only gap was presentation: the old `start` was a curl one-liner and the hints never named the Burp steps, both fixed below. FLAG BAR and FLAG SECRECY are preserved untouched: visiting /csrf/framedemo alone, a bare POST, or a POST with a token never seen on a framed load all earn nothing, and the token is single-use.
- Changes applied: vuln object in modules/csrf/challenges/clickjacking.js updated. tools now "BZ, B" (Burp first as the recommended path, browser kept since the click is browser-driven). start rewritten as a Burp-oriented starting point ("In Burp, open the proxied browser to /csrf/framedemo, then find the /csrf/vip-action frame request in Proxy history and inspect its response headers for framing protection.", no curl one-liner). hints ladder keeps its Nudge/Technique/Explicit tiers (still exactly 3, as the test suite asserts) and now names the Burp step where it helps (Proxy history, Repeater); nudges only, no exploit payloads pasted. how made Burp-flavored: describes walking the framing chain through Burp (proxied load, confirm the missing header, replay the framed GET and form POST with the one-time token) and notes the browser click performs the same chain. Route logic untouched.
