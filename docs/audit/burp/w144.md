# Burp-first audit: w144 (formula-pipe)

Challenge: formula-pipe, "Pipe Prefix (LibreOffice)", difficulty Easy.
Module: formula. File: modules/formula/challenges/formula-pipe.js.

## Verdict

BURP-CLEAN. The full exploit chain runs over standard HTTP and works via
Burp Suite Community tools: Proxy to capture the Add contact POST,
Repeater to fetch /formula/export.csv and read the flag from the
X-Flags response header. No raw sockets, no non-HTTP protocols, no
Burp-mangled bytes (the payload |'cmd'!A0 is plain ASCII), no
curl-specific behavior (plain urlencoded form POST).

## Tools

Old: B (Browser)
New: BZ, B (Burp/ZAP first, Browser second)

Rationale: the natural exploit path is intercepting a form POST and
replaying a download in Repeater. The browser alone can submit the form,
but Burp is the intended tool.

## Burp workflow steps

1. Proxy: browse to /formula and submit the Add contact form. Intercept
   the POST to /formula/add and set the name field to a pipe-prefixed
   value (a payload starting with |). Forward the request; the server
   answers 302 and stores the contact raw.
2. Proxy: request GET /formula/export.csv (or just download the export
   from the Export page) and send it to Repeater.
3. Repeater: replay the export request. The response carries the CSV
   body with the raw pipe-prefixed cell, and the flag arrives in the
   X-Flags response header.
4. Intruder (optional, not required): could fuzz name/note prefixes
   (e.g. |, =|) to see which trigger the X-Flags header, but the hint
   ladder already narrows it to the pipe.

## Issues

None blocking. Verified live on a scratch instance:

- POST /formula/add with name=|'cmd'!A0 returned 302 (contact stored).
- GET /formula/export.csv returned 200, CSV body contained the raw
  cell |'cmd'!A0, and X-Flags carried PENTRIX{...}.
- /formula page returned 200.
