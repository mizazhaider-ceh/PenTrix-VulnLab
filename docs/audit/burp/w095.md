## Verdict

**BURP-CLEAN**

## Burp workflow steps

1. In Burp's built-in browser, open the IDOR shop (`/idor`) and log in as bob (or alice) using the on-page quick login.
2. In Proxy history, find the logged-in request and send it to Repeater (the session cookie is carried automatically).
3. In Repeater, change only the request line path to the staff member directory under `/idor/admin/` (it is not linked anywhere in the UI).
4. Send the request. A 200 response renders the flag banner ("Flag captured") and the staff member table, because the route checks login but never checks the admin role.

## Issues

None for Burp solvability. The exploit is a single authenticated GET with no special bytes, no raw socket needs, no curl-specific behavior, and no non-HTTP protocol. Cookies and the plain ASCII path pass through Proxy/Repeater untouched.
