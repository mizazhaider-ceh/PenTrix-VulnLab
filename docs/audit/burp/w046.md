# Burp audit w046: XXE File Read (modules/xxe/challenges/file)

## Verdict

BURP-CLEAN.

The exploit is a single ordinary HTTP request: POST /xxe/import with an
`application/x-www-form-urlencoded` body whose `xml` field holds the XXE
payload (confirmed against tests/xxe.test.js, which posts `{ xml }` as form
data, and tests/helpers.js, which uses the form content type for such posts).
The server expands the external entity and echoes its content in the
"Parsed content" block, awarding the flag when the secret marker
(XXE-SECRET-4471) is present. Nothing about this needs raw sockets,
malformed HTTP, unreproducible timing, or byte sequences Burp normalizes:
every special character in the payload (`&`, `<`, `>`, quotes) is plain
URL-encodable ASCII that Repeater handles natively.

## Tools

Old: `B, C` (Browser, curl)
New: `BZ, B, C` (Burp/ZAP first; Browser and curl still work)

## Burp workflow

1. Proxy: browse to the XML importer at /xxe/import and submit the form once
   with harmless XML, e.g. `<data>hello</data>`.
2. Repeater: send that POST to Repeater. Replace only the `xml` form field
   with the DOCTYPE payload that declares an external entity using a
   `file://` SYSTEM URI pointing at the absolute path of secret.txt.
3. Reference the entity (e.g. `&xxe;`) inside `<data>` so the file content
   lands in the "Parsed content" echo. The response page shows exactly where
   injected content echoes back, so aim there.
4. Submit and read the flag box in the result page.

## Issues

None. No Burp-mangled bytes, no curl-specific behavior, no non-HTTP protocol.
The payload is standard ASCII XML sent as an encoded form field.
