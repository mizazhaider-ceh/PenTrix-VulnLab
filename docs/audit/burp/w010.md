# Burp-first audit: w010, debug (Verbose Debug Errors)

- Module: misconfig
- Challenge file: `modules/misconfig/challenges/debug.js`
- Route: `GET /misconfig/debug`, error path via `?err=1`

## Verdict

**BURP-CLEAN.** The full exploit chain works with plain, standard HTTP through Burp Proxy and Repeater. No raw sockets, no malformed HTTP, no timing dependency, no byte mangling, no curl-specific behavior, no non-HTTP protocol. Community edition is enough.

## Tools

Old: `B` (Browser)
New: `BZ, B` (Burp/ZAP first, then Browser)

The exploit is one GET request with a query parameter. Burp is the recommended tool because the natural workflow is click-through in Proxy, then replay and inspect in Repeater. Plain browser also works, so `B` stays as secondary.

## Burp workflow steps

1. Proxy: open `http://localhost:3000/misconfig/debug`. The status page says debug mode is "off" and shows a "Simulate an error" link.
2. Proxy: click "Simulate an error". In the Proxy HTTP history, note the request that flipped the page: `GET /misconfig/debug?err=1`.
3. Repeater: send that request to Repeater and replay it. The response body contains a verbose stack trace plus a full app config dump (dbPassword, debugToken, apiKey, sessionSecret).
4. Read the config dump in the response. The flag is awarded and rendered in the output (flag box shows a `PENTRIX{...}` value). No Intruder run needed: one parameter, one known-good value.
