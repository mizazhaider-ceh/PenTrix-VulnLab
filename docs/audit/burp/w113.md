## redirect-double-slash (Protocol-Relative Redirect)

**Verdict:** BURP-CLEAN

**Tools old -> new:** `B, C` -> `BZ, B`

**Burp workflow:**
1. In the browser (proxied through Burp), open `/redirect/go` and submit the "where to next" form.
2. Find the GET request in Proxy HTTP history and send it to Repeater.
3. In Repeater, change the value of the `next` query parameter to a protocol-relative target (a value starting with two slashes) and send.
4. In the response, inspect the `Location` header: it now points at the attacker host while the browser keeps the current scheme. The 302 body carries the flag.

**Issues:** None. The flag awards server-side on a plain GET with a URL-encoded query parameter; nothing in the chain needs raw sockets, mangled bytes, or curl-specific behavior. The old `start` was a curl one-liner, which conflicted with the Burp-first voice.

**Changes applied:**
- `tools`: `B, C` -> `BZ, B`
- `start`: Burp-oriented starting point (capture the form GET in Proxy, send to Repeater); no curl one-liner
- `hints`: each step now names the Burp action (Proxy capture, Repeater edit, Location header inspection); nudges only, no exploits pasted
- `how`: tool-neutral ("In Repeater, send /redirect/go with next set to a protocol-relative target and confirm the Location header points at an external host.")

## redirect-javascript (javascript: Scheme Honored)

**Verdict:** BURP-CLEAN

**Tools old -> new:** `C` -> `BZ, B`

**Burp workflow:**
1. In the browser (proxied through Burp), open `/redirect/js` and submit the promo form.
2. Find the GET request in Proxy HTTP history and send it to Repeater.
3. In Repeater, change the value of the `next` query parameter to a `javascript:` URL and send.
4. In the response, inspect the `Location` header: the server honors the `javascript:` scheme and returns it verbatim. The 302 body carries the flag.

**Issues:** None. Flag awards server-side in the response body on a plain GET; no raw-socket needs, no Burp-mangled bytes, no curl-specific behavior. The old `tools` listed only `C` and the `start` was a curl one-liner, which conflicted with the Burp-first voice.

**Changes applied:**
- `tools`: `C` -> `BZ, B`
- `start`: Burp-oriented starting point (submit the promo form through Burp Proxy, send the request to Repeater); no curl one-liner
- `hints`: each step now names the Burp action (Proxy capture, Repeater edit, Location header inspection); nudges only, no exploits pasted
- `how`: Burp-flavored ("In Repeater, request /redirect/js with next set to a javascript: URL and confirm the Location header carries that scheme.")
