# w120 verdicts

## jsonp/callback-xss

- Verdict: BURP-CLEAN
- Tools: "B" -> "BZ, B"
- Burp workflow:
  1. In the Burp browser, open /jsonp/user?callback=hello and watch the response in Proxy (Proxy > Intercept). The body is a JavaScript function call: hello({"user":"alice","role":"user","token":"..."});. The callback value is pasted verbatim into executable JavaScript.
  2. Send that request to Repeater and vary the callback parameter. Try values that close the function call early so your own JavaScript becomes part of the response body. The parameter accepts parens, quotes and operators; standard URL encoding in Repeater handles them with no Burp mangling.
  3. Load the tampered URL as a script in the Burp browser so the injected code runs. Have it read the per-session token from the data object and echo it to /jsonp/beacon-xss?v=callback-xss&n=<token>.
  4. The beacon response renders the flag box. No raw sockets, no curl-only behavior, no non-HTTP steps anywhere in the chain.
- Issues: none. The breakout payload is a plain query parameter (no Burp-mangled bytes), the feed and beacon are ordinary GET requests, and script execution happens in Burp's browser, which is the D16-supported path.
