## ssti-nounderscore (Underscore Blacklist Bypass)

- Verdict: BURP-CLEAN
- Tools: B, C -> BZ, B, C
- Burp workflow: Open /ssti/nounderscore in the Burp browser with Proxy on, submit a note, and send the request to Repeater. In Repeater, first send input={{7*7}} to confirm the engine still evaluates templates (the underscore filter only strips underscores, it does not disable evaluation). Then in Repeater, send an eval() inside {{ }} that builds the underscore from String.fromCharCode(95) at run time and evaluates the assembled variable name; the response renders the flag and the flag bar appears. Quotes and plus signs in the payload need ordinary URL encoding, which Repeater applies automatically (select the value and use URL-encode as needed). Fully encoded form %7B%7Beval(%22db%22%2BString.fromCharCode(95)%2B%22pass%22)%7D%7D verified to return the flag.
- Issues: none. Plain well-formed HTTP GET with a query parameter; no raw sockets, no malformed HTTP that Burp would normalize, no timing dependence, no bytes Burp would mangle. The negative control (typing the underscore directly) also behaves identically through Burp: it returns no flag.
- Changes applied: tools set to BZ, B, C. start replaced the curl two-liner with a Burp Proxy capture plus Repeater probe description, no curl one-liner. hints now name the Burp step (Proxy capture, send to Repeater, probe the input parameter) and give nudges only, never paste the exploit. how reworded to Burp-flavored eval assembly.

## ssti-rce (SSTI to Remote Code Execution)

- Verdict: BURP-CLEAN
- Tools: B, C -> BZ, B, C
- Burp workflow: Open /ssti/exec in the Burp browser with Proxy on, submit an expression, and send the request to Repeater. In Repeater, send expr={{7*7}} to confirm the engine evaluates templates (page echoes 49). Then in Repeater, reach the child-process module through the template scope, run a harmless system command synchronously, and convert its output to text so it renders in the response; the page shows uid=... output and the flag bar appears. Ordinary URL encoding of quotes (and braces if desired) is enough; Burp Repeater handles it. Encoded form %7B%7Brequire(%22child_process%22).execSync(%22id%22).toString()%7D%7D verified to return uid=0(root) output.

Standard HTTP GET with a query parameter; the RCE payload is evaluated server side from the parameter value, so nothing about the exploit depends on raw sockets, HTTP edge cases, timing, or byte-level control that Burp would normalize. The arithmetic-only probe correctly returns no flag.
- Changes applied: tools set to BZ, B, C. start replaced the curl one-liner with a Burp Proxy capture plus Repeater probe description. hints now name the Burp step (Proxy capture, send to Repeater, probe expr, require the child-process module) and give nudges only. how reworded to Burp-flavored Repeater send.
