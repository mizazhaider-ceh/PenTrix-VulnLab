# Burp audit w123: host-abs-url

## Verdict
BURP-CLEAN

## Challenge
Absolute Continue URL (modules/hostheader/challenges/host-abs-url.js).
POST /hostheader/login builds the post-login 302 Location as an absolute URL
from the request Host header. A poisoned Host header makes the 302 point at an
attacker-controlled host, which awards the flag.

## Tools: old -> new
B, C -> BZ, B

## Burp workflow steps
1. Open Burp, set browser proxy, browse to /hostheader/login.
2. Log in once as alice / alice123 to capture the POST in Proxy history.
3. Send the POST /hostheader/login request to Repeater.
4. Edit only the Host header to a domain you control (e.g. evil.com).
5. Send and read the response: the 302 Location header points at the poisoned
   host, and the response body carries the flag box.

## Issues
None. The test uses spoofed Host headers on origin-form request lines, so no
absolute-URI request-line trickery is involved. Burp Repeater sends origin-form
by default and Host header editing is trivial. No raw sockets, no malformed
HTTP, no curl-specific behavior.

## Changes applied
- tools: 'B, C' -> 'BZ, B' (Burp first per D16).
- start: replaced the curl one-liner with a Burp-oriented starting point
  (proxy the login, send to Repeater, edit Host, log in).
- hints: renamed the Burp step in all three nudges (Repeater, change only the
  Host header, read the 302 Location). No exploits pasted.
- how: Burp-flavored, tool-neutral: POST /hostheader/login in Repeater with a
  controlled Host, then read the 302 Location.
- The page tip still mentions curl -i; the primary flow is Burp.
