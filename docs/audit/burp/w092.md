# Burp audit w092: auth/reset (Predictable Password Reset Tokens), auth/security-question (Guessable Security Question)

## Challenge 1: reset (Predictable Password Reset Tokens)

### Verdict
BURP-CLEAN. The exploit chain is plain HTTP: a GET that renders the reset token
on screen, then a POST to `/auth/reset/confirm` carrying a forged token. No raw
sockets, no binary bytes Burp would mangle, no curl-specific behavior, no
non-HTTP protocol. Every step maps to Proxy, Repeater, and Burp Decoder.

### Tools: old -> new
- Old: `B, C` (Browser, curl)
- New: `BZ, B` (Burp/ZAP first, Browser kept)
- Why: the observe-token then replay-confirm loop is Proxy/Repeater/Decoder
  work. Curl is no longer needed as a starting point, so C drops.

### Burp workflow steps
1. Set Burp Proxy as the browser proxy and browse to
   `http://localhost:3000/auth/reset`. Request a reset for `alice`.
2. The page renders the token on screen. Paste it into Burp's Decoder to see
   what it encodes (base64 of the username). This is the vulnerability:
   the token is deterministic and carries no randomness.
3. Follow the confirm link so the form loads, then send the
   `POST /auth/reset/confirm` request to Repeater.
4. In Repeater, replace the token field with a token you mint yourself for
   `admin` (the same base64-of-username encoding you observed) and set a new
   password. Send it.
5. The response renders the "Password changed" page with the flag banner,
   because the token was never legitimately issued for `admin`.
6. Intruder is not required; this is a single forged token, not a fuzzing job.

### Issues
- None blocking. Old tool tags (`B, C`) and a curl one-liner as the starting
  point did not match the Burp-first voice (D16).

### Changes applied
- `modules/auth/challenges/reset.js` (vuln object only):
  - tools: `B, C` -> `BZ, B`
  - start: curl one-liner replaced with a Burp-oriented starting point
    (Proxy to the reset page, request a reset for alice, follow the confirm
    link, send its POST to Repeater)
  - hints: now name the Burp steps (Decoder for the token, Repeater for the
    confirm POST); nudges only, no exploit pasted
  - how: Burp-flavored phrasing (Decoder and Repeater carry the whole chain),
    same meaning

## Challenge 2: security-question (Guessable Security Question)

### Verdict
BURP-CLEAN. The exploit chain is plain HTTP: a GET of the public bio page that
reveals the "secret" answer, then a POST to `/auth/question-reset` with the
answer and a new password. No raw sockets, no binary bytes Burp would mangle,
no curl-specific behavior, no non-HTTP protocol. Every step maps to Proxy and
Repeater.

### Tools: old -> new
- Old: `B` (Browser)
- New: `BZ, B` (Burp/ZAP first, Browser kept)
- Why: D16 puts Burp/ZAP first. The traffic is a normal form POST, so it fits
  Proxy/Repeater without any special tooling.

### Burp workflow steps
1. Set Burp Proxy as the browser proxy and browse to
   `http://localhost:3000/auth/bio/alice`. Read the public bio.
2. The bio states the answer to the security question outright (mother's
   maiden name). That public fact is the whole credential.
3. Browse to `http://localhost:3000/auth/question-reset`, fill in the form,
   and send the `POST /auth/question-reset` request to Repeater.
4. In Repeater, set the username and the answer read from the bio, add a new
   password, and send.
5. The response renders the "Password changed" page with the flag banner.
6. Intruder is not required; no brute force is involved.

### Issues
- None blocking. Tool tag was browser-only and the starting point was a curl
  one-liner, neither matching the Burp-first voice (D16).

### Changes applied
- `modules/auth/challenges/security-question.js` (vuln object only):
  - tools: `B` -> `BZ, B`
  - start: curl one-liner replaced with a Burp-oriented starting point
    (Proxy to the question-reset page and to alice's public bio)
  - hints: now name the Burp steps (read the bio through Proxy, replay the
    reset POST in Repeater); nudges only, no exploit pasted
  - how: Burp-flavored phrasing (Proxy and Repeater carry the whole chain),
    same meaning
