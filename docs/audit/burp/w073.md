# Burp-first audit w073: kid-default

Challenge: modules/jwt/challenges/kid-default.js (Default Key for Missing kid)

## Verdict

CLEAN. The whole exploit chain is one plain form-urlencoded POST
(`POST /jwt/kiddefault`, body `token=<JWT>`), so it works entirely through
Burp Proxy and Repeater with standard HTTP. No redesign needed. Vuln object
updated to Burp-first voice. N stays because signing an HS256 token needs an
HMAC, which Burp Suite Community cannot do natively; one short Node line is
genuinely helpful here (D16).

## Tools old -> new

- Old: `N` (Node/JWT only)
- New: `BZ, N` (Burp/ZAP first, Node kept for signing the forged token)

## Burp workflow steps

1. With Burp Proxy on, open http://localhost:3000/jwt/kiddefault in the
   browser and submit the token form once to learn the request.
2. In Proxy HTTP history, right-click POST /jwt/kiddefault and send it to
   Repeater.
3. Think like the developer who wrote this: a missing `kid` header falls back
   to a hardcoded default key. The key will be something tiny and guessable
   typed while testing ('test' is the classic).
4. Sign a kid-less admin token (role=admin) with the guessed key. One Node
   line does this since Burp Community has no native JWT signer.
5. In Repeater, replace the `token` body value with the forged token and send.
   A 403 means the guess was wrong; a 200 renders "Welcome, admin" with the
   flag.
6. To spray many candidates, save each signed token (one per guessed key) and
   use Intruder's Sniper attack on the `token` parameter with those tokens as
   payloads, then watch for the 200 response.

Why this works: the route trusts a kid-less token against a hardcoded
fallback key (`DEFAULT_KID_KEY`), so anyone who guesses that key can mint a
valid admin token without touching the real key table.

## Issues

- None blocking. The test (tests/jwt.test.js, "wrong default guess is
  rejected, right default key earns the flag") wins with plain HTTP posts:
  no raw-socket tricks, no special headers, no cookies, no Burp-mangling
  risk (base64url JWT bodies survive form encoding fine).
- Pre-audit voice mismatch: the vuln object listed only N and `start` was a
  curl/Node one-liner, contradicting the Burp-first doctrine. Fixed.

## Changes applied

1. `tools`: 'N' -> 'BZ, N' (BZ first per D16).
2. `start`: Burp-oriented starting point (browse with Proxy on, submit the
   form once, send the request to Repeater); curl one-liner removed.
3. `hints`: all three rewritten to name the Burp step (Proxy the form,
   send to Repeater, swap the token in Repeater and resend; 403 means try
   the next guess). Still nudges only, no exploit pasted.
4. `how`: Burp-flavored ("Catch the token form in Burp Proxy, move it to
   Repeater, guess the hardcoded default key, sign a kid-less admin token
   with it, and resubmit.").
