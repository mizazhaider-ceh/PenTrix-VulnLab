## session/logout (Logout Does Not Destroy the Session)

- Verdict: BURP-CLEAN
- Tools: "B, DT" -> "BZ, B"
- Burp workflow:
  1. In the browser (with Burp Proxy as the proxy), open /session/logoutdemo and log in as admin with the credentials shown on the challenge page.
  2. Find the POST /session/logoutdemo/login request in Burp's Proxy history and note the Set-Cookie value for lab_sid.
  3. Click the Log out link. Find the GET /session/logoutdemo/logout request in the Proxy history and confirm the browser keeps sending the same lab_sid cookie afterwards.
  4. Right-click the logout request (or any request carrying the cookie) and send it to Repeater, then change the path to /session/logoutdemo/secret. Alternatively, in Repeater craft a plain GET /session/logoutdemo/secret with a Cookie header carrying the old lab_sid value.
  5. Send the request. The server returns the secret admin page with the flag box, because logout only flipped a flag on the server and never invalidated the session id.
- Issues: none. Standard Cookie header replay over plain HTTP, no raw-socket needs, no byte-level quirks, no curl-specific behaviors.
- Changes applied: vuln object in modules/session/challenges/logout.js updated. tools now "BZ, B" (Burp first, DevTools dropped since the workflow is driven by Proxy/Repeater). start rewritten as a Burp-oriented starting point (proxy the login, watch the Cookie header through logout, no curl one-liner). hint reworded to name the Burp step. hints ladder keeps its Nudge/Technique/Explicit tiers and now names the Burp steps (Proxy history, capture lab_sid, replay in Repeater); no exploit payloads pasted. how now names the Burp-driven flow in tool-neutral language (log in, capture the cookie through Burp Proxy, log out, replay the secret request in Repeater).
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (DB_PATH=/tmp/burp-w101.db PORT=18101 node app.js) returned HTTP 200 for /session/logoutdemo; server killed afterwards (only my instance, other workers' instances untouched).

## session/never-expires (Sessions Never Expire)

- Verdict: BURP-CLEAN
- Tools: "B, DT" -> "BZ, B"
- Burp workflow:
  1. In the browser (with Burp Proxy as the proxy), open /session/neverexpires and click through to the session archive (/session/legacy-archive).
  2. Read the archive table: it prints the decade-old admin session id in the Session id cell.
  3. Right-click any request in Burp's Proxy history and send it to Repeater. Change the path to /session/legacy-admin and set the Cookie header to the archived sid value (lab_sid=<archived sid>).
  4. Send the request. The server accepts the decade-old session and returns the legacy admin panel with the flag box, because sessions live for 10 years and age alone never invalidates them.
- Issues: none. The sid is a 32-char hex string taken from the archive page; setting it as a plain Cookie header in Repeater is standard HTTP with no raw-socket needs or byte-level quirks.
- Changes applied: vuln object in modules/session/challenges/never-expires.js updated. tools now "BZ, B" (Burp first, DevTools dropped since the workflow is driven by Proxy/Repeater). start rewritten as a Burp-oriented starting point (proxy the archive page, read the archived sid, no curl one-liner). hint reworded to name the Burp step. hints ladder keeps its Nudge/Technique/Explicit tiers and now names the Burp steps (open the archive in the proxied browser, send to Repeater, set the lab_sid Cookie header); no exploit payloads pasted. how now names the Burp-driven flow in tool-neutral language (copy the archived sid, open the legacy admin panel in Repeater with that sid as the cookie).
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (DB_PATH=/tmp/burp-w101.db PORT=18101 node app.js) returned HTTP 200 for /session/neverexpires and /session/legacy-archive, and HTTP 403 for /session/legacy-admin without a cookie (expected: the admin panel correctly rejects cookie-less requests); server killed afterwards (only my instance, other workers' instances untouched).
