# w145 Burp-first audit: cache-deception

## Verdict
BURP-CLEAN. The full exploit chain (prime the path-only cache as alice, then
read the victim's cached stylesheet from a cookie-less session, flag in the
X-Flag response header) works entirely through Burp Suite Community with
Proxy + Repeater. No raw sockets, no malformed HTTP, no byte tricks, no
protocol tricks. All requests are plain GETs; session identity travels in
normal cookies; the flag arrives in a normal response header.

## Tools: old -> new
- old: `B, C` (Browser, curl)
- new: `BZ, B, C` (Burp/ZAP first, then Browser, curl)

## Burp workflow steps
1. Set Burp as the browser proxy and open `/http/cache-login?user=alice` in
   the browser; this logs alice in (session cookie).
2. In the browser, visit `/http/account.css`. The edge node caches alice's
   personalized stylesheet under the path-only key (response header
   X-Cache: MISS confirms the prime).
3. Switch to a fresh attacker session: a private window, or a Repeater tab
   with no cookies. Send GET /http/account.css.
4. In Repeater, inspect the raw response: header X-Cache: HIT and the
   X-Flag header carries the flag (the response body is CSS, so the flag is
   only visible in the headers).

## Issues
- The old `start` field was a curl one-liner, which contradicts the
  Burp-first doctrine (D16).
- The old hints said nothing about which Burp step to use.
- The old `how` was curl-centric.

## Changes applied
In `modules/http/challenges/cache-deception.js`, vuln object only:
- `tools`: `B, C` -> `BZ, B, C`.
- `start`: rewritten as a three-step Burp workflow (proxy login as alice,
  fresh cookie-less session, read X-Flag header); no curl one-liner.
- `hints`: nudges only, each names the Burp step (Repeater compare, Proxy
  login plus cookie-less Repeater tab, inspect response headers). No
  exploits pasted.
- `how`: tool-neutral/Burp-flavored rewrite.

Verified: `node --check` passes; `git diff` has zero em dashes; scratch
server booted (DB_PATH=/tmp/burp-w145.db PORT=18145), `/http` returned 200
and `/http/account.css` returned X-Cache: MISS, then the server was stopped.
