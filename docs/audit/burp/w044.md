# Burp-first audit: w044, cmdi-pipe (Ping Gadget v8) and cmdi-tab (Ping Gadget v9)

## Challenge 1: cmdi-pipe (Ping Gadget v8, ; blocked)

- Module: cmdi
- Challenge file: `modules/cmdi/challenges/cmdi-pipe.js`
- Route: `GET /cmdi/ping8`

### Verdict

**BURP-CLEAN.** The full exploit chain works with plain, standard HTTP through Burp Proxy and Repeater. The award condition (`host.includes('|') && ID_EVIDENCE.test(out)`) needs only a `|` in the query parameter after a valid host. A pipe needs no URL-encoding and passes through Repeater untouched. No raw sockets, no malformed HTTP, no timing dependency, no byte mangling, no curl-specific behavior, no non-HTTP protocol. Community edition is enough.

### Tools

Old: `B, C` (Browser, curl)
New: `BZ, B, C` (Burp/ZAP first, then Browser, then curl)

The exploit is one GET request. Burp is the recommended tool because the natural workflow is click-through in Proxy, then separator probing in Repeater. Plain browser and curl still work, so `B` and `C` stay as secondary.

### Burp workflow steps

1. Proxy: open `http://localhost:3000/cmdi/ping8`, submit a plain host like `127.0.0.1`.
2. Proxy history: find the `GET /cmdi/ping8?host=127.0.0.1` request and send it to Repeater.
3. Repeater: confirm the filter strips semicolons, then swap in a shell separator the filter never touches (one that feeds the first command's output into the next) after a valid host, and send.
4. Read the response body. The flag is awarded only when the second command's real output shows up in the response, so end with a command whose output is unmistakable.

### Issues

None. The challenge was already Burp-clean; the audit only changed presentation (tool tags and voice), not behavior. Test `cmdi-pipe` sends the payload with `encodeURIComponent`, so `%7C` arrives intact and Express decodes it to a literal `|`; Repeater sends it the same way.

### Changes applied

In `modules/cmdi/challenges/cmdi-pipe.js` (vuln object only):

1. `tools`: `B, C` -> `BZ, B, C` (Burp/ZAP listed first, per Burp-first doctrine).
2. `start`: was a curl one-liner. Now Burp-oriented: open the page in Proxy, submit a normal host, send the request to Repeater, and probe the host parameter there.
3. `hints`: rewritten so each step names the Burp action (Repeater to watch the filter strip semicolons, Repeater to swap in an untouched separator, Repeater to confirm real command output in the response). Nudges only, no exploit pasted.
4. `how`: Burp-flavored: in Repeater, chain a second command after a valid host with the pipe separator (the filter only strips semicolons), then confirm its real output in the response body.

### Verification

- `node --check` on the edited file: pass.
- Diff contains zero em dash characters.
- Booted scratch server (`DB_PATH=/tmp/burp-w044.db PORT=18044 node app.js`): `/cmdi/ping8` 200; `?host=127.0.0.1%7Cid` 200 with the flag box rendered. Server killed after check.

## Challenge 2: cmdi-tab (Ping Gadget v9, spaces blocked, again)

- Module: cmdi
- Challenge file: `modules/cmdi/challenges/cmdi-tab.js`
- Route: `GET /cmdi/ping9`

### Verdict

**BURP-CLEAN.** The full exploit chain works with plain, standard HTTP through Burp Proxy and Repeater. The award condition (`host.includes('\t') && PASSWD_EVIDENCE.test(out)`) needs only a literal tab in the decoded query parameter. The test suite itself proves the mechanism: it sends the host through `encodeURIComponent`, which turns the tab into `%09`, and Express decodes `%09` back to a tab. Burp Repeater sends `%09` through untouched (no mangling, no re-encoding issue). No raw sockets, no malformed HTTP, no timing dependency, no Burp-mangled bytes, no curl-specific behavior, no non-HTTP protocol. Community edition is enough.

### Tools

Old: `B, C` (Browser, curl)
New: `BZ, B, C` (Burp/ZAP first, then Browser, then curl)

The exploit is one GET request with `%09` where the shell needs a word separator. Burp is the recommended tool because the natural workflow is click-through in Proxy, then payload probing in Repeater. Plain browser and curl still work, so `B` and `C` stay as secondary.

### Burp workflow steps

1. Proxy: open `http://localhost:3000/cmdi/ping9`, submit a plain host like `127.0.0.1`.
2. Proxy history: find the `GET /cmdi/ping9?host=127.0.0.1` request and send it to Repeater.
3. Repeater: probe the filter first (watch it strip spaces), then build a chain with a separator the filter allows and `%09` wherever the shell needs a word separator. Repeater sends `%09` untouched.
4. Read the response body. The flag is awarded only when the second command's real output shows up in the response, so pick a command that prints a recognizable file.

### Issues

None. The tab encoding behavior is confirmed by the test itself (`cmdi-tab: a stripped space fails, a literal tab is whitespace too` uses `encodeURIComponent`, i.e. `%09` on the wire). The audit only changed presentation (tool tags and voice), not behavior.
