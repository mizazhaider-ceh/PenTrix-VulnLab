# Burp-first audit: w076 crypto-b64-cookie

Challenge: Base64 "Encryption" (crypto-b64-cookie)

## Verdict

BURP-CLEAN

## Tools old -> new

Old: `B, DT`
New: `BZ, B, DT`

Burp/ZAP moved to first position. The challenge is fully solvable through
Burp Proxy plus Repeater plus the Decoder tab, so BZ belongs at the front.
Browser and DevTools remain because the page works in a plain browser too.

## Burp workflow steps

1. Browse to /crypto#crypto-b64-cookie with Burp Proxy on and click
   "Get a session cookie". The server sets vlab_b64 and also prints the
   value on the page.
2. Right-click the login POST in Proxy history and send it to Repeater.
3. Copy the vlab_b64 value and send it to Burp Decoder. Decode as Base64.
   The result is JSON with user and role fields.
4. Edit the JSON so role is admin. In Decoder, re-encode as Base64.
5. In Repeater, POST to /crypto/b64/check with the forged cookie in the
   form field, or paste it into the forge form on the page. The dashboard
   greets you as admin and the flag appears.

## Issues

None. The whole chain is standard HTTP form traffic. The cookie value is
plain base64 of ASCII JSON, so Burp Decoder handles it with no byte
mangling. No raw sockets, no binary tricks, no curl-only behavior.
