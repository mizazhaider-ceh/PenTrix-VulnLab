## email (Change Email with No CSRF Token, state-changing GET)

**Verdict:** BURP-CLEAN

**Tools old -> new:** `B` -> `BZ, B`

**Burp workflow:**
1. In Burp, configure the target scope for the PenTrix lab app and route the browser through Proxy.
2. In the browser, log in as alice and open the Email settings page (`/csrf/change-email`).
3. In Proxy HTTP history, find the `GET /csrf/change-email` request and send it to Repeater. This request carries the session cookie.
4. In Repeater, add an `email` query parameter (e.g. a new address) and send. No token is required: the endpoint is a state-changing GET with no anti-CSRF token and no Origin/Referer check.
5. The response shows "Email changed" and awards the flag server-side. This is exactly what a forged cross-site request from an attacker's page would do to the victim.
6. For the full attack narrative, right-click the captured request in Proxy and use Engagement tools -> "Generate CSRF PoC" to build the attacker's HTML page (img tag or auto-submitting form) carrying the forged URL.

**Issues:** None. The exploit chain is a plain GET with a query parameter and a session cookie: nothing needs raw sockets, mangled bytes, or curl-specific behavior. Anonymous requests cannot trigger it (the app requires login), but Burp captures the session cookie normally through Proxy, so the logged-in Repeater request works. The old `start` was a curl one-liner and `tools` lacked the Burp tag, which conflicted with the Burp-first voice.

**Changes applied:**
- `tools`: `B` -> `BZ, B` (Burp/ZAP first, browser kept for the victim-side narrative)
- `start`: Burp-oriented starting point (route browser through Burp Proxy, log in, open Email settings, find the GET in Proxy history, send to Repeater); no curl one-liner
- `hints`: each step now names the Burp action (Proxy capture, Repeater forgery, Generate CSRF PoC); nudges only, no exploits pasted
- `how`: Burp-flavored ("In Repeater, send GET /csrf/change-email with an email query parameter while carrying the logged-in session cookie; no token or confirmation is required.")
