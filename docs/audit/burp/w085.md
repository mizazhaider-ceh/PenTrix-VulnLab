# Burp-first audit: w085, biz-negative-qty (Negative Quantity Credit)

## Verdict
BURP-CLEAN. The full exploit chain runs in Burp Suite Community with only
Proxy and Repeater. No raw sockets, no malformed HTTP, no curl-specific
behavior, no non-HTTP protocol.

## Tools old -> new
- Old: `"B"` (Browser)
- New: `"BZ, B"` (Burp/ZAP first, Browser kept)
- Rationale: the vuln is parameter tampering on `qty` in a form POST body.
  That is the canonical Burp Proxy intercept-and-edit flow, so per D16 the
  Burp voice is primary.

## Burp workflow steps
1. Set Burp Proxy intercept on and browse to the challenge:
   `http://localhost:3000/bizlogic/negative-qty`.
2. In the browser, keep the default quantity and click Checkout.
3. In the Proxy intercept tab, the request is a plain
   `POST /bizlogic/negative-qty` with
   `Content-Type: application/x-www-form-urlencoded` and body `qty=1`.
4. Edit the body so `qty` holds a negative value, then Forward the request.
5. The response page shows "The shop paid you." plus the Flag captured
   banner. Repeater works too: send the captured POST again with different
   negative values. Intruder can fuzz `qty` over a numeric payload list.

## Issues
None found. The body is standard `application/x-www-form-urlencoded`
(`express.urlencoded` parses it), Burp never mangles it, the flag is
awarded on the same response (no second request needed), and the server
distinguishes only integer vs non-integer (`qty === 0` rejected with 400).

## Changes applied
Edited the `vuln` object in
`modules/bizlogic/challenges/biz-negative-qty.js` only:
- `tools`: `"B"` -> `"BZ, B"`.
- `start`: replaced the curl one-liner with a Burp-oriented starting point
  (browse with Proxy intercepting, submit the form, catch and edit the
  POST, forward it).
- `hints`: rewritten as a Burp hint ladder (intercept the POST in the
  intercept tab, look at the request body, forward the modified request).
  Nudges only, no pasted exploits.
- `how`: Burp-flavored wording (intercept the checkout POST, change qty to
  a negative number, forward it, the shop credits the balance).
- No em dashes anywhere in the diff (grep verified: 0 matches).

## Verification
- `node --check` on the edited file: OK.
- Scratch boot (`DB_PATH=/tmp/burp-w085.db PORT=18085 node app.js`):
  `GET /bizlogic` -> 200, `GET /bizlogic/negative-qty` -> 200.
- Exploit simulation of the Burp-modified body (fresh session cookie):
  `POST /bizlogic/negative-qty` with `qty=-1` -> 200, response contains
  "Flag captured" and `PENTRIX{...}`, followed
  by the fix panel. Benign `qty=1` gives no flag. Server killed after.
- FLAG BAR kept: flag awarded only via the award() path on the negative
  balance condition. FLAG SECRECY kept: no flag values added to hints or docs.
