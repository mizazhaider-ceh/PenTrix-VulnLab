### Burp workflow steps
1. Proxy on, browse to `/sqli/register` in the Burp browser and register an account normally.
2. Check Proxy history: the POST to `/sqli/register` (payload lands, stored safely via parameterized query) is followed by the GET to `/sqli/profile?u=...` (payload fires when the stored display name is interpolated into a new query).
3. Send the register POST to Repeater and shape the `display_name` value so it sleeps harmlessly in storage but becomes SQL once the profile lookup reuses it.
4. Register the crafted account, then request `/sqli/profile?u=YOUR_USERNAME` (Repeater GET or browser). The stored value detonates in the second query, the lookup lands on the admin account, and the flag box appears.

Multi-step flows are fine under D16: Burp keeps both requests in Proxy history with session cookies intact. Everything is standard HTTP; no special protocol or timing needs.
