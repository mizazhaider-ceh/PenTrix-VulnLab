# Burp Audit Verdicts: SSTI curly and dotblock (w024)

## ssti-curly (Curly-Brace Strip Bypass)

### Verdict
BURP-CLEAN

### Tools old -> new
Old: `B, C`
New: `BZ, B`

Burp/ZAP moves to first position because the brace-count fuzzing is textbook Repeater work: send one request, vary the number of braces, watch the rendered output change. The browser stays second since the challenge page is a normal HTML form. The curl tag was dropped: curl works but is no longer the recommended path under the Burp-first doctrine, and the challenge needs nothing curl-specific.

### Burp workflow steps
1. Proxy: configure the browser to use Burp Proxy, open `/ssti/curly`, and submit the echo form with any baseline text. Confirm the GET request with the `input` parameter appears in HTTP history.
2. Repeater: send the request to Repeater (right-click, Send to Repeater, or Ctrl+R). Set `input` to a plain template expression and send. The response shows the filter stripped the braces, so the math never evaluates. This establishes the baseline.
3. Repeater (bypass): keep resending with more brace pairs wrapped around the same expression. The filter removes only the first `{{` and the first `}}` once, without re-scanning. After enough passes, one valid `{{ }}` pair survives and evaluates.
4. Confirm the flag: the rendered output shows the doubled number and the raw input still contained `{{ }}`, so the challenge awards the flag automatically. Intruder is optional here: mark the brace count as a payload position (Sniper) to sweep the counts faster.

### Issues
None found. The whole chain is plain HTTP GET traffic through a standard query parameter: no raw socket control, no malformed HTTP, no timing sensitivity, no byte-exact payloads that Burp would mangle. Curly braces URL-encode cleanly and survive Proxy, Repeater, and Intruder unchanged. The single-strip filter runs on the server after Burp delivers the request, so the bypass logic is unaffected by Burp normalization.

- `tools`: `B, C` -> `BZ, B`
