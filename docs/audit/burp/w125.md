# Burp Audit w125: host-reset-poison (Password Reset Poisoning)

## Verdict

BURP-CLEAN. The full exploit chain works with Proxy, Repeater and a normal browser over standard HTTP. No raw sockets, no malformed HTTP, no curl-only behavior.

## Burp workflow steps

1. Open Burp Proxy, browse to GET /hostheader/forgot, submit the reset form for the victim email.
2. In Proxy HTTP history, send the POST /hostheader/forgot request to Repeater.
3. In Repeater, edit the Host header line to name a domain you control and send the request.
4. Read the reset token from the "Email sent" lab view in the response. The reset link now points at your domain.
5. Visit /hostheader/evil-collect?token=THE_TOKEN in your browser. The collector awards the flag because the token was issued under a poisoned host.

## Issues

None blocking. The challenge is a single POST with a rewritten Host header, the canonical Repeater exercise. Burp preserves the header verbatim and normalizes nothing here. Note: the legitimate-host token is rejected by the collector by design, so the learner must actually poison the header.
