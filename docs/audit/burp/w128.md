# Burp Audit w128: csti/basic (Basic Template Evaluation)

## Verdict

BURP-CLEAN. The full exploit chain works through Burp Suite Community
with Proxy, the embedded browser, and Repeater, using standard HTTP
only. No raw sockets, no Burp-mangled bytes, no curl-specific behavior,
no non-HTTP protocols.

## Tools (old -> new)

- Old: `B`
- New: `BZ, B` (Burp/ZAP first, Browser kept). Matches the tools taxonomy
  in lib/page.js (~line 231): B=browser, BZ=Burp/ZAP.

## Burp workflow steps

1. Point Burp Proxy at your browser (or open Burp's embedded browser) and
   browse to http://localhost:3000/csti/basic. The greeting form renders
   through Proxy.
2. In the form, save a greeting containing an arithmetic expression in
   `{{ }}` delimiters (for example `{{7*7}}`). The page POSTs it to
   /csti/basic, which stores it in your session.
3. Reload /csti/basic. The preview renders the stored template, the
   client-side engine evaluates the expression, and the preview shows
   49. View the page source in Proxy: it carries the page-bound
   CSTI_NONCE token.
4. The page beacons for you automatically: when the output contains 49 it
   fires GET /csti/beacon?v=basic&d=49&n=<page token>. Watch the beacon
   request in Proxy, then forward it. The response carries the flag
   banner (per-deployment flag, FLAG BAR and FLAG SECRECY unchanged).
5. Alternative Repeater path: copy the beacon request from Proxy history
   into Repeater, paste a fresh CSTI_NONCE from a fresh page load, and
   send. Tokens are single-use per page load, so replaying a token returns
   400, which proves the anti-replay design is live.

## Issues

- None blocking. The old `start` field carried a curl one-liner
  (`curl ... | grep -n CSTI_NONCE`), which is a curl-specific habit, not
  Burp-first. The old `how` was curl-flavored and the old hints did not
  name any Burp step.
- The beacon shortcut defenses (bare beacon without a page load gets
  400; guessed token gets 400; replayed token gets 400) are all standard
  HTTP status responses, so they are fully observable and debuggable in
  Repeater. No redesign needed for them.

## Changes applied

In modules/csti/challenges/basic.js, `vuln` object only:

1. `tools`: "B" -> "BZ, B".
2. `start`: replaced the curl one-liner with a Burp-oriented starting
   point (proxy the browser or use the embedded browser, find the form
   and the CSTI_NONCE token in the page source).
3. `hints`: three Burp-flavored nudges (open in Burp's browser and save
   an expression in the form; find CSTI_NONCE in Proxy page source and
   replay the beacon in Repeater; watch the page auto-beacon in Proxy and
   see the flag come back). Nudges only, no exploits pasted.
4. `how`: Burp-flavored (save the template in Burp's embedded browser,
   load the page, the preview renders 49 and the page fires its beacon
   with the page-bound token to claim the flag).
