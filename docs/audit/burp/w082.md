## bizlogic/biz-coupon-stack

- Verdict: BURP-CLEAN
- Tools: "B" -> "BZ, B"
- Burp workflow:
  1. In the browser, open the checkout page and submit the coupon form once with any single code (e.g. SAVE50) while Burp Proxy intercepts.
  2. In Proxy > HTTP history, right-click the POST /bizlogic/coupon-stack request and send it to Repeater.
  3. In Repeater, experiment with the codes parameter: the page tells you to separate multiple codes with commas or spaces, and it lists three codes. Add more codes and send each variation.
  4. Observe the receipt: when the stacked percentages cross 100%, the page renders "Discount hit 100% or more" with a negative total, and the flag box appears. Replaying the request with one code first (50% off, still paying) versus the stacked set confirms the difference.
  5. Optional: use Intruder to cycle the codes parameter through all single, pair and triple combinations (sniper attack on the codes field) and sort by response length to spot the flag-bearing response.
- Issues: none. The exploit is a plain application/x-www-form-urlencoded POST over standard HTTP; nothing Burp would normalize, mangle, or fail to replay. Codes are uppercase-transformed and split server-side on non-alphanumeric separators, so Burp's default URL-encoding of commas/spaces is handled fine. No raw-socket tricks, no malformed HTTP, no non-HTTP protocols.
