## idor-apikey-regen

- Verdict: BURP-CLEAN
- Tools: "B, C" -> "BZ, B"
- Burp workflow:
  1. In Burp Suite Community, set the browser to use Burp's proxy (Proxy > Intercept off, history recording on) and log in to the IDOR shop as alice at /idor/login/alice, then open /idor/apikey.
  2. Click "Regenerate my key" in the browser and find the POST /idor/apikey/regen request in Proxy history. Note the user_id parameter holding your own account id.
  3. Right-click the request and send it to Repeater. In Repeater, change the user_id parameter to another account's id (the admin is id 1) and send.
  4. The response shows the fresh API key generated for that account. Copy the key from the response body.
  5. Open /idor/apikey/use in the browser (or send a new GET /idor/apikey/use?key=... request in Repeater) with the copied key. The page confirms the key belongs to the other user and shows the flag, because the rotation row for that key is marked via_idor by you.
- Issues: none. The chain is a plain urlencoded form POST followed by a GET with a query string, both replayable in Repeater with standard HTTP. No raw sockets, no byte mangling, no curl-specific behavior.
- Changes applied: vuln object in modules/idor/challenges/idor-apikey-regen.js updated. tools now "BZ, B" (Burp first, curl tag dropped because the whole chain is a Proxy/Repeater job). start rewritten as a Burp-oriented starting point ("Point your browser at Burp's proxy, then visit http://localhost:3000/idor/login/alice to log in and open /idor/apikey.", no curl one-liner). hints ladder keeps Nudge/Technique/Explicit tiers and now names the Burp step (intercept the regenerate click, send to Repeater, edit user_id); no exploit payloads pasted. how made Burp-flavored: intercept the regeneration POST, edit user_id to another account's id, then use the fresh key.
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (DB_PATH=/tmp/burp-w096.db PORT=18096 node app.js) returned HTTP 200 for /idor and for /idor/apikey and /idor/comments as logged-in alice; server killed afterwards.

## idor-comment-delete

- Verdict: BURP-CLEAN
- Tools: "B, C" -> "BZ, B"
- Burp workflow:
  1. In Burp Suite Community, set the browser to use Burp's proxy and log in to the IDOR shop as bob at /idor/login/bob, then open /idor/comments.
  2. Read the comments table in the browser and note the id of a comment written by someone else (a row that shows "Not yours" with no delete button).
  3. Delete one of your own comments in the browser while Proxy records history, then right-click that POST /idor/comments/delete request and send it to Repeater.
  4. In Repeater, change the id parameter to the id of someone else's comment and send. The response confirms the other author's comment was deleted and shows the flag, because the server keys deletion on id alone and never checks authorship.
  5. Optional: send the request to Intruder and iterate the id parameter over the comment id range to confirm any id deletes regardless of author.
- Issues: none. The chain is a single urlencoded form POST keyed by a numeric id, fully replayable in Repeater/Intruder with standard HTTP. No raw sockets, no byte mangling, no curl-specific behavior.
- Changes applied: vuln object in modules/idor/challenges/idor-comment-delete.js updated. tools now "BZ, B" (Burp first, curl tag dropped because the whole chain is a Proxy/Repeater job). start rewritten as a Burp-oriented starting point ("Point your browser at Burp's proxy, then visit http://localhost:3000/idor/login/bob to log in and open /idor/comments.", no curl one-liner). hints ladder keeps Nudge/Technique/Explicit tiers and now names the Burp step (intercept your own delete click, send to Repeater, try a different id); no exploit payloads pasted. how made Burp-flavored: submit another user's comment id to the delete endpoint from Repeater.
- Verification: node --check passes. grep for em dash over the challenge file diff: zero. Scratch server (DB_PATH=/tmp/burp-w096.db PORT=18096 node app.js) returned HTTP 200 for /idor and /idor/comments as logged-in bob; server killed afterwards.
