Worker: w074 | Module: jwt | Challenges: kid-sqli, no-expiry | Date: 2026-10-19

## Challenge 1: kid-sqli (SQL Injection in kid Lookup)

### Verdict
BURP-CLEAN.

### Tools old -> new
`"N, C"` -> `"BZ, N"`.

### Burp workflow steps
1. Proxy on, open `/jwt/kid` in the Burp browser and submit the sample guest token once normally.
2. In Proxy history find the POST to `/jwt/kid` and send it to Repeater.
3. In Repeater, mint a new JWT whose header `kid` breaks out of the quoted SQL lookup so the SELECT returns a key you control. The kid travels base64url-encoded inside the token, so quotes and spaces are plain ASCII over HTTP and Burp never mangles them.
4. Sign that token with the key you smuggled into the query (the Burp JSON Web Tokens extension can mint and sign tokens, or a small local Node/Python signing script works), put it in the Repeater body as `token=`, and forward. The server verifies your token against the key you chose, role `admin` lands, and the flag box appears.

The whole chain is standard HTTP form POSTs. No raw sockets, no non-HTTP protocols, no curl-specific behavior, no bytes Burp would mangle. N stays genuinely helpful for the HMAC signing step alongside Burp.

### Issues
- `tools` listed `N, C` with Burp absent, contrary to the D16 Burp-first doctrine. The curl one-liner in `start` was removed.
- `hints` were tool-agnostic and `hints[2]` nearly pasted the full exploit recipe; hints should nudge, not hand over the chain.

### Changes applied
- `tools`: `"N, C"` -> `"BZ, N"` (BZ first, N kept for token signing, C dropped).
- `start`: replaced the curl one-liner with a Burp-oriented starting point (Proxy, submit sample token, send POST to Repeater).
- `hints`: rewrote all three to name Burp steps (Proxy, Proxy history, Repeater, JWT extension or local signing script) as nudges only; no exploit pastes.
- `how`: made Burp-flavored (smuggle the key in, sign, submit through Repeater).
- `hint` (short field): left unchanged, already tool-neutral.

## Challenge 2: no-expiry (Expiry Never Checked)

### Verdict
BURP-CLEAN.

### Tools old -> new
`"B"` -> `"BZ, B"`.

### Burp workflow steps
1. Proxy on, open `/jwt/noexpiry` in the Burp browser. The page prints the leaked admin token, which expired an hour ago.
2. Copy the token from the page (Proxy history shows the GET response carrying it verbatim).
3. Submit the token unchanged, either in the page form or by sending the POST to Repeater and pasting the token there. The verifier never checks the `exp` claim, so the expired token is accepted and the flag box appears.

Pure token replay over standard HTTP. Burp preserves the exact token string, nothing expires in transit, and the entire attack needs no tooling beyond Proxy and Repeater.

### Issues
- `tools` listed only `B`; Burp was not named despite Proxy/Repeater being the natural voice for a capture-and-replay flow.
- `start` was a curl one-liner, contrary to Burp-first doctrine.

### Changes applied
- `tools`: `"B"` -> `"BZ, B"`.
- `start`: replaced the curl one-liner with a Burp-oriented starting point (Burp browser, Proxy on, copy leaked token from the page).
- `hints`: rewrote all three to name Burp steps (Proxy, Proxy history, Repeater) as nudges only.
- `how`: made Burp-flavored (submit unchanged through the browser or Repeater).
- `hint` (short field): left unchanged, already tool-neutral.
