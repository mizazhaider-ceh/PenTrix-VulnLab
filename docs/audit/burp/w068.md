## Challenge 1: pkce-skip (Lab 8: PKCE Downgrade)

**Verdict:** BURP-CLEAN

**Tools:** old `C` -> new `BZ, B`

**Burp workflow steps:**
1. Start Burp, turn on Proxy intercept (or just history logging), and route the browser through it.
2. Log in to the IdP as bob and open the Lab 8 page.
3. Click the authorize-with-code_challenge link and approve the request on the consent screen.
4. Copy the issued code from the redirect target shown on the approval page.
5. Find the token exchange request in Proxy history, send it to Repeater, and replay it with no `code_verifier` parameter.
6. The token endpoint returns 200 and the JSON includes a `flag` field.

**Issues:** None. The entire exploit chain is standard HTTP: GET login, GET authorize, POST approve, POST token. No raw sockets, no malformed HTTP, no Burp-mangled bytes, no curl-specific behavior.

**Changes applied:**
- `tools`: `C` -> `BZ, B` (BZ first, per taxonomy in lib/page.js).
- `start`: replaced the curl login one-liner with a Burp-oriented starting point (proxy browser, log in as bob, send token exchange to Repeater).
- `hints`: rewritten as Burp nudges that name Repeater and Proxy without pasting an exploit.
- `how`: Burp-flavored (authorize in browser, replay token POST in Repeater minus the verifier).
- Award logic untouched (lives in shared doTokenExchange, out of scope for this file).
