## formula-dde (DDE Command Execution)

### Verdict
BURP-CLEAN.

### Tools old -> new
`B` -> `BZ, B` (Burp first per D16; browser form entry stays as the discovery path).

### Burp workflow steps
1. Proxy on, open `/formula` in the Burp browser and add one normal contact, so the baseline POST to `/formula/add` lands in Proxy history.
2. In Proxy history, send that POST to Repeater. The body is a plain `application/x-www-form-urlencoded` body with `name` and `note` parameters.
3. In Repeater, change the `name` parameter into a formula cell that calls the DDE() spreadsheet function with a target application, a topic, and a system command. The exporter only RFC 4180 quotes the cell, it never neutralizes the formula trigger, so the exported cell still opens as a live formula.
4. Send the request (expect a 302 redirect back to `/formula`), then request `/formula/export.csv` and read the `X-Flags` response header: the flag arrives there and the scoreboard marks the challenge captured.

The whole chain is a standard form POST plus a standard CSV download. Burp handles the urlencoding of `=`, `"`, `;`, `(`, `)` without mangling anything, and the flag is visible in Repeater's response headers. No raw sockets, no malformed HTTP, no curl-only behavior.

- `hints` described the DDE mechanism but never named the Burp steps (Proxy capture, push to Repeater, shape `name`, check `X-Flags`).
- `how` and `start` were tool-neutral / curl-oriented, not Burp-flavored.

### Changes applied
- `tools`: `B` -> `BZ, B`.

- `hints`: all three now name the Burp step (baseline POST in Proxy history, push to Repeater, edit `name`, check the `X-Flags` header after downloading the export). Nudges only; no exploit pasted.
