# Burp-first audit: ssti-wordfilter (w027)

## Verdict: BURP-CLEAN

Challenge: `modules/ssti/challenges/ssti-wordfilter.js`, route `GET /ssti/wordfilter?input=...`. The naive template engine eval()s anything inside `{{ }}` after deleting the words `flag`, `secret` and `config` (case-insensitive) from the raw input. The flag sits in the in-scope variable `vaultSecret`. The test-proven bypass (tests/ssti.test.js line 48) is `{{eval("vaultSec"%2B"ret")}}`: the filter strips nothing from the fragments, the engine concatenates them at run time and reads the secret variable, and the flag is awarded when the rendered output contains it.

Nothing in this chain needs anything beyond standard HTTP. The exploit is a plain GET with a query parameter, deterministic, no timing, no raw sockets, no Burp-mangled bytes (the `+` becomes `%2B`, which Repeater handles in its params table), no curl-specific behavior and no non-HTTP protocol. The bypass discovery (fragment order, case tricks, encoding variants, alternative concat forms) is exactly the classic Intruder fuzzing flow called out in D16.

## Tools: old -> new

`B, C` -> `BZ, B` (Burp/ZAP now first; browser keeps the form entry point; curl removed since the flow is Burp-native).

## Burp workflow steps

1. **Proxy**: with Burp Proxy on, open `/ssti/wordfilter`, submit a note, and watch the GET land in the proxy history.
2. **Repeater**: send the request to Repeater. Set the `input` parameter to `{{7*7}}` to prove the engine evaluates templates (response shows 49). Then type the full flag variable name directly and watch the filter strip it in the response, so `{{vault}}` renders empty.
3. **Repeater (bypass design)**: split the blocked word into harmless fragments and evaluate their concatenation inside `{{ }}`, so the filter never sees the whole word in the raw input.
4. **Intruder**: send the request to Intruder and fuzz filter-bypass variants on the fragment payload (fragment order, case tricks, encoding variants) until the rendered note returns the flag.
5. **Capture**: the rendered response containing the flag triggers the flag bar via the normal award path.
