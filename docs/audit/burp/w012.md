# Burp-First Audit w012: Exposed .git Directory (misconfig/git)

Challenge: modules/misconfig/challenges/git.js, vuln id "git", difficulty Medium.

## Verdict

BURP-CLEAN.

The full exploit chain is five plain HTTP GET requests with no special
bytes, headers, or timing: `/.git/HEAD`, `/.git/refs/heads/main`,
`/.git/objects/`, `/.git/objects/<dir>/`, `/.git/objects/<dir>/<file>`.
Burp handles every step without normalization risk: Proxy captures the
responses, Repeater replays the path walk, and Intruder can fuzz the
`<dir>/<file>` object paths if desired. No raw sockets, no malformed HTTP,
no non-HTTP protocols, no curl-specific behavior.

## Tools old -> new

Old: `C` (curl only).
New: `BZ, C` (Burp/ZAP primary, curl still available as a fallback).

## Burp workflow steps

1. With Burp Proxy running and intercept off, browse to
   `/misconfig/.git/HEAD`. The response body is the branch ref.
2. Send the request to Repeater (Ctrl+R). Change the path to
   `/.git/refs/heads/main` and send. The response is the 40-char commit hash.
3. In Repeater, request `/.git/objects/` to list the loose-object store.
   The single directory is the first two hex chars of the commit hash.
4. Open `/.git/objects/<first-two-chars>/` in Repeater; the listing reveals
   the remaining 38 characters as the object filename.
5. Fetch `/.git/objects/<dir>/<file>` in Repeater. The response is the commit
   object; read the diff to recover the leaked backup token.

(For an enumeration-style variant, Intruder can fuzz `/.git/objects/` paths,
but the chain works cleanly by hand in Repeater.)

## Issues

None. The original vuln object was curl-first only (`tools: 'C'`, a curl
one-liner `start`), which conflicted with doctrine D16. The routes needed no
changes: all responses are standard text/HTML over HTTP and replay
identically through Proxy/Repeater.
