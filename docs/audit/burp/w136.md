# Burp Audit w136: api/exposure (Excessive Data Exposure)

## Verdict

BURP-CLEAN. The exploit chain is one plain GET request over standard HTTP.
The flag is awarded when the response contains the string `"password"`,
and it is returned in the `X-Pentrix-Flag` response header. Everything is
visible in Burp Suite Community Proxy history and Repeater.

## Tools

Old: `B, C` (Browser, curl).
New: `BZ, B` (Burp/ZAP, Browser). Burp now leads; the browser stays only
for loading the viewer page that generates the capturable traffic.

## Burp workflow steps

1. Target tab: add the lab host to scope (e.g. http://localhost:3000).
2. Proxy tab: enable Intercept off, browse to `/api/users/view` in the
   configured browser, then open the HTTP history.
3. In the Proxy history, find the request `GET /api/users`.
4. Right-click it and choose "Send to Repeater".
5. Repeater tab: click Send. The 200 response shows the full JSON array,
   including the leaked `password` field on every user row.
6. Inspect the response headers in Repeater: the `X-Pentrix-Flag` header
   carries the flag. The challenge is captured; the viewer page at
   `/api/users/view` also displays the flag box after capture.

## Issues

- The old `tools` field was `B, C`, leading with the browser and curl,
  neither of which reads response headers as naturally as Burp Repeater.
- The old `start` was a curl one-liner (`curl -i`), not Burp-oriented.
- The old hints talked about "fetching" generically and never named the
  Burp steps (Proxy history, Repeater).
- `how` was tool-neutral but passive; it now names the Burp flow.
- The underlying vulnerability needed no change: no raw sockets, no
  Burp-mangled bytes, no curl-specific behavior, HTTP only.

## Changes applied

File: `modules/api/challenges/exposure.js`, vuln object only.

- `tools`: `B, C` -> `BZ, B`.
- `start`: curl one-liner replaced with a Burp-oriented starting point
  (browse the viewer with Proxy on, find GET /api/users in history,
  send to Repeater, inspect the full response).
- `hint`: now mentions proxying the raw request in Burp.
- `hints`: three nudges naming the exact Burp steps (Proxy history,
  Send to Repeater, check response headers). No exploits are pasted.
- `how`: Burp-flavored rewrite.

Verified: `node --check` passes; `git diff` contains zero em dashes;
scratch boot on PORT=18136 returned 200 on `/api/users/view` and the
`X-Pentrix-Flag` header was present on `/api/users`. Server stopped.
No tests were touched. No commit, no push.
