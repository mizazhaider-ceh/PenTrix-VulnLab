# Burp Audit w009: misconfig / backup (Exposed Database Backup)

## Verdict

BURP-CLEAN. The exploit chain is a plain HTTP GET served verbatim by Express.
Every step works in Burp Community with only standard tools: Proxy for
browsing, Repeater for the filename guess, and Burp search in the response
body for credentials and tokens. No raw sockets, no malformed HTTP, no timing
tricks, no byte mangling, no curl-specific behavior, no non-HTTP protocol.

## Tools old -> new

`B, C` -> `BZ, B` (Burp/ZAP first, browser second; curl dropped as primary).

## Burp workflow steps

1. Proxy the lab (e.g. http://localhost:3000) in Burp and browse to /misconfig.
2. Send the /misconfig page request to Repeater.
3. In Repeater, change the path to common backup filenames under /misconfig/
   (e.g. backup.sql) until one returns a 200 with a SQL dump instead of 404.
4. Read the response body and search it for plaintext credentials or tokens.
5. The flag is awarded on the successful GET of the dump file.

## Issues

None for Burp compatibility. Behavior confirmed against
tests/misconfig.test.js: guessing wrong names (e.g. backup.bak) returns 404
and awards nothing; only the correct filename triggers the award.
