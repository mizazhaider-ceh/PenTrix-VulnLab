# Burp-first audit w139: redos-email (Catastrophic Email Regex)

## Verdict
BURP-CLEAN. The exploit chain is a plain GET to `/redos/email?email=<input>` through standard HTTP, and the flag is awarded when the server's wall-clock regex check exceeds 1000 ms (the page body reports `Time: X ms`, and the delay is directly visible in Burp Repeater's response timer). No raw sockets, no Burp-mangled bytes, no curl-specific behaviors, no non-HTTP protocol. The whole chain works through Burp Proxy, Repeater, and Intruder (Community edition is enough).

## Tools old -> new
- Old: `B, C` (Browser, curl)
- New: `BZ, B` (Burp/ZAP first, Browser kept, curl dropped)

## Burp workflow steps
1. Start Burp Proxy and configure the browser to use it.
2. Browse to `/redos/email` in the proxied browser. The form page and the result page both print the exact email regex, including the nested quantifier in the local part.
3. Submit the form once, then right-click the request in Proxy HTTP history and send it to Repeater.
4. In Repeater, edit the `email` parameter: build an input that is almost valid (a long run of characters the local part allows, with no `@` anywhere), ending in a character that breaks the match so the engine must retry every split.
5. Send, and watch the Repeater response time. Grow the run a few characters at a time (Intruder with a single payload position can ramp this automatically). Each added character multiplies the backtracking work.
6. When the reported time crosses the 1000 ms threshold, the response body contains the flag: "Denial of service demonstrated".

## Issues
- None block Burp-first solving. One design note: the 33 character input cap means the payload must fit in 33 chars, but the catastrophic backtracking fires well inside that limit, so Intruder length-ramping converges quickly.

## Changes applied
In `modules/redos/challenges/redos-email.js` (`vuln` object only):
- `tools`: `B, C` -> `BZ, B` (BZ first, curl dropped).
- `start`: replaced the curl one-liner with a Burp-oriented starting point (open `/redos/email` in the proxied browser, send the signup request to Repeater, add an email parameter).
- `hints`: rewritten as Burp-step nudges (send the request to Repeater, read the printed regex, build the long valid run with no `@`, watch the Repeater timer, ramp with Intruder until the 1000 ms threshold is crossed). No exploits pasted.
- `how`: Burp-flavored (send the GET in Repeater with an email of about 30 repeated valid local-part characters plus a match-breaking tail, staying within the 33 char cap; the check crosses the threshold and the flag is awarded).

Verified: `node --check` passes, zero em dashes in the file, scratch server (`DB_PATH=/tmp/burp-w139.db PORT=18139`) returned 200 on `/redos/email`, and an evil input returned 200 with a ~23 s response time (well past the threshold). Server stopped cleanly. FLAG BAR and FLAG SECRECY untouched.
