# Burp-First Audit: w039 (lfi/traversal, Basic Path Traversal)

## Verdict
BURP-CLEAN. The exploit chain works end to end through standard HTTP and is
fully reproducible via Burp Proxy, Repeater and Intruder (Community edition is
enough). No redesign needed.

## Tools
- Old: `B, C` (Browser, curl)
- New: `BZ, B, C` (Burp/ZAP first, Browser, curl)

## Exploit chain (verified on scratch boot)
1. Open the challenge link `/lfi/view?file=readme.txt` in the browser with Burp
   Proxy intercepting.
2. Forward the request to Repeater.
3. In Repeater, change the `file` query parameter from `readme.txt` to a
   traversal payload (e.g. `../docs/secret.txt`) and send.
4. The response renders the secret marker, and the flag box
   (`PENTRIX{...}`) is awarded. A plain read (`file=readme.txt`) shows no flag,
   so the award correctly requires the traversal.
5. Optional depth fuzzing: send the request to Intruder and fuzz traversal
   depth and encodings (`..%2f`, `....//`, double-encoded dots and slashes),
   watching responses for the secret marker.

## Burp workflow steps
- Proxy: intercept a normal document open request.
- Repeater: modify the `file` parameter to inject `../` sequences, adjust depth
  until the secret marker appears in the response.
- Intruder: fuzz depth/encoding variants (ideal Intruder work per D16).
- No Decoder trickery, no timing attacks, no raw sockets required.

## Issues
None blocking. The request is a plain GET with a standard URL-encoded query
parameter; nothing here needs raw sockets, malformed HTTP that Burp would
normalize, unreproducible timing, Burp-mangled bytes, curl-specific behaviors,
or non-HTTP protocols.
