## upload/stored-xss

- Verdict: BURP-CLEAN
- Tools: "B, C" -> "BZ, B, C"
- Burp workflow:
  1. Start Burp Proxy, open the PixelDrop upload page (/upload) in your proxied browser, and confirm the POST /upload?filename= request appears in the HTTP history. The endpoint takes the filename from a query parameter and stores the raw request body bytes unchanged.
  2. Send the intercepted upload request to Repeater (right-click, Send to Repeater, or Ctrl+R).
  3. In Repeater, set the ?filename= query parameter to a .html name (for example evil.html) and replace the entire request body with your own HTML file bytes containing JavaScript. Send the request.
  4. The response confirms the file is stored and returns its /uploads/ link. Open that link in your proxied browser: the server serves the file inline, so the stored script executes in your browser (stored XSS). The challenge awards the flag when a .html or .svg file is stored.
  5. Optional: send the request to Intruder with the filename extension as a payload position to confirm only .html/.svg names earn the flag while other extensions do not.
- Issues: none. The whole chain is plain HTTP: one POST with a raw body and a query parameter, then one GET in the browser. No multipart framing for Burp to reshape, no raw-socket control, no malformed HTTP that Burp would normalize, no timing sensitivity, no byte-exact payloads that Burp would mangle. The server stores whatever bytes arrive, so Proxy, Repeater, and Intruder deliver them faithfully.
