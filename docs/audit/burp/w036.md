# Burp-first audit: w036, double-encode + filter-bypass (LFI)

- Module: lfi
- Challenge files: `modules/lfi/challenges/double-encode.js`, `modules/lfi/challenges/filter-bypass.js`
- Routes: `GET /lfi/double` (Encoding Bypass), `GET /lfi/download` (Naive Filter Bypass)

Both challenges were audited in one worker. Each gets its own section below.

---

## Challenge 1: double-encode (`/lfi/double`, Encoding Bypass)

### Verdict

**BURP-CLEAN.** The full exploit chain works with plain, standard HTTP through Burp Proxy, Repeater, and the Burp Decoder. No raw sockets, no malformed HTTP, no timing dependency, no byte mangling, no curl-specific behavior, no non-HTTP protocol. Community edition is enough.

Encoding analysis: the app reads the parameter from the raw request line (`rawParam` on `req.originalUrl`) and decodes it twice with `decodeURIComponent` (once for the check, once for the read). Burp Repeater sends the request line verbatim, so a twice-encoded value arrives at the app exactly as typed, unlike curl `--data-urlencode` which would collapse one encoding layer before the app ever sees it. The exploit therefore does NOT depend on curl's specific URL-encoding behavior; Burp is the more faithful tool for this challenge, because what you paste into Repeater is byte-for-byte what the server receives.

### Tools

Old: `C` (curl)
New: `BZ, C` (Burp/ZAP first, then curl)

Burp is the recommended tool because the natural workflow is Decoder to encode the payload twice, then Repeater to send it verbatim and compare the filter's response with the final read. curl still works if you supply the already-encoded value, so `C` stays as secondary.

### Burp workflow steps

1. Proxy: browse to `http://localhost:3000/lfi/double`. The page explains that traversal sequences are rejected after one decode and offers a library of benign documents.
2. Proxy: submit the form with a normal page name (e.g. `readme.txt`). Send the request to Repeater.
3. Decoder: take the traversal you want (dots and slashes), run it through Burp Decoder "URL encode" twice in a row, and copy the result.
4. Repeater: paste the twice-encoded value into the `page` parameter and send. The "Blocked" check only decodes once, so it sees harmless text; the app then decodes a second time and reads the file.
5. Read the response: the page shows the final decoded path and the file contents. When the secret content appears, the flag is awarded in the flag box. A plain traversal gets "Blocked" instead, which is the correct failure signal.

### Issues

None. The challenge was already Burp-clean; the audit only changed presentation (tool tags and voice), not behavior.

### Changes applied

In `modules/lfi/challenges/double-encode.js` (vuln object only, no route logic touched):

1. `tools`: `C` -> `BZ, C` (Burp/ZAP listed first, per Burp-first doctrine).
2. `start`: was a curl one-liner. Now Burp-oriented: browse to `/lfi/double` in Proxy, send the request to Repeater, and inspect how the filter treats the page parameter.
3. `hints`: reworded so each step names the Burp action (Proxy to Repeater handoff, Decoder to encode twice, comparing the "Blocked" response with the decoded read). Nudges only, no exploit pasted.
4. `how`: tool-neutral, Burp-flavored: slip a twice-encoded traversal past the one-decode filter on `/lfi/double`; Repeater reveals when the filter sees harmless text while the read rebuilds the traversal. The old text pasted the full exploit payload; the new text does not.

### Verification

- `node --check` on the edited file: pass.
- Diff contains zero em dash characters.
- Booted scratch server (`DB_PATH=/tmp/burp-w036.db PORT=18036 node app.js`): `/lfi/double` 200. A request carrying a twice-percent-encoded traversal on the request line (the exact bytes Burp Repeater would send) returned the "Flag captured" banner. Server killed after check.

## Challenge 2: filter-bypass (`/lfi/download`, Naive Filter Bypass)

### Verdict

**BURP-CLEAN.** The full exploit chain works with plain, standard HTTP through Burp Proxy and Repeater. No raw sockets, no malformed HTTP, no timing dependency, no byte mangling, no curl-specific behavior, no non-HTTP protocol. Community edition is enough.

Encoding analysis: the payload is plain ASCII (`....//` nested traversal), so there is nothing for any HTTP client to encode differently. The exploit is byte-identical in curl, the browser, and Burp Repeater.

### Tools

Old: `B, C` (Browser, curl)
New: `BZ, B, C` (Burp/ZAP first, then Browser, then curl)

Burp is the recommended tool because the natural workflow is click-through in Proxy, then iterate on the `file` parameter in Repeater and read the post-filter "Contents of" line to confirm the collapse. The plain browser form also works, so `B` stays; `C` stays as tertiary.

### Burp workflow steps

1. Proxy: open `http://localhost:3000/lfi/download?file=about.txt`. The page offers a document library and a download form.
2. Proxy: submit the form for a normal document. In the Proxy HTTP history, note the request shape: `GET /lfi/download?file=about.txt`.
3. Repeater: send the request to Repeater. First try a plain `../` traversal and read the response: the filter strips it, and the page shows an "Error reading" line, confirming the single-pass strip.
4. Repeater: try the same traversal nested inside itself in the `file` parameter. The filter removes the inner sequence once and never re-scans, so the response's "Contents of" line shows a fresh `..` sequence surviving, and the secret content is served.
5. When the secret content appears, the flag is awarded in the flag box.

### Issues

None. The challenge was already Burp-clean; the audit only changed presentation (tool tags and voice), not behavior.

### Changes applied

In `modules/lfi/challenges/filter-bypass.js` (vuln object only, no route logic touched):

1. `tools`: `B, C` -> `BZ, B, C` (Burp/ZAP listed first, per Burp-first doctrine).
2. `start`: was a curl one-liner. Now Burp-oriented: open the download URL in Proxy, send the request to Repeater, and watch how the file parameter changes after the filter.
3. `hints`: reworded so each step names the Burp action (Proxy to Repeater handoff, confirming the plain traversal gets stripped, working out the collapse and aiming at the docs folder). Nudges only, no full exploit pasted.
4. `how`: tool-neutral: bypass the single-pass filter with a nested traversal so the stripped result still carries `..` and reads the secret via `/lfi/download`. The old text pasted the full exploit payload; the new text describes the technique without spelling it out.

### Verification

- `node --check` on the edited file: pass.
- Diff contains zero em dash characters.
- Booted scratch server (`DB_PATH=/tmp/burp-w036.db PORT=18036 node app.js`): `/lfi/download?file=about.txt` 200, and a request with the nested-traversal value (verbatim bytes, as Repeater would send) returned the "Flag captured" banner. Server killed after check.
