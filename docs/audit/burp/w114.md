# Burp audit w114: redirect-pollution (Parameter Pollution Picks Last)

## Verdict
BURP-CLEAN. The full exploit chain runs over a plain HTTP GET with a duplicate
`next` query parameter, which Burp Repeater reproduces exactly (duplicate the
parameter in the raw request line and Go). No raw sockets, no Burp-mangled
bytes, no non-HTTP protocol involved. Verified live on a scratch server: 302
with Location pointing at the last value, and the flag banner rendered in the
response body.

## Tools: old -> new
Old: `C` (curl only)
New: `BZ, B, C` (Burp/ZAP first, browser and curl still valid)

## Burp workflow (verified steps)
1. In Burp Proxy, browse to `http://localhost:3000/redirect/polluted` and
   intercept the GET request (or just copy the request line).
2. Send the request to Repeater.
3. In Repeater, edit the request line so `next` appears twice, with the first
   copy holding a harmless value and the second copy holding the target URL.
4. Send and watch the response: the `Location` header honors the last value
   while the first one was the camouflage.
5. The response body confirms the capture ("Flag captured") once more than
   one value is supplied with an external last hostname.

Optional with Intruder: set the second `next` value as a payload position and
sweep a short list of external hosts to observe which one lands in Location.

## Issues found
- None blocking Burp use. Duplicate query parameters survive Burp Proxy and
  Repeater untouched (Burp does not dedupe or reorder them).
- The challenge's original hints/tools leaned on curl one-liners, which did not
  match the D16 Burp-first voice. Fixed by rewording (see Changes applied).

## Changes applied (modules/redirect/challenges/redirect-pollution.js)
- `tools`: `C` -> `BZ, B, C` (Burp/ZAP first, keeping browser and curl).
- `start`: replaced the curl one-liner with a Burp-oriented starting point
  (browse through the proxy, send to Repeater, add a second `next` param,
  compare the Location header).
- `hints`: all three hints now name the Burp step (Proxy -> Repeater, edit the
  query string, watch Location). They give nudges only, never the exploit URL.
- `how`: tool-neutral with Burp flavor (duplicate `next` in Repeater, check
  which value lands in Location).
