## ssrf-file (file:// scheme SSRF)

- Verdict: BURP-CLEAN
- Tools: C -> BZ, C
- Burp workflow: Open the FetchKit form at /ssrf/fetch-file through Burp Proxy, submit the form once with any harmless URL, and send the request to Repeater. Confirm a normal http(s) URL fetches and shows a response body. Then, in Repeater, change the url parameter to use the file:// scheme aimed at a classic world-readable system file (the Unix user database), and send; the fetcher reads the file with the server's privileges and the response body contains the root account entry, which awards the flag. The url value needs no special encoding in Repeater, plain slashes in the query string work fine.
- Issues: none. Plain GET requests with a query-string parameter; Burp Community Proxy and Repeater handle everything with no mangling. No raw sockets, no malformed HTTP, no timing dependency, no Burp-mangled bytes (the file:// scheme and path pass through Repeater untouched), no curl-specific behavior, no non-HTTP protocols.
- Changes applied: tools set to BZ, C (BZ first). start replaced the curl one-liner with a Burp Proxy plus Repeater starting point. hint and hints rewritten to name the Burp steps as nudges only, no exploits pasted (the full file URL is never written in the hints). how reworded to Burp-flavored copy. FLAG BAR and FLAG SECRECY unchanged: the flag award condition (response body contains 'root:') is identical, and the flag value is never exposed in copy.

## ssrf-hex-ip (Hex IP bypass)

- Verdict: BURP-CLEAN
- Tools: C -> BZ, C
- Burp workflow: Open the Hex IP fetcher form at /ssrf through Burp Proxy, submit a URL with the plain loopback host (http://127.0.0.1:PORT/ssrf/internal/secret), and send the request to Repeater. Confirm the 403: the naive substring blocklist rejects the raw '127.0.0.1' string. Then, in Repeater, re-spell the host in hex (0x7f.0.0.1) inside the same url parameter and send; the raw string check no longer matches, but the server-side URL parser normalizes the hex spelling to 127.0.0.1, the fetch reaches the internal secret path, and the internal marker in the response awards the flag. For fuzzing, send the request to Intruder and attack the url parameter with a short payload list of alternate loopback spellings (Sniper is enough). Burp does not normalize hex IP spellings inside parameter values, so the spelling reaches the server exactly as typed.
- Issues: none. Plain GET requests with a URL-encoded query parameter; Burp Community Repeater and Intruder handle everything with no mangling. No raw sockets, no malformed HTTP, no timing dependency, no Burp-mangled bytes, no curl-specific behavior, no non-HTTP protocols.
- Changes applied: tools set to BZ, C (BZ first). start replaced the curl one-liner (which had pasted the winning hex URL) with a Burp Proxy plus Repeater starting point. hint and hints rewritten to name the Burp steps as nudges only, no exploits pasted. how reworded to match the established Burp Repeater one-liner pattern used by sibling challenges. FLAG BAR and FLAG SECRECY unchanged: the flag award condition (internal secret marker fetched through /ssrf/hex-ip) is identical, and the flag value is never exposed in copy.
