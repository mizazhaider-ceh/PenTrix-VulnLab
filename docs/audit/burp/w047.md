# w047 verdicts

## xxe/ssrf (SSRF via XXE)

- Verdict: BURP-CLEAN
- Tools: "C" -> "BZ, C"
- OOB note: no out-of-band callback server is needed for this challenge. The flag is awarded in-band: the XML importer fetches the lab's own internal secret endpoint (`/ssrf/internal/secret` on the same app) server-side and splices the response, including the `SSRF-INTERNAL-9921` marker, straight into the parsed import output. The module's OOB collector (`/xxe/collector`) belongs to the separate parameter-entity challenge and is not part of this chain, so Burp Collaborator (Pro-only) is never required; Community Edition is enough.
- Burp workflow:
  1. In the browser, open the XML Importer page (/xxe/import) with Burp Proxy intercepting, paste a benign document like `<data>hello</data>`, and submit the form once.
  2. In Proxy, catch the POST /xxe/import request and send it to Repeater.
  3. In Repeater, replace the `xml` parameter value with a document that declares a DOCTYPE with an external entity whose SYSTEM identifier is an http:// URL aimed at the lab's internal SSRF secret endpoint (127.0.0.1 on the lab's own port), and reference that entity inside `<data>`.
  4. URL-encode the parameter value (right-click the selection and convert, or use the Repeater Inspector) so characters like `&`, `"`, `<` and `>` do not break the form field, then send.
  5. Observe the response: the "Parsed content" section now contains the internal endpoint's response including `SSRF-INTERNAL-9921`, and the flag box for xxe:ssrf is awarded. If the response shows an entity error instead, check the URL port matches the running lab and that the parameter stayed fully URL-encoded.
  6. Optional: use Intruder on the URL parameter segment to confirm the status endpoint returns nothing useful while the secret endpoint returns the marker, proving the exact target matters.
- Issues: none. The import form is a standard `application/x-www-form-urlencoded` POST; Burp does not normalize or mangle the XML bytes as long as the parameter is URL-encoded. The server-side fetch has a 5s timeout but localhost answers instantly, so no timing hazard. No raw sockets, no malformed HTTP, no non-HTTP protocols.
