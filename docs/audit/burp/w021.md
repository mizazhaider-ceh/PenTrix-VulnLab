Doctrine D16: every challenge fully solvable via Burp Suite (Proxy, Repeater, Intruder; Community enough). Voice is Burp-first, not curl-first.

## xss-markdown (XSS via Naive Markdown Links)

- Verdict: BURP-CLEAN
- Tools: B -> BZ, B
- Burp workflow: Start Burp Proxy and browse to /xss/markdown in the proxied browser. Render a note normally and send the captured Render POST to Repeater. The md parameter is a plain urlencoded form field; tweak it in Repeater and watch the response until the link target lands inside <a href="..."> as a javascript: URL. Open the rendered note in the proxied browser and click the link: the beacon fires from the browser and the claim status flips.
- Issues: none. Standard form POST, no normalization risk, no timing or raw-socket needs. Burp Repeater's parameter editor handles the urlencoded encoding of the md value (brackets, parens, quotes) automatically. The exploit needs a real browser click on the rendered link, which the Burp-proxied browser does natively; the test asserts the unclicked link awards nothing, and that behavior is unchanged.
- Changes applied: tools set to BZ, B. start now describes Proxy capture plus sending the Render POST to Repeater, no curl one-liner. hints name the Burp steps (Proxy intercept, Repeater submit, click in the proxied browser) and give nudges only, no exploit pasted. how reworded to Burp-flavored replay plus browser click.

## xss-svg-upload (Stored XSS via SVG Upload)

- Verdict: BURP-CLEAN
- Tools: B, C -> BZ, B, C
- Burp workflow: Start Burp Proxy and browse to /xss/svg in the proxied browser. Upload a plain SVG normally and send the captured Upload SVG POST to Repeater. Despite the "upload" name this is a plain urlencoded form POST (name and svg parameters, no multipart), so the whole chain is Repeater-friendly: edit the svg parameter value in Repeater, send, and follow the 302 Location to the served file link. Open that file link in the proxied browser; the SVG opens as its own document with Content-Type image/svg+xml, the script runs, the beacon fires, and the claim status flips.
- Issues: none blocking. Two crafting notes, neither a Burp limitation. (1) The SVG body carries & characters that must be percent-encoded inside the urlencoded svg parameter; Repeater's parameter editor does this automatically. (2) The XML CDATA requirement stays a payload concern: a bare & outside CDATA breaks SVG parsing, and that is already documented in the claim box on the page. The test asserts a token-less file URL (no ?n=) is rejected, and that behavior is unchanged.
- Changes applied: tools set to BZ, B, C. start now describes Proxy capture of the upload and Repeater tweaking of the svg form parameter, no curl one-liner. hints name the Burp steps (Proxy intercept, Repeater upload, open the file link in the proxied browser) and give nudges only, no exploit pasted. how reworded to Burp-flavored replay plus browser open of the served file.
