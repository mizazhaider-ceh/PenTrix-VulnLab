## 1. nested-deep (Deep Nesting Bypass, Easy)

### Verdict
BURP-CLEAN.

### Tools old -> new
`"B, C"` -> `"BZ, B"`.

### Burp workflow steps
1. Proxy on, open `/lfi/nested` in the Burp browser and submit the form once with a normal value (e.g. `readme.txt`).
2. In Proxy history, send the captured GET to Repeater.
3. In Repeater, tamper with the `page` parameter using nested dots so the server's one-pass global `../` strip rebuilds a traversal from the leftovers. The dots and slashes are all unreserved characters, so Burp sends them byte-for-byte with no mangling.
4. Fire and read the rendered file contents in the response. When the secret marker shows while the post-strip filename still carries `..`, the flag box and fix panel appear.

The whole exploit chain is a single standard HTTP GET with a query parameter; Burp Repeater handles the payload without touching the dots or slashes. No raw sockets, no malformed HTTP, no curl-only behavior, no timing tricks.

### Issues
- `tools` listed `C` (curl) with a curl `start` one-liner, contrary to the D16 Burp-first doctrine.
- `hints` were tool-agnostic; they never named the Burp steps that make parameter tampering fast (Proxy capture, Repeater tweak-and-resend).

### Changes applied
- `tools`: `"B, C"` -> `"BZ, B"` (Burp first per D16).
- `start`: replaced the curl one-liner with a Burp-oriented starting point (Proxy on, open `/lfi/nested`, send to Repeater, tamper with the `page` parameter).
- `hints`: third hint rewritten to name the Burp step (send to Repeater, sketch the collapse on paper before firing); nudges only, no exploit pastes. The short `hint` field was already tool-neutral and was left unchanged.
- `how`: made Burp-flavored (nested dots, worked out and fired in Burp Repeater).
