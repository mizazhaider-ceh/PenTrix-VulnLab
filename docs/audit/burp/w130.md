# w130 Burp Audit: stored (Stored Template in Profile Name)

## Verdict
BURP-CLEAN

## Tools old -> new
`B` -> `BZ, B`

The old start field was a curl one-liner (`curl -s http://localhost:3000/csti/stored | grep -c "Member directory"`), which only checks page reachability and does not capture the exploit chain. Replaced with a Burp-oriented start. `BZ` now leads; `B` stays because the page itself renders the member directory and auto-fires the beacon in a real browser.

## Burp workflow steps
1. Set up Burp Proxy as the interception proxy and point a browser at it.
2. In the browser, visit `/csti/stored`. Submit the profile form with a template expression as the display name. The form POSTs to `/csti/stored/profile` with a plain `application/x-www-form-urlencoded` body (`name=...`), fully Proxy/Repeater compatible.
3. Reload the directory page. The stored name is evaluated by the client-side template engine for every visitor, so the rendered result (49) proves evaluation in your browser.
4. Watch Burp's Proxy HTTP history: the page fires a GET to `/csti/beacon?v=stored&d=49&n=<CSTI_NONCE>` by itself once the stored template renders as 49. The beacon echoes the one-time page-bound token rendered into the page script as `var CSTI_NONCE = "..."`, and the response awards the flag.
5. Alternative pure-Repeater path (no browser JS needed): send the form POST `/csti/stored/profile` in Repeater with your session cookie, GET `/csti/stored` and copy `CSTI_NONCE` from the response body, then GET `/csti/beacon?v=stored&d=49&n=<token>` with the same session cookie. Verified live: POST returned 302, beacon returned 200 with the flag awarded.
6. The token is single-use per page load: a replayed token gets 400. Fetch a fresh token from a fresh page load for each attempt.

Intruder can fuzz display-name values or delimiters (`{{ }}` vs `[[ ]]`) as a bonus step, but the chain needs only Proxy plus Repeater.

## Flag secrecy notes
The nonce is per-session and single-use (`cstiConsumeNonce` deletes it on award); beacons with missing, guessed, or replayed tokens are rejected with 400, and `d` must equal `49`. The flag is issued only by the server-side `award()` call. No redesign needed: FLAG BAR and FLAG SECRECY preserved.
