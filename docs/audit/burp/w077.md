# Burp-first audit: w077, crypto/cbc-bitflip (CBC Bit-Flipping)

## Verdict
BURP-CLEAN. The exploit chain is plain HTTP POST traffic carrying a base64-ASCII cookie value: mint a guest cookie (POST /crypto/cbc/login), base64-decode it, XOR the IV bytes sitting over "guest" with ("guest" xor "admin"), re-encode, and POST the forged cookie to /crypto/cbc/check. Burp Community covers every step: Proxy captures the mint request and cookie, Decoder handles the base64 decode, hex edit, and XOR transform, and Repeater (or the browser form) delivers the forged cookie. No redesign needed; only the vuln metadata needed Burp-first wording. Changes applied to modules/crypto/challenges/crypto-cbc-bitflip.js only.

## Tools: old -> new
- Old: `P, C`
- New: `BZ, P, C`

## Burp workflow steps
1. Proxy: configure the browser to use Burp Proxy, open /crypto/cbc, and click "Mint a guest cookie". In the HTTP history (or on the mint page itself) you will see the base64 vlab_cbc cookie.
2. Decoder: send the cookie to Decoder (or open the Decoder tab and paste it). Decode as Base64. The first 16 bytes are the IV; the challenge page shows the full plaintext layout, so you can see that the role value 'guest' sits in block 0, right under the IV (bytes 9..13 of the block).
3. Decoder (hex edit): flip the IV bytes sitting over 'guest' so the decrypted block reads 'admin' instead (XOR them with 'guest' xor 'admin'). Decoder has a Hex editor plus an XOR transform and an Encode step.
4. Repeater or browser: re-encode to Base64 in Decoder and POST the forged cookie as the `cookie` field to /crypto/cbc/check, or paste it into the "Forged cookie" form on the page.
5. Observe the response: the page renders "Forged cookie accepted" with the flag box when the server sees role=admin. An unflipped guest cookie earns nothing, and garbage base64 is rejected with a 400.

## Issues found
None. The whole chain is standard HTTP GET/POST through form fields: no raw socket control, no binary bytes in the request body (the cookie is base64 ASCII, safe for Burp forms and Repeater), no timing sensitivity, no malformed HTTP, and no Burp normalization that would mangle the payload. The XOR math that Burp's Decoder cannot do is a simple byte-level operation the student can compute by hand or with Decoder's XOR transform. The server-side JSON layout is fixed and documented on the page, so no flag-bar or flag-secrecy concerns arise: the flag awards only when the cookie decrypts to role=admin, and minting or failed attempts award nothing (matches tests/crypto.test.js).
