Verdict: BURP-CLEAN

The exploit chain is two plain GET requests (robots.txt, then the disallowed backup.zip). Nothing here needs curl, raw sockets, or any special encoding. The challenge works fully through Burp Proxy and Repeater with standard HTTP, Community Edition included.

Tools old -> new: `B, C` -> `BZ, B`. Burp is now the recommended tool; browser stays as a secondary option.

Burp workflow steps:
1. Configure the browser to proxy through Burp (Proxy on).
2. Browse to `http://localhost:3000/misconfig/robots.txt` and read the Disallow entries.
3. Send the request to Repeater and request the disallowed archive path under the same `/misconfig` prefix.
4. Open the downloaded backup.zip and read the backup token inside.

Issues: none in the exploit chain. The old `start` field was a curl one-liner, and hints did not name the Burp steps; both fixed.

Changes applied:

- `start` rewritten as a Burp Proxy/Repeater starting point; the curl one-liner was removed.
- `hints` now name the Burp steps (Proxy the rules file, then Repeater for the archive); no exploit details pasted.
- `how` rewritten tool-neutral around Proxy and Repeater.
- FLAG BAR kept: reading robots.txt alone awards nothing; only fetching the zip awards (matches test expectation).

## Challenge 3: trace (HTTP TRACE Enabled (XST))

Verdict: BURP-CLEAN

The TRACE primitive is sent from Burp Repeater by changing the method verb on a request to `/misconfig/trace`. The exploit does not depend on any `curl -X TRACE` quirk: it is a standard HTTP request with a custom method token, and Burp Community Edition Repeater lets you edit the method field freely. The server reflects the headers back in the response; Burp displays this with no mangling, so there is no Burp-mangled-bytes concern.

Tools old -> new: `C` -> `BZ, C`. Burp is now the recommended tool; curl stays as a secondary option.

Burp workflow steps:
1. In Burp Repeater, create a request to `http://localhost:3000/misconfig/trace`.
2. Change the method verb to TRACE and add a Cookie header.
3. Send the request and read the reflected request in the response; the Cookie header comes straight back (the XST primitive).

Issues:
- The explainer page (`GET /trace`) said "Browsers cannot send TRACE; use curl:" with a curl one-liner, which contradicted the Burp-first doctrine. Fixed: it now says to change the method verb in Burp Repeater and shows the raw TRACE request line instead.
- The single-line `hint` said "a command-line HTTP client can: ask it to use a custom request method". Fixed: it now names Burp Repeater explicitly.

Changes applied:
- `tools` changed from `C` to `BZ, C` (Burp recommended first).
- `start` rewritten as a Burp Repeater starting point; the `curl -X TRACE` one-liner was removed.
- `hints` now name the Burp step (send TRACE from Repeater); no exploit details pasted.
- `how` rewritten tool-neutral around Burp Repeater.
- Explainer page text updated to Burp-first (no behavior change to the TRACE handler).
- FLAG BAR and FLAG SECRECY kept: the GET explainer awards nothing; only a real TRACE awards.
