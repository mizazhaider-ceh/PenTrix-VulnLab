# Burp-first audit w142: formula-csv (Classic Formula Injection)

## Verdict
BURP-CLEAN. The exploit chain is a plain POST of form fields (`POST /formula/add`, `application/x-www-form-urlencoded`) followed by a plain GET (`/formula/export.csv`). The flag arrives in the `X-Flags` response header. No raw sockets, no Burp-mangled bytes, no curl-specific behaviors, no non-HTTP protocol. The whole chain works through Burp Proxy (capture the form submit), Repeater (iterate on the payload in the `name` field, then GET the export and read the response headers), and Intruder (Community edition is enough).

## Tools old -> new
- Old: `B` (Browser)
- New: `BZ, B` (Burp/ZAP first, Browser kept, curl never mentioned)

## Burp workflow steps
1. Start Burp Proxy and configure the browser to use it, with Intercept on.
2. Browse to `/formula` (ContactBase). The page shows the "Add a contact" form and the "Download CSV export" link.
3. Submit the form once with any name. Proxy captures `POST /formula/add`; right-click it and send it to Repeater.
4. In Repeater, edit the `name` parameter: make the cell start with a formula trigger character (`=`, `+`, `-`, `@`) so a spreadsheet treats it as a live formula. The classic shape pipes a Windows shell command through the pipe operator and anchors it with a cell reference. Iterate on this value in Repeater and resend.
5. After each change, GET `/formula/export.csv` in Repeater. The response is the CSV file (Content-Type `text/csv`, Content-Disposition attachment) with your cell embedded raw (RFC 4180 quoting only, which does not neutralize a formula).
6. Inspect the response headers: the flag arrives in the `X-Flags` response header when the export contains a matching cell.
7. (Optional) Use Intruder with the `name` parameter as the payload position to fuzz formula trigger prefixes quickly.

## Issues
- None block Burp-first solving. One design note: four challenge routers register the same `/export.csv` path and the first mounted router serves every export request, but the `classify` function in `formula-csv.js` awards every matching vuln id, so the other three formula challenges remain solvable too. FLAG BAR and FLAG SECRECY untouched.

## Changes applied
In `modules/formula/challenges/formula-csv.js` (`vuln` object only):
- `tools`: `B` -> `BZ, B` (BZ first).
- `start`: replaced the curl one-liner with a Burp-oriented starting point (open the lab in Burp with Intercept on, let Proxy capture `POST /formula/add`, send to Repeater, iterate on the formula payload, then GET `/formula/export.csv` and inspect the `X-Flags` header).
- `hints`: rewritten as Burp-step nudges (intercept the add-contact POST in Proxy; send the POST to Repeater to iterate; request the export in Repeater after each change and watch the `X-Flags` header). No exploits pasted.
- `how`: Burp-flavored (add a contact whose name cell is a live spreadsheet formula, then request the CSV export in Repeater and read the `X-Flags` response header).

Verified: `node --check` passes, zero em dashes in the file, scratch server (`DB_PATH=/tmp/burp-w142.db PORT=18142`) returned 200 on `/formula`, a Repeater-style POST of the classic `=cmd|'/C calc'!A0` cell returned 302, and `GET /formula/export.csv` returned 200 with `X-Flags: PENTRIX{...}` and the raw payload cell visible in the CSV body. Server stopped and port closed. FLAG BAR and FLAG SECRECY untouched.
